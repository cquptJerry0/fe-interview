# 单题 SOP

## 通用前提

- 先确认答案方向正确，再抽象成 SOP；不要一上来只写流程。
- 单题输出统一只保留 3 个大模块：`模块 1｜主回答`、`模块 2｜深入展开`、`模块 3｜追问与详细回答`。
- 每个大模块下面都必须有固定小标题，不能临场自由发挥结构。
- 不引用外部文档；题库没有的内容，直接补内部专题深挖。

## 通用执行顺序

1. 先给出这道题的完整答案。
2. 用“能不能直接面试说出来”来评审答案。
3. 再按题型套进对应 SOP。
4. 最后判断是进模板化回答，还是补专题深挖。

## 知识状态判断

只允许三种状态：

- `已覆盖`：已有高质量题卡，可直接复用。
- `部分覆盖`：有入口卡，但深度不够，需要本题补强。
- `需建档`：题库没有，或现有内容撑不起追问。

## 难题加厚规则

### 默认触发范围

- React 原理
- 状态管理
- 性能优化
- 网络与缓存
- 复杂场景题
- 多层追问明显的对比 / 开放题

### 触发后最少固定增加

- `1 张额外 ASCII 图`
- `1 个额外例子`
- `1 段精炼伪代码`

### 加厚原则

- 加厚是为了更容易看懂，不是为了堆概念。
- 口语稿不跟着无限变长，额外内容优先放在原理图、例子、伪代码里。
- 难题要做到：读完后不需要继续追问才能看明白主链路。

## 图解优先规则（CSS / 布局 / 可视区类）

适用范围：

- CSS 布局
- 盒模型与尺寸约束
- 文本溢出与省略
- 滚动与可视区判断
- 定位与层叠
- 坐标、宽高、可见区计算

固定要求：

- 代码只是一部分，必须优先图解，不能只堆 CSS 属性或 JS 片段。
- 至少 `2 张 ASCII 图`。
- 必须画清盒模型 / 布局约束 / 尺寸或坐标计算 / 失败原因。
- 如果有兼容、降级或回退方案，必须画出“主方案 vs 兼容方案”的差异，不能只列名。
- 如果题目核心是“为什么不生效 / 为什么失败”，图里必须直接表现触发条件和失败原因。

## 八股题 SOP

### 适用范围

- 原理题
- 机制题
- 边界题
- 单点知识题

### 模块 1｜主回答

固定小标题：

1. `一句话结论`
2. `原理图（ASCII）`
3. `最小例子`
4. `面试口语稿`

要求：

- 结论必须直接回答题目。
- 原理图必须画出“触发条件 -> 核心机制 -> 结果”。
- 最小例子必须能证明结论。
- 口语稿必须能直接说出口，不写教材腔。

### 模块 2｜深入展开

固定小标题：

1. `原理链路`
2. `业务化解释`
3. `取舍 / 易错点`
4. `深挖判断`

要求：

- 不能只重复结论，要补“为什么”。
- 要能解释“这个点为什么会在真实项目里出问题”。
- 深挖判断要明确是否需要补专题卡。

### 模块 3｜追问与详细回答

固定小标题：

- `追问 1`
- `追问 2`
- `追问 3`
- `追问 4`
- `追问 5`

要求：

- 每个追问都要有完整回答，不能只列标题。
- 优先覆盖：原理、边界、排查、相近概念区别。
- 原本散落在文末的边界补充，统一并入这里。

### 质量门禁

- 有明确结论。
- 有 ASCII 图。
- 有最小例子。
- 有口语稿。
- 有业务化解释。
- 有 3 个以上追问详答。

## 场景题 SOP

### 适用范围

- 线上问题处理
- 稳定性题
- 兜底 / 降级题
- 体验治理题

### 模块 1｜主回答

固定小标题：

1. `处理目标`
2. `分层处理图（ASCII）`
3. `兜底流程 / 最小方案`
4. `面试口语稿`

要求：

- 先说处理目标，再给方案。
- 要体现“预防 / 降级 / 恢复 / 监控”或同等级分层思路。
- 不能只给一个技巧点，比如只说 `onError`。

### 模块 2｜深入展开

固定小标题：

1. `问题拆解`
2. `业务场景`
3. `取舍 / 易错点`
4. `专题判断`

### 模块 3｜追问与详细回答

固定小标题：

- `追问 1`
- `追问 2`
- `追问 3`
- `追问 4`
- `追问 5`

要求：

- 优先覆盖：失败分类、恢复策略、监控、边界。
- 回答要能体现排查和治理，不只是表面兜底。

### 质量门禁

- 有分层处理思路。
- 有最小兜底方案。
- 有场景化取舍。
- 有监控 / 追踪意识。
- 有 3 个以上追问详答。

## 对比 / 开放题 SOP

### 适用范围

- 技术选型题
- 方案对比题
- 开放表达题
- “怎么选 / 为什么选”题

### 模块 1｜主回答

固定小标题：

1. `选择结论`
2. `选择图 / 决策树（ASCII）`
3. `最小对比表 / 最小例子`
4. `面试口语稿`

要求：

- 不能答成“谁更好”，要答成“什么场景怎么选”。
- 决策树要能让人一眼看到选择条件。
- 最小对比表只保留最关键维度，不能铺满无效细节。

### 模块 2｜深入展开

固定小标题：

1. `对比维度`
2. `选项本体拆解`
3. `取舍 / 易错点`
4. `专题判断`

要求：

- 不仅要回答“怎么选”，还要讲“每个选项本身是什么”。
- 特别深的实现原理，不塞进口语稿，挂到专题深挖。

### 模块 3｜追问与详细回答

固定小标题：

- `追问 1`
- `追问 2`
- `追问 3`
- `追问 4`
- `追问 5`

要求：

- 优先覆盖：原理、边界、实现方式、适用场景。
- 回答里要体现你知道这些选项本身怎么工作。

### 质量门禁

- 有选择结论和决策树。
- 有最小对比表。
- 有选项本体拆解。
- 有 3 个以上追问详答。
- 至少指出 1 个值得拆专题的原理点。

## 归档动作

- 每道题最终要打上：`可快答`、`可展开`、`一追就断` 之一。
- 难题要额外标记：`标准版可掌握`、`加厚版后可掌握`、`仍需专题深挖`。
