# 编程题写法

适用范围：

1. 算法题
2. 页面实现题
3. 组件题
4. 手写函数题、机制题、工具题

## 默认原则

1. 第一版先给笔试最小可用版，不要一开始就写很多。
2. 代码量以 3-5 分钟可手写完成为准，先保证能过题、能讲清。
3. 默认不要先写工程化封装、泛型设计、完整容错、过多扩展参数。
4. 如果用户说“笔试”“手写”“先在聊天框输出”“先给简单版”，优先进一步压缩到最短可用解。
5. 只有用户明确要“满分版”“工程版”“可复用版”，再补第二版代码。

## 固定输出

1. 思路
2. 最小可用版代码
3. 关键边界
4. 复杂度，算法题才需要顺便告诉我怎么算
5. 口述顺序
6. 如果需要，再给进阶版或满分版

## 最小可用版要求

1. 优先使用最直接的数据结构和最少的辅助函数。
2. 能内联就先内联，能少一层封装就少一层。
3. 注释只保留必要的一两句，不要把答案写成教程。
4. 先满足题目主目标，再在“关键边界”里补充未展开的工程点。
5. 如果某些优化会明显拉长代码，先口头点到即可，不要默认写进第一版。

## 口述顺序模板

1. 先说最直接可行的思路
2. 再把最小可用版快速写出来
3. 再说指针、状态或数据结构怎么变
4. 再说边界条件
5. 最后说复杂度或还能怎么优化
