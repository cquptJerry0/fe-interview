# 专题题写法

适用范围：

1. 输入 URL 到页面显示
2. 浏览器渲染链路
3. RenderNG / Viz
4. SSR
5. JS 执行机制全链路
6. React 渲染与调度
7. 工程化底层原理题

## 输出结构

```txt
Part 1｜技术讲解
- 一句话结论
- 主链路图
- 分阶段展开
- 结论证明材料
- 关键误判点
- 工程/业务例子

Part 2｜面试作答
- 思维导图关键点
- 60-90 秒口语稿
- 高频追问
- 复习标记
```

## 必须做到

1. 不是只讲老八股，要讲现代实现。
2. 如果涉及浏览器、框架、运行时这类会演进的话题，先搜索最新官方或一手资料，再开始写。
3. 要把“规则链路”和“真实工程意义”一起讲清。
4. 口语稿最后必须落到一个真实业务例子。
5. 不能为了压缩篇幅牺牲说服力，专题稿默认比普通题更厚。
6. 如果是浏览器架构题，至少要明确：
   - browser process
   - renderer process
   - commit
   - 现代渲染流水线
   - Viz 或最终出像素路径
7. 如果用户已经明确认可过某一版回答，落盘版本必须以那一版为下限，不能简化回普通八股。
8. 搜索时优先顺序：
   - 官方文档
   - 官方博客
   - 规范或维护者资料
   - 论文或源码文档
9. 不要把旧版本实现、历史文章结论、过时八股，写成当前口径。
10. 如果搜索后发现资料之间存在版本差异，要在答案里明确“这是当前官方公开口径”。
11. 浏览器题优先看 Chromium / Chrome for Developers / MDN。
12. React 题优先看 react.dev。
13. Vue 题优先看 vuejs.org。
14. `JS 底层` 专题优先看 ECMAScript 规范、WHATWG HTML event loop、MDN 对应条目。
15. `JS 底层` 专题不能只写 `this + 闭包`，必须把编译时、运行时、执行上下文、环境记录、Reference Record、函数对象的 `[[Environment]]`、原型、闭包、Promise Job 和宿主调度串成一条链。
16. `JS 底层` 专题必须单独写出“关键误判点”和“把面经题串回总图”，让读者知道每道题在整条链上的位置。
