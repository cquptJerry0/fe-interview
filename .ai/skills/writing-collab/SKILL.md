# 写作共创

让读者理解、判断或完成具体事情。先确定本篇目标，再选择内容、组织逻辑和表达形式；按目标验收，不按模板完整度验收。

## 工作边界

- 根据当前请求进入相应阶段。已有有效大纲或只需局部修改时，复用已确认内容，不重新走完整流程。
- 写作授权不自动包含创建文件、发布飞书、调用真实业务接口或执行文中命令的授权。沿用当前环境的权限要求；未获文件授权时，在对话内维护约定。
- 本 skill 独立提供写作指导，不调用 `technical-document-writing` 或 `distill-work-summary` 作为写作模板。事实调查、平台读写按实际需要使用可用工具。
- 区分研究记录、写作约定和交付正文。调研过程及协作记录默认不进入正文；复盘需要呈现定位路径时，只保留帮助读者理解根因与判断的部分。
- 本 skill 是候选协作机制，结构校验和模拟用例通过不代表真实正文稳定可用。用户认可大纲、授权写入或未继续批评，均不等于正文通过。

## 始终执行的底线

`内容`：结论有依据，事实、推断、计划和未知不混写；细节能服务读者任务。不补造数字、因果、职责、个人贡献或已验证状态。

`逻辑`：文章目的明确，关键章节各有职责，概念可理解，段落能接上。主题目录不能直接当作可写大纲；资料完整不能替代论证完整。

`格式`：标题准确，文字可读，图表代码各有用途。没有固定标题字数、段落长度、难点数量或必画图数量；不靠禁词表和格式变换解决内容问题。

当篇的明确要求优先于本 skill 的默认建议，但不能改变事实。用户偏好只在已确认范围内使用，不从一次局部反馈推导全局禁令。

## 执行路径

将业务需求与技术资料整理成工作总结、答辩模块，并需要从大纲推进到排版或飞书交付时，按需读取[模块写作与交付](references/协作与验收/模块写作与交付.md)。已有主线、大纲或正文就从当前阶段继续，不将完整流程强加给局部修改或其他文种。

### 1. 注入目标并整理材料

从上下文提出简短目标：给谁看，看完需要知道、判断或完成什么，主次目标及范围是什么。已有明确目标就直接采用；只对实质影响主线的分歧提问，不发一次性问卷，不重复确认。

读取[目标识别与主次](references/目标与取舍/目标识别与主次.md)、[场景策略](references/目标与取舍/场景策略.md)。材料分散或不足时读取[材料整理与缺口](references/协作与验收/材料整理与缺口.md)。决定目标是否足以推进，不要求每个字段都填满。

### 2. 共创足以指导正文的大纲

读取[大纲共创与确认](references/协作与验收/大纲共创与确认.md)。展示实际文章结构；关键章节写清回答的问题、拟表达的结论、依据和边界，简单小节简写。只提出有实质差异的选择。

大纲确认后，记录确认范围。关键结论仍缺依据时，说明缺口，不能把该节标成已具备正文条件。

### 3. 按约定写正文

读取[正文生成与试写](references/协作与验收/正文生成与试写.md)，按本篇目标选用下方指导。高风险表达可先试写一个代表片段；不默认逐段审批。已经清楚的任务直接起草。

保持已确认的主线、职责、详略与边界。发现事实推翻大纲时，回到受影响决策，不能为了遵守大纲编造内容。

### 4. 验收并处理反馈

读取[验收与返工](references/协作与验收/验收与返工.md)，脱离聊天上下文通读。检查底线与目标达成，修复交付阻断项后再提供可交付版本；资料不足时可交付明确标记的草稿或局部成果，不宣称全文合格。

纠偏时读取[共识保存与纠偏](references/协作与验收/共识保存与纠偏.md)。目标变化时读取[目标变更与影响](references/目标与取舍/目标变更与影响.md)，明确替换旧约定，不累计互相冲突的要求。

用户要求同步本地与飞书时，另按[飞书块与重点标记](references/格式与图表/飞书块与重点标记.md)核对格式转换和交付范围。仅要求画板或截图占位时，不扩成实际制图、截图采集或浏览器检查。

## 按问题选读

以下参考按当前问题读取，不一次加载全部文件。每份参考中的基线是检查依据，场景建议保留选择空间。

### 内容

- 资料过多、深浅失衡：[信息筛选与详略](references/内容指导/信息筛选与详略.md)。
- 背景过长、目标不落地：[背景问题与目标](references/内容指导/背景问题与目标.md)。
- 数字、状态、因果和来源：[事实证据与数据](references/内容指导/事实证据与数据.md)。
- 设计价值、架构边界和比较：[方案机制与取舍](references/内容指导/方案机制与取舍.md)。
- 面向执行的指南：[操作步骤与异常](references/内容指导/操作步骤与异常.md)。
- 总结、成果和个人贡献：[结果价值与贡献](references/内容指导/结果价值与贡献.md)。

### 逻辑与语言

- 结构返工和章节重复：[主线与章节职责](references/逻辑与语言/主线与章节职责.md)。
- 判断缺依据、比较无结论：[因果比较与论证](references/逻辑与语言/因果比较与论证.md)。
- 概念难懂、术语堆叠：[概念引入与解释](references/逻辑与语言/概念引入与解释.md)。
- 段落跳跃、机械过渡：[段落展开与承接](references/逻辑与语言/段落展开与承接.md)。
- 空泛、绕口、重复总结：[句子表达与删冗](references/逻辑与语言/句子表达与删冗.md)。

### 格式

## 共识、样本与验证

本篇约定使用[轻量模板](assets/本篇写作约定.md)，内容随文章保存在经授权的位置，或保留在对话内；不要把每篇事实和反馈写回共享 skill。稳定偏好的全局更新须获得用户确认。

需要学习对象时，先读[来源与适用场景](references/样本/来源与适用场景.md)，再选读[失败与纠偏记录](references/样本/失败与纠偏记录.md)或[优秀片段解析](references/样本/优秀片段解析.md)。样本推荐不代表用户认可；示例中的业务事实不可迁移到新文章。

`tests/` 是 skill 维护者的行为验证用例，普通写作不逐项运行：[目标适配](tests/目标适配.md)、[大纲正文一致性](tests/大纲正文一致性.md)、[纠偏与目标变更](tests/纠偏与目标变更.md)、[正文基线与交付](tests/正文基线与交付.md)。
