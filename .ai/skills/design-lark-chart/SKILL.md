# Design Lark Chart

## 强制执行：入口标准不可跳过

**先定主题 → 必须匹配并读取好案例 → 完整 ASCII → 按认可设计生成原生节点 → 检查、写入、回读、真实读图 → 交付。**

- 新复杂图和结构重绘必须先选合适案例、查看真实预览、读取设计说明，再交付完整 ASCII；准备绘制时必须读取对应源码。只看案例名称不算参考。
- 默认返回一套推荐方案。ASCII 必须把分区、节点、主链、必要支路、数据和调度画在一张可独立理解的图内，不能拆几段让用户自己拼。
- 用户只要骨架、ASCII 或 prompt 时停在对应阶段，禁止远端写入；已认可布局直接接续，不逐节点询问。用户明确要求直接完成时，先给简洁的完整设计，再连续执行，不增加审批轮次。
- 已有图的小范围改词/参数调整不重新做全图设计：回读当前图、沿用认可案例和结构，仅重算受影响部分。关键事实改变已认可结构时说明影响再调整。
- **未满足下面的构成、组件、文字和视觉要求，不能进入正式写入；未回读和查看真实导图，不能宣布成图完成。**

## 必须先走案例路由

按真实关系匹配，命中最相关项；案例是制作起点，不是可跳过的文末链接。

| 当前关系 | 必须读取/查看 | 沿用什么 |
|---|---|---|
| 多入口、任务汇合、数据读写、阶段推进 | [素材供给阶段案例](references/material-supply-case.md)、其完整 ASCII 和真实预览；实施前读取 build/finalize 源码 | 原生分区、顶部图例、独立入口、共用水平主链、数据与调度的邻近布局 |
| 主流程＋局部机制＋平台或身份依赖 | [自动发布案例](references/four-lane-case.md)及真实预览；实施前读取案例源码 | 横向阶段与必要依赖层、局部展开、执行与依赖分开 |
| 时序、职责分层、树、页面、状态等其他关系 | [参考样本路由](references/reference-atlas.md)中匹配样本及对应 assets/previews 或用户可访问参考 | 对应关系表达，不套四阶段或四通道 |

返回设计时先说“参考……；沿用……；本次调整……”。参考图的结构、组件、配色分别判断。用户只认可组件和配色时，禁止照搬其业务结构。无适配或可访问案例时如实说明，以已核实事实形成草图，不虚称案例已验证。

## 完整 ASCII 的交付合同

设计回复依次包含：
1. **设计说明**：主题、范围、参考案例、阅读方向。
2. **视觉定义**：分区名及色值、组件和线型图例、文字层级。
3. **一张完整 ASCII**：真实分区及执行主体、完整主链、必要判断/分支/汇合/结果、来源与目标、必要数据和调度关系。细节多可附局部展开，但主图必须独立成立。

**不通过**：只有标题空框；只画主链漏必要对象；拆开主链/表/调度让用户拼；所有对象同一方框且无组件映射；颜色不能对应分区；块内堆段落；关系没有含义；未知事实画成已实现。按 [ASCII 输出标准](references/ascii-contract.md)自查。

## 画板构成与严格视觉标准

### 标题、图例与分区

- **大图必须有整图标题与清楚的分区标题。** 整图标题采用独立原生 text_shape，默认左对齐、加粗；分区采用原生 section，其 `section.title` 生成原生标题标签，不用浮动矩形叠文字冒充。
- 服务名称放在分区内并与标题、第一排节点留出空间。整图标题、分区标题、服务名称、节点标题不得混成一类文字。
- 顶部集中图例：真实组件示例＋含义、颜色编码、实虚线含义。只展示本图使用的类别；组件外不挂散乱字段或解释小字，图例旁说明和原生线标签除外。
- 分区按真实阶段/职责划分，**大块包小块，节点和同区连线有真实归属**，不是只覆盖背景。阶段数和宽度按业务决定；同一服务可出现在多个阶段，禁止虚构服务凑分区。

### 组件映射：先判断对象再选形状

| 对象 | 原生组件 | 文字要求 |
|---|---|---|
| 动作 | round_rect 圆角矩形 | 中文对象＋具体动作 |
| 条件 | diamond 菱形 | 可回答的条件，分支结果在线上 |
| 起止/终止/结果 | round_rect2 胶囊 | 具体对象及状态 |
| 消息队列 | **horiz_cylinder 水平圆柱** | 中文消息用途＋必要 topic |
| 数据库表 | **cylinder 竖直圆柱** | 中文数据含义＋实际表名 |
| 面板/文件/版本对象 | note_shape 文档形 | 来源/目标、中文对象＋key、内测/正式版本 |
| 平台/调度 | predefined_process 平台框 | 中文职责＋必要完整服务名 |
| 真实执行环境、认证 | hexagon / parallelogram | 仅有真实对象且有定位价值时使用 |
| 范围 | **section 原生分区** | 真实边界与原生标题 |

类型以当前 schema 和回读为准；这些映射已有案例，不得猜不存在的 enum。队列、数据库、文件版本不能统称存储。不为了丰富形状补造平台、账号或机制。

### 字体与节点描述

- 同级字体、尺寸和间距保持一致，明确整图标题、分区标题、节点主信息、技术名称和线标签的层级。案例参数为起点，不把绝对字号或画幅固定成所有图标准。
- 节点先中文用途/对象/动作，再放必要的完整服务名、key、字段、表名；执行主体由分区说明后不机械重复。一个块表达一个动作、判断或对象，通常一至三行；必要条件/字段可增加行数，不塞说明段落。
- 区分来源和目标，Draft 与正式版本；不写孤立“处理”“可用”“状态变化”让读者猜对象。字段按语义层级主动换行，禁止孤立尾字母、拆开的英文单词或含义改变。
- **形状外框不等于文字内接区**。优先改短句、调整宽高/布局，不连续缩字号塞文字；服务名、标题、字段和每行末尾都必须实际读图验收。

### 配色、留白与线型

- 白底，分区浅色底，内部节点轻量；默认参考成功案例。分区底色表达阶段/归属，组件形状及填色表达对象类型，两套编码在图例定义，禁止又借同色表达无关成功/失败状态。
- 阶段流程起点色板：浅蓝 `#EEF3FF`、浅青 `#EFF9F8`、浅绿 `#F0F8F1`、浅灰 `#F5F6F8`；动作白色，判断 `#FEF1CE`，队列 `#DFF5E5`，数据库/结果 `#EAE2FE`。色值集中维护，其他图型和用户明确配色可调整并定义含义。
- 横向主链保持单向、不折行；独立入口上下排列并在真实位置汇合。纵向关联只表示读写、调用、依赖、归属或细节展开，不伪装时间顺序。
- 先预留主线、分支、数据线、标签通道再摆节点；同区/跨区留白分别计算，非机械等宽。不能无限加宽或缩字掩盖密度问题。
- 主链实线、读写/调度清楚虚线（默认主线 `#454F5D`、虚线 `#626F80`）；标签写关系含义。所有连接两端绑定节点，箭头按语义决定。
- **不穿节点、不压文字、不让无关线共线形成假合流。** 交叉本身不表示合流；必须避让或明确表达。正常展示尺寸能看清虚线、标签和箭头才合格。

## 原生实现：强制告警

- 制作链是 DSL/布局 → 转换 → 原生修正 → 最终结构检查 → 写入 → 回读 → 真实导图；DSL 只是中间格式。**禁止用整图图片或 SVG 替代用户要求的原生可编辑图。** 特殊格式仅用户指定或已查证关键能力无法满足时进入 [例外](guides/optional-formats.md)。
- **DSL connector 放顶层；原生分区归属是另一层规则。** 子节点按分区局部坐标存储，同区连接线与端点使用同一坐标空间，跨区连线使用全局坐标。本次已验证细节和通用源码见 [原生绘制](guides/native-drawing.md)。
- 先用全局坐标计算端点、折点、包围盒和避让，最后统一转换局部坐标。换形状或尺寸后重算，不能只改 type。
- 几何检查必须从最终原生结构还原全局坐标，不能只查早期布局。绑定端点、父分区、标题留白、实际文字与层级均必须核对。
- 写前回读当前图、保留用户同期改动、备份、dry-run；复用原 token。写入成功后查询失败只读观察，不能重复副作用或另建图。
- **回读与实际导图均通过才宣布完成**；静态通过、文件存在或本地模拟图不能替代线上视觉。整图检查阅读顺序，局部放大检查标题遮挡、截字、断词、穿线、标签拥挤和虚线可见性。

## 源码、协作与验收

- 案例保存完整 ASCII、设计/参数、最终生成与修正源、原生节点和真实预览；最后几轮修正必须合回可执行流程，禁止依赖聊天手工补丁。
- 复用组件映射、样式、坐标转换和绑定连线代码，业务内容独立输入。**生成/检查默认不写远端，目标画板必须显式指定，不继承案例 token。**
- 小改只重算受影响区域；接口若整板替换，以当前完整结构合并，不冒称局部 patch。范围/目标改变才重新确认；默认当前助手执行与检查，不主动拆代理。
- 只汇报真正检查的范围；真实导图不可用则明确缺口。裁白边可改善展示，保留原导图，不能靠裁图修复原画板。交付最新可编辑文档/画板及简短变更。
- 入口标准为强约束，具体实现按 [原生绘制](guides/native-drawing.md)；分步方法按 [定主题](workflow/01-purpose.md)、[搭骨架](workflow/02-skeleton.md)、[填内容](workflow/03-content.md)、[展开细节](workflow/04-details.md)、[整体优化](workflow/05-refinement.md)。
- 版本与局部范围按 [协作规则](guides/collaboration.md)，证据按 [边界](references/evidence.md)。修改 Skill 后运行原生回归和完整性测试，再按 [场景验收](tests/scenarios.md)检查实际行为；关键词匹配不能证明助手已经学会。
