# 5. 整体优化

先检查图能不能讲明白，再处理视觉。每轮只验收约定范围：骨架尚未展开的机制不是本轮缺陷，完整成图则应核对全部需求。

## 从读者视角检查

按正常展示尺寸读图，尝试回答主题中的问题。沿主路径讲一遍，确认读者能判断起点、区域职责、关键条件和结果，不需要先听一大段说明。

| 反馈或现象 | 优先修什么 |
|---|---|
| 不知道在讲什么 | 回到主题与范围，不先加标题小字 |
| 各块联系不清 | 骨架关系与连接含义 |
| 节点看不懂 | 主体、动作和对象命名 |
| 技术内容不足 | 必要的条件、输入输出、等待或隔离机制 |
| 小字太多 | 重复解释与内容取舍，不先缩字号 |
| 线混乱、文字被夹住 | 端口、通道、线标签空间与形状内接区 |

图形、字体和留白按实际文案计算；判断框、胶囊、平行四边形的可用文字区小于外框。避免孤立尾字、缩写无人理解、标签压在箭头或交叉点上。同类节点统一，不要求不同信息量的区域机械等宽。

保留真实业务关系，不能为零交叉删边，也不能把无关线合成一根母线。真实分叉、合流之外的交叉必须无歧义。

## 必须逐项验收

- 全图：整图标题、原生分区标题、顶部图例齐备且可读；阅读方向、独立入口、共用主链与结果清楚。
- 组件：水平队列、竖直数据库、文档形版本对象映射准确；字段/服务名在节点或分区内部。
- 局部：阶段标题不覆盖服务名；每行文字不裁切；菱形内接区安全；长字段无孤立尾字母；虚线和箭头在真实展示尺寸可辨认。
- 走线：最终原生全局几何检查绑定/归属/穿节点，检查同区及跨区坐标空间；不得拿旧 DSL 几何证明原生正确。标签及无关线交叉需实际读图。
- 交付：ASCII 与成图保持对应；回读与真实导图均完成，保留原导图；仅裁白边不能修复原板。修改过协作文档/画板后重新交付最新位置。

以上失败先修产物。静态通过、文件存在或本地模拟预览都不等于线上验收通过；无法完成时说明缺口。

## 按交付阶段验证

- ASCII / prompt：检查主题、完整主线、位置约定和关系，不执行远端写入。
- 本地预览：实际查看生成结果，说明尚未在飞书验证。
- 飞书更新：按 [原生绘制](../guides/native-drawing.md) 检查最终节点、备份和 dry-run，写入后回读并查看真实导图。静态检查通过不等于视觉通过。
- 只复核未改动的已验收版本：直接给链接或结论，不为重复验收再写入。
- 正式文档回填：仅在授权范围内执行，确认正式位置、图名、图注与画板内容，不能沿用另一位置的验收结论。

当前 agent 做一次实际读图检查，记录具体问题和修正。没有评分门槛，不默认另开测试画板、生成变体或请独立 reviewer；用户明确要求时才做相应扩展。

## 何时结束

本轮约定已完成且无具体阻断问题就交付。可以说明下一步，但不制造“是否继续优化”的空转。后续反馈以当前版本为起点，不重新设计已认可部分。

同一问题连续三轮修复仍失败时停止自动试错，报告原因和一个推荐方向。远端导图不可用时保留源文件、回读证据和本地稿，明确未完成远端视觉验证，不能冒称成功。
