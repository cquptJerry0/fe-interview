# 协作场景验收

这些场景用于实际使用或授权的独立演练，不是静态自动测试。运行时记录输入、实际产物、工具副作用、用户被问了什么以及发现的问题；不能只匹配标题或关键词就宣称行为通过。

## 新图：只要骨架

输入：“画一下代码合入、制品发布、模板更新的关系，先给 ASCII 骨架，不写飞书。制品发布失败时模板不更新，模板失败不撤回制品。”

检查：先明确图的目的；给真实区域、主要节点及两种失败影响；定义内容、位置、颜色、图形含义；不虚构版本算法或锁机制；不调用远端写入，不提前画满机制。

## 接续：成批填内容

前置：用户已认可骨架与配色。输入：“方向可以，把制品和模板两部分补完整。”

检查：接续原布局；必要主步骤完整；成批处理两块，不逐节点请示、不再交同一版空骨架；事实缺口仅针对会改变设计的事项确认。

## 局部改词与用户手工改动

前置：远端有用户刚改过的平台名称。输入：“只把 Git CAS 换成能讲懂的话，别动其他地方。”

检查：回读当前图；核实机制后改动作表述和必要留白，保留用户名称与并发语义；不改颜色或总体布局。若真实接口整板替换，检查未改区域保留，而不口头声称是局部 API。

## 细节不足

输入：“等待那块还是看不懂，补一下为什么等、失败了怎么办。”

检查：查清等哪个任务、如何识别结果、是否有超时和人工处理；展开为与主节点关联的局部关系，不加两块说明文，不凭经验发明重试次数。

## 原生绘图

输入：“沿用四通道案例的感觉，直接快速更新指定画板。”

检查：默认原生组件，不先问 DSL / Mermaid / SVG；结构按本业务确定；授权目标内备份、dry-run、回读与真实导图。原生文字、形状、标签和双端绑定应保留，参考图本身不被覆盖。

## 格式例外

输入：“已有 Mermaid 时序图，只修改一条返回消息。”

检查：尊重用户指定格式和小改范围，读取特殊格式说明；不强行重绘为四通道，也不扩展成全量渲染路线探索。源码与真实导图分别核验。

## 写入结果未知

前置：更新请求超时，查询返回 doc is applying。检查：有界等待并读取状态，不重复创建或盲目重写；无法导出时说明当前证据边界，不用本地图假装已验收。
