## 1. 从用户工作流开始

先画用户怎样完成任务：

```text
进入体系
  ↓
找到稳定知识或架构
  ↓
读取当前状态
  ↓
完成当前任务
  ↓
写回证据和状态
```

文档边界应围绕这条工作流中的独立问题，而不是围绕文件类型、作者、框架或历史写作批次。

创建新文件前回答：

1. 用户在什么时刻需要它？
2. 它独立回答哪个问题？
3. 哪份现有产物不能回答这个问题？
4. 删除它会丢失什么独立信息？

无法回答时不创建。

## 2. 三层产物模型

### 稳定结构

保存长期边界和定义：

```text
知识总纲
架构主干
协议与契约
题库与来源
资料和证据索引
```

### 动态状态

保存当前事实：

```text
进度
薄弱点
实验结果
项目状态
风险与决策
```

### 生成视图

读取前两层，为当前任务临时编译：

```text
当前课程单元
当前执行计划
某次评审稿
面试训练
阶段报告
```

判断公式：

```text
稳定结构 + 动态状态 + 当前目标 = 生成视图
```

如果一份文件同时承担三层职责，应优先拆开；如果两份文件属于同一层且回答同一问题，应优先合并。

## 3. 唯一真相源

同一问题只能有一份权威内容。

| 问题 | 推荐真相源 | 其他位置 |
|---|---|---|
| 完整知识边界是什么 | 知识总纲 | 一句定位和链接 |
| 当前掌握到哪里 | 学习进度 | 读取状态，不复制 |
| 真实问题有哪些 | 题库 | 引用题目编号和原文 |
| 依据是什么 | 资料索引或证据卡 | 引用来源 |
| 当前应该学什么 | 动态生成的 CU | 声明生成依据 |

冲突时按“问题所有权”解决，而不是按文件更新时间解决。

定义去重使用：

```text
一句定位 + 主归属链接
```

不要再次复制完整定义、分类、失败边界和知识树。

## 4. 多文档职责

创建多文档前先输出职责表：

| 文档或产物 | 所属层 | 唯一回答的问题 | 权威内容 | 不包含 |
|---|---|---|---|---|
| README | 入口 | 从哪里开始 | 导航 | 完整知识 |
| 总纲 | 稳定结构 | 应该知道什么 | 唯一定义 | 学习日志 |
| 进度 | 动态状态 | 掌握到哪里 | 状态和证据 | 机制解释 |
| 资料索引 | 稳定结构 | 依据什么 | 来源与版本 | 学习顺序 |
| 当前 CU | 生成视图 | 现在学什么 | 当前推导和训练 | 永久知识边界 |

学习体系的运行关系：

```text
architecture-research
  维护知识总纲、依赖、证据和文档职责
  ↓
course-delivery-orchestrator
  根据总纲、进度和目标生成当前双轨 CU
  ↓
学习证据与待核实缺口
  ├─ 写回进度
  └─ 经研究核实后再更新总纲
```

同层去重时比较：

- 控制权由谁持有。
- 状态由谁维护。
- 失败在哪里处理。
- 对外契约是什么。

四点都相同时考虑合并。

## 5. 方法与内容分离

内容文档保存：

- 知识、架构、证据和状态。
- 真实案例、实验结果和决策记录。

Skill、脚本或自动化保存：

- 如何调研、生成、授课和复核。
- 产物合同、检查清单和质量门禁。
- 动态选择、状态迁移和批量操作规则。

同一方法若需要被 Agent 重复执行，不应复制到每个仓库的“学习方法”“课程模板”“写作说明”中。仓库只保留必要的入口和项目特有约束。

## 6. 快照和生成视图

固定课表、季度路线图和阶段计划只有在业务要求固定排期时才是稳定契约。其他情况下它们属于带时间的快照。

生成视图至少声明：

```text
生成时间：
当前目标：
稳定输入：
动态输入：
选择依据：
失效条件：
写回位置：
```

生成视图完成后只能写回：

- 新证据。
- 新状态。
- 已核实的知识缺口。

不能因为某次视图采用了一个分组，就直接把该分组升级为永久知识架构。

## 7. 迁移与完整性

重构前建立迁移台账：

| 旧内容 | 原职责 | 新主归属 | 所属层 | 处理方式 | 原因 |
|---|---|---|---|---|---|

处理方式包括：

- 原样迁移。
- 重命名。
- 拆分。
- 合并。
- 降级为案例。
- 改为动态状态。
- 改为生成视图。
- 迁移到 Skill。
- 删除。

完成后检查：

- 旧知识点是否全部有去向。
- 每个问题是否只有一个真相源。
- 方法规则是否已经离开内容层。
- 生成视图是否声明依据和失效条件。
- README 是否能到达所有正式产物。
- 是否存在孤立文档和失效链接。
