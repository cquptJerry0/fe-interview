# 用户评审门禁

## 总原则

知识体系调研与总纲设计默认采用三次评审。每次只让用户评审当前最重要的决策，不要求用户一次检查所有细节。

用户明确说“我先评审”“先不改”“确认后再写”时，门禁不可跳过。

用户明确要求“一步到位”时，可以连续执行，但仍要在最终结果中展示三阶段关键决策。

## 第一次评审：研究设计

### 评审目标

确认研究问题、边界、来源和证据门槛，避免搜索范围无限扩张。

### 必须展示

```text
核心决策问题
研究范围
非目标
关键假设
来源分层
准备调研的对象及理由
预期产物
```

### 不应展示

- 大量正文。
- 最终架构结论。
- 尚未查证的框架功能清单。

### 确认问题

```text
这组研究问题、资料范围和证据要求是否成立？确认后再执行完整调研。
```

## 第二次评审：统一架构

### 评审目标

确认多来源合订后的问题分类、概念边界和文档职责。

### 必须展示

```text
核心判断
统一心智图
一级结构
概念归一结果
主要冲突与处理
文档职责表
旧内容迁移策略
一个细颗粒度章节示例
```

### 不应展示

- 所有章节的完整正文。
- 大量低层框架 API。
- 未经确认的文件改动。

### 确认问题

```text
这套主干、章节边界和文档职责是否成立？确认后先写一个完整样章。
```

## 第三次评审：完整样章

### 评审目标

确认颗粒度、语言、英文注释、图表密度和掌握要求。

### 必须展示

- 一个完整章节。
- 核心知识点。
- 概念边界。
- 失败模式。
- 最小实验或验证。
- 英文术语注释示例。

### 确认问题

```text
这个样章的颗粒度、中文表达和英文注释是否符合预期？确认后按同一标准批量落地。
```

## 修改授权

研究结论获得认可不自动等于文件修改授权。

需要创建、修改、删除或改名文件时，必须单独说明：

- 要修改哪些文件。
- 每个文件职责如何变化。
- 是否删除或迁移旧文件。
- 如何验证没有遗漏。

收到明确的“可以”“OK”“同意”后再执行。

## 评审反馈处理

用户指出“结构不对”时，先修正：

1. 主问题。
2. 一级结构。
3. 文档职责。
4. 章节归属。

不要先润色句子。

用户指出“看不懂”时，先检查：

1. 是否缺少最简心智。
2. 是否连续堆英文。
3. 是否只有术语没有机制。
4. 是否缺少真实例子。
5. 是否把多个抽象层混在一起。

用户指出“内容缺斤少两”时，先回到迁移台账和覆盖矩阵，不直接增加零散段落。
