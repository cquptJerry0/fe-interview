# 统一规则

## 内容规则

- 默认中文。
- 先结论，后展开。
- 单题入口卡统一只保留 `2` 个大 Part：`Part 1｜技术讲解`、`Part 2｜面试作答`。
- `Part 1` 负责把技术讲清楚；`Part 2` 负责把答案说出去。
- `Part 1` 允许按题型选择不同讲法，不再强制所有题都套同一组固定小标题。
- 不引用外部文档；仓里没有的关键知识，不是跳过，而是先补清，再决定是否沉淀专题。

## 入口卡的新标准

### Part 1｜技术讲解

最低要求：

- 有直接回答题面的结论。
- 有主链路图或结构化可视化。
- 有能证明结论的材料，如最小例子、反例、伪代码、对比表。
- 有工程视角，说明为什么真实项目里会踩坑。

### Part 2｜面试作答

最低要求：

- 有 `20 秒快答`。
- 有 `60-90 秒口语稿`。
- 有 `3` 个以上高频追问详答。
- 有 `关联专题 / 复习标记`。

## 专题深挖的新标准

专题深挖卡是系统知识链，不是单题尾巴。它至少满足：

1. 能从底层规则串到上层表现，形成完整链路。
2. 能覆盖 `3` 个以上相关知识点，而不是只解释一个名词。
3. 需要多张图才能讲清，不靠一段口语稿糊过去。
4. 能承接多个入口卡，而不是只服务一道题。

专题卡最低组成：

- `总览图`
- `分段链路`
- `关键误判点`
- `反例 / 对比`
- `业务化案例`
- `排查视角`
- `追问地图`
- `回链入口卡`

## 图解优先规则

适用范围：

- CSS
- 布局
- 滚动
- 溢出
- 定位
- 可视区
- 尺寸 / 坐标计算

最低要求：

- 这类题默认重图解，弱化纯属性堆砌。
- 至少 `2` 张 ASCII 图。
- 图里必须说明约束关系、失败原因或打断方式。
- 如果存在兼容 / 回退方案，必须说明方案差异和代价。

## 难题加厚规则

### 默认触发范围

- JS 执行机制
- React 原理
- 状态管理
- 性能优化
- 网络与缓存
- 多层追问明显的开放题

### 最少固定增加

- `1` 张额外图
- `1` 个额外反例或业务例子
- `1` 段精炼伪代码或判断步骤

### 加厚原则

- 加厚是为了更容易理解，不是为了堆概念。
- 口语稿不跟着无限变长，额外内容优先补在图、例子、伪代码里。
- 加厚后的内容应做到：不继续追问，也能看懂主链路。

## 命名规则

- 入口卡尽量一题一文件、一知识点一文件。
- 专题深挖按“系统链路”命名，不按零碎名词命名。
- 目录里只列真实存在的专题文件；未落地内容放到“规划中”，不混进正式条目。

## 评分规则

### 逻辑性

- 有没有直接回答题面。
- 图能不能把链路画清。
- 证明材料能不能撑住结论。

### 面试满分度

- 快答能不能先占位。
- 口语稿能不能直接复述。
- 有没有业务化解释。
- 有没有追问和边界。

### 体系化程度

- 单题有没有明确挂到专题。
- 专题有没有承接多个入口卡。
- 是否做到“入口卡解决怎么答，专题卡解决继续往下挖什么”。
