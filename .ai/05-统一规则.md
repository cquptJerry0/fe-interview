# 统一规则

## 内容规则

- 默认中文。
- 先结论，后展开。
- 单题统一只保留 3 个模块：`主回答`、`深入展开`、`追问与详细回答`。
- 每个模块都必须有固定小标题，不能临场自由发挥结构。
- 先确认答案，再抽象 SOP；不要只写流程，不校准答案。
- 不引用外部文档；缺失知识统一沉淀为内部专题。

## 难题加厚规则

### 默认触发范围

- React 原理
- 状态管理
- 性能优化
- 网络与缓存
- 复杂场景题
- 多层追问明显的对比 / 开放题

### 最少固定增加

- `1 张额外 ASCII 图`
- `1 个额外例子`
- `1 段精炼伪代码`

### 加厚原则

- 多图、多例子、精炼伪代码属于理解辅助，不属于冗余展开。
- 加厚版不新增第 4 个模块，只在现有 3 个模块内补内容。
- 难题内容要做到：读者无需继续追问，也能看懂主链路。

## 命名规则

- 题库卡尽量一题一文件、一知识点一文件。
- 综合入口卡可以存在，但必须链接到内部深挖卡。
- 编程题一题一个文件，除非真的需要独立 Demo。

## 评分规则

### 逻辑性

- 有没有先说结论。
- 图能不能把链路画清。
- 口语稿能不能直接复述。

### 面试满分度

- 有没有最小例子。
- 有没有业务化解释。
- 有没有取舍和易错点。
- 有没有追问与详细回答。
- 能不能自然挂到内部深挖链路。

### 难题完成度

- 有没有额外图。
- 有没有额外例子。
- 有没有精炼伪代码。
- 是否做到不继续追问也能看懂主链路。
