# 面试仓库使用说明

这个仓库现在是秋招上场系统，不再只是旧的面经仓。

核心判断只有一个：

```text
这个内容现在能不能上考场？
```

## 内容结构

这个仓库包含五块：

1. `raw`：原材料区，只放来源、摘录和提取问题，不写完整答案。
2. `bagu`：八股主系统，放概念、原理和高频问题的可上场答案。
3. `coding`：手写主系统，放题型、思路、标准实现和口述模板。
4. `project`：项目主系统，放项目故事线、技术选择、追问和兜底。
5. `tracker`：唯一主表，维护线别、模块、条目、状态、Git 文件和下一步动作。

## 默认工作方式

1. 用户输入一篇面经时，优先使用 `[01-intake-interview](/Users/bytedance/Projects/personal/面试/.ai/skills/01-intake-interview/SKILL.md)`。
2. 用户要求回答某道题或沉淀某个主题时，优先使用 `[02-answer-question](/Users/bytedance/Projects/personal/面试/.ai/skills/02-answer-question/SKILL.md)`。
3. 输入是原材料时，优先进入 `raw`。
4. 输入已经是可复习、可口述、可手写、可追问的内容时，优先进入 `bagu / coding / project`。
5. 进度和状态只维护在 `tracker/master.csv`，飞书表是同步视图，不是正文真源。

## 路由规则

1. 面经正文进入 `raw/mianjing`。
2. 学习来源、文章、官方文档进入 `raw/learning-sources`。
3. 旧索引、旧笔记、暂时无法直接复用的历史材料进入 `raw/old-notes`。
4. JavaScript、浏览器、React、Vue、408 等概念和原理问题进入 `bagu`。
5. JS 手写、React 手写、LeetCode 题型进入 `coding`。
6. AI 项目、后端、数据库、Redis、Hive、项目故事线进入 `project`。

## 统一约束

1. 默认中文。
2. `20 秒快答` 统一替换成 `思维导图关键点`。
3. `60-90 秒口语稿` 的结尾，默认补 1 句工程或业务例子。
4. 没有用户明确授权，不修改文件。
5. raw 里不写完整答案。
6. 不把飞书和 Git 都当正文内容库。
7. 专题题默认先搜索最新官方或一手资料，再动笔；不要只靠旧记忆写成传统八股。
8. 代码输出题默认保留原始题干和原始代码，不能只剩结论。
9. 多道输出题如果共享同一条底层知识链，优先合并成一个总专题，不要拆成多个浅专题。
10. `JS 底层` 这类专题，默认至少覆盖：编译时、运行时、执行上下文、环境记录、词法作用域、作用域链、`this`、箭头函数、原型、原型链、闭包、`Promise Job`、微任务、宿主事件循环和渲染边界。
