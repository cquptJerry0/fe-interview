# answer-coaching（满分答案 Skill）

## 目标

输出“可口述、可追问、可落地”的满分答案，并按题型自动切换解题攻略，而不是用一套模板覆盖所有题。

## 输入

- 单题：`title/type/tags/difficulty`
- 用户口述答案（可选）
- 路由策略（快答/深讲/教到会）

## 输出

- 双评分：逻辑性 + 面试满分度（0-10）
- 扣分点（每项 <=3 条，必须可改）
- 改写版满分回答（按题型路由）
- 追问脚本（4 轮：理解/边界/取舍/排障）
- 费曼复述检查清单（教到会时必给）

## 执行流程

1. 识别题型：优先用 `type`，缺失时按 `title/tags` 推断。
2. 路由攻略：根据题型加载对应 reference（见下表）。
3. 生成答案：先满足 4 个必选块，再补充题型特有模块。
4. 质量校验：检查证据、取舍、边界、排障是否完整。
5. 输出评分：按统一评分标准给出分数与可执行改进点。

## 题型路由（核心）

- 八股题 -> `.ai/references/answer-strategies/01-八股题攻略.md`
- 场景题 -> `.ai/references/answer-strategies/02-场景题攻略.md`
- 开放题 -> `.ai/references/answer-strategies/03-开放题攻略.md`
- 手写题 -> `.ai/references/answer-strategies/04-手写题攻略.md`
- 项目复盘题 -> `.ai/references/answer-strategies/05-项目复盘攻略.md`

推断规则（当 type 缺失）：
- 包含“怎么实现/原理/区别/为什么”优先判为八股题
- 包含“如果你来做/线上故障/性能抖动/怎么排查”优先判为场景题
- 包含“怎么看/如何取舍/架构演进”优先判为开放题
- 包含“手写/实现一个/封装一个”优先判为手写题
- 包含“你做过/项目里/负责过”优先判为项目复盘题

## 统一强约束（所有题型都必须满足）

- 回答必须包含 4 个必选块：技术解释、业务举例、面试口述版（60-90秒）、追问
- 其他内容（图解/对比取舍/实践验证/易错点）按题型补充
- 每题至少 1 条可验证证据（指标/日志/实验/最小复现任一）
- 追问参考答法必须可 15-30 秒口述
- 评分口径统一走 `.ai/policies/02-评分标准与维度.md`

## 质量门禁（输出前自检）

- 技术解释：必须有“机制 + 约束 + 最小例子”
- 业务举例：必须有“背景与约束 / 方案与取舍 / 实施与验证 / 结果与复盘”
- 面试口述版：可连续读完，不是碎片 bullet
- 追问：至少 3 个，覆盖边界、取舍、排障
- 禁止空话：避免“优化了很多、效果很好”这类无证据描述

## 边界说明

- 当题目类型为“编程”时，不在本 skill 内展开代码细节，转交 `coding-exercise`
- 当题目包含多类型复合（如“原理 + 场景”），主类型按题干诉求选，次类型作为补充段落
