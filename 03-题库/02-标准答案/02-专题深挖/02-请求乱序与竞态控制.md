## 为什么要深挖这题

因为很多人只会说“加防抖”，但请求乱序本质是异步竞态，和触发频率不是同一个问题。

## 上游原理

- 用户输入会连续触发多次请求
- 后发请求不一定后返回
- UI 如果不做保护，旧结果会覆盖新结果

## 核心机制拆解

常见两种方案：
- `AbortController`：直接取消旧请求
- 请求序号：只认最后一次请求结果

## Demo / 最小复现

```js
let latestId = 0

async function search(keyword) {
  const requestId = ++latestId
  const result = await fetchData(keyword)
  if (requestId !== latestId) return
  render(result)
}
```

## 排障脚本

- 人工快速输入：观察结果是否闪回旧数据
- 日志里打请求序号和关键词
- 看旧请求是否在新请求完成后仍然回写 UI

## 什么时候该用 / 不该用

- 搜索、筛选、联想输入必须考虑
- 单次点击提交类请求通常不是主要矛盾
