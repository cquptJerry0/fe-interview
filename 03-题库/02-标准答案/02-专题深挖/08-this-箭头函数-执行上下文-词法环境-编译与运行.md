# JS 核心执行机制链路

这张专题卡不是单点补丁，而是把下面这条链一次打通：

`编译时规则 -> 执行上下文创建 -> 词法环境 / 变量环境 -> 作用域链 -> 普通函数 this -> 箭头函数 this -> 闭包`

## 1. 先看整条链的总览图

```txt
源码写出来
  -> 先确定函数定义位置
  -> 先确定词法作用域关系

代码真正执行
  -> 为每次调用创建执行上下文
  -> 放入 this / arguments / 变量环境 / 词法环境

运行中取值
  -> 普通标识符沿作用域链查找
  -> 普通函数 this 看调用方式
  -> 箭头函数 this 沿外层词法环境拿

函数离开原位置后仍被引用
  -> 外层环境继续保留
  -> 闭包成立
```

这条链里最容易混掉的，不是某个定义本身，而是下面三组边界：

- `编译时确定规则` vs `运行时拿到具体值`
- `调用栈` vs `作用域链`
- `普通函数 this` vs `箭头函数 this`

## 2. 编译时先定什么，运行时再定什么

### 2.1 编译时 / 解析时先确定的东西

- 函数定义在什么位置。
- 标识符应该沿哪条外层词法链往外找。
- 箭头函数没有自己的 `this`，以后只能向外层环境拿。

### 2.2 运行时才会确定的东西

- 当前这次调用会创建哪一个执行上下文。
- 普通函数这次调用的 `this` 到底是谁。
- 当前作用域链上每一层环境里，变量最终是什么值。

```txt
最稳的回答方式：

不是“纯编译时”
也不是“纯运行时”

而是：
  规则是静态的
  值是在运行时按规则拿到的
```

## 3. 执行上下文、变量环境、词法环境到底是什么关系

```txt
调用一个函数
  -> 创建执行上下文 EC
  -> EC 里会关联：
       this
       arguments
       Variable Environment
       Lexical Environment

后续代码执行时
  -> 变量 / 函数声明放到对应环境记录里
  -> 标识符查找沿外层环境引用往外找
```

面试里不必把规范术语讲得特别学院化，但至少要知道：

- 执行上下文是“这次执行的运行容器”。
- 词法环境可以理解成“这层作用域里有哪些绑定，以及它的外层是谁”。
- 变量环境、词法环境在很多面试语境下可以先粗理解成“这次执行可访问的绑定集合”，但如果被追问，就要知道它们不是完全同一个概念。

## 4. 作用域链：变量为什么从这里往外找

### 4.1 先看代码

```js
var a = 10

function test() {
  console.log(a)
}

function fn() {
  var a = 20
  test()
}

fn()
```

### 4.2 为什么输出是 `10`

```txt
test 定义在全局
  -> test 的外层作用域已经确定是全局

运行 fn()
  -> 只是让 fn 进入调用栈
  -> 不会改写 test 原本的外层作用域指向

所以 test 查找 a
  -> 先看自己
  -> 再沿定义时确定的外层链往全局找
  -> 找到 a = 10
```

这里最容易混掉的是两条链：

- 调用栈：谁先执行、谁后执行。
- 作用域链：变量应该往哪找。

调用关系不会改写词法作用域关系。

## 5. 普通函数 `this`：由调用方式决定

### 5.1 判断核心

- 普通函数有没有自己的 `this`？有。
- 这个 `this` 看什么？看这次调用方式。

```txt
obj.fn()
  -> this 通常指向 obj

fn()
  -> 浏览器非严格模式普通脚本里常见是 window
  -> 严格模式 / ES Module 里常见是 undefined

fn.call(x)
  -> this 指向 x
```

### 5.2 常见误判

- 不要把普通函数的 `this` 理解成“定义在谁里面就永远是谁”。
- 对普通函数来说，定义位置不决定 `this`，调用方式才决定。

## 6. 箭头函数 `this`：没有自己的，只能向外层拿

### 6.1 先看代码

```js
const obj = {
  name: 'obj',
  fn1() {
    const fn = () => this.name
    return fn
  },
}

const other = { name: 'other', fn1: obj.fn1 }

const a = obj.fn1()
const b = other.fn1()

console.log(a()) // obj
console.log(b()) // other
```

### 6.2 为什么两次结果不同

```txt
调用 obj.fn1()
  -> 这次外层普通函数 fn1 的 this = obj
  -> 在这次调用里创建的箭头函数
  -> 记住外层 this = obj

调用 other.fn1()
  -> 这次外层普通函数 fn1 的 this = other
  -> 在这次调用里创建的箭头函数
  -> 记住外层 this = other

所以不是“箭头函数在编译期把 this 永远写死成某个对象”
而是：
  规则静态确定：没有 own this，只能向外拿
  具体拿到谁：取决于创建它那次外层调用的 this
```

### 6.3 为什么 `call / apply / bind` 对箭头函数不生效

- 因为这些 API 能改的是“有自己动态 `this` 的函数”。
- 箭头函数没有这个槽位，它只会回外层词法环境里拿。

## 7. 闭包：为什么函数离开原位置后还能继续访问外层变量

```txt
函数定义位置确定
  -> 外层词法环境关系确定

函数执行时创建环境
  -> 如果内部函数被外部继续引用
  -> 外层环境不会立刻释放

结果
  -> 后续还能继续访问外层变量
  -> 这就是闭包
```

闭包不是额外神秘机制，它只是“词法作用域 + 外部引用仍然存在”的自然结果。

## 8. 关键误判点总表

| 误判 | 更准确的说法 |
| --- | --- |
| 箭头函数的 `this` 是编译时决定的 | 规则是静态的，但具体值取决于创建它那次外层调用 |
| 谁调用函数，函数就用谁的作用域 | 调用关系只影响执行栈，不改写词法作用域 |
| 普通函数和箭头函数的 `this` 只是写法不同 | 普通函数有自己的动态 `this`，箭头函数没有 |
| 闭包等于匿名函数 | 命名函数一样可以形成闭包 |
| 一有内存问题就是闭包泄漏 | 真正的问题通常是不必要的长生命周期引用 |

## 9. 反例 / 对比

### 9.1 普通函数 vs 箭头函数

```js
const obj = {
  name: 'obj',
  normal() {
    return function () {
      return this && this.name
    }
  },
  arrow() {
    return () => this.name
  },
}

const normalFn = obj.normal()
const arrowFn = obj.arrow()
```

```txt
normalFn()
  -> 看 normalFn 这次怎么被调

arrowFn()
  -> 不看 arrowFn 自己怎么被调
  -> 只看创建它那次外层 arrow() 的 this
```

### 9.2 `var` vs `let`

```js
for (var i = 0; i < 3; i++) {
  setTimeout(() => console.log('var', i), 0)
}

for (let j = 0; j < 3; j++) {
  setTimeout(() => console.log('let', j), 0)
}
```

```txt
var 场景
  -> 多个回调共享同一个绑定

let 场景
  -> 每轮循环有独立绑定
```

## 10. 业务化案例

- 回调函数被传来传去，很多人以为“在哪调就用哪层变量”，结果把调用栈和作用域链混了。
- 事件处理函数里如果随手写箭头函数，往往是为了稳定拿住外层上下文；但如果你本来需要的是“由调用者决定 this”，箭头函数就不合适。
- React 里的 stale closure，本质上也是闭包带来的“回调拿到创建那一刻变量快照”的问题。

## 11. 排查视角

### 11.1 看到 `this` 不对时

- 先判断这是普通函数还是箭头函数。
- 如果是普通函数，回到调用方式看：`obj.fn()`、`fn()`、`call/apply/bind()` 分别是什么。
- 如果是箭头函数，回到“它是在哪一次外层调用里被创建的”。
- 再确认当前是不是严格模式或 ES Module。

### 11.2 看到变量取值不对时

- 先看函数定义位置，不要先看调用位置。
- 画出“当前层 -> 外层 -> 更外层”的词法链。
- 分清是作用域链问题，还是调用栈导致的执行时序问题。

### 11.3 看到内存占用升高时

- 看是不是有事件监听、定时器、缓存、全局数组把函数长期留住了。
- 看闭包里是不是抓着大对象、DOM 或上下文。
- 排查重点是解除引用，不是机械地“禁用闭包”。

