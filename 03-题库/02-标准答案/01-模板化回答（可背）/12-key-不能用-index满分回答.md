## 这题在问什么

这题不是在挑语法细节，而是在问你有没有理解：
- `key` 在 diff 里到底起什么作用
- 为什么“看起来能跑”的 index，在插入/删除/排序时会埋 bug
- 这种 bug 为什么常常表现成状态错位

## 60 秒直答

`key` 的作用是给列表项一个稳定身份，让框架在 diff 时知道“这是同一个节点”，还是“这是新节点”。如果用 `index` 当 key，在列表新增、删除、排序时，后面节点的 key 会整体漂移，框架就可能把旧节点错误复用到新位置上，导致输入框值、组件内部状态、动画状态错位。所以只有在列表完全静态、不插入不排序时，`index` 才勉强可接受；只要列表会变，优先用业务唯一 id。

## 核心机制

- diff 不是只看内容，还看节点身份
- `key` 稳定，框架才能稳定复用节点
- `index` 不稳定，尤其在中间插入或排序时问题最大

## 最小例子

```jsx
{list.map((item, index) => (
  <InputRow key={index} value={item.value} />
))}
```

如果你在列表头部插入一项，后面的 `index` 全变了，旧组件状态就可能跟着错位。

## 业务 / 验证

我会用输入框列表示例解释最直观：
- 每一行都有内部输入状态
- 中间插入一行后，如果 key 用 index，原来第二行的状态可能跑到第三行
- 验证方式就是做一个最小 demo：输入几行内容，再在顶部插入一项，看值是否串位

## 常见追问

- 哪些场景下用 index 勉强还能接受？
- key 是不是只影响性能，不影响正确性？
- React 和 Vue 在 key 上的思路是否一样？
- 如果没有后端 id，该怎么生成稳定 key？

## 易错点

- 只会背“index 不好”，举不出状态错位例子
- 把 key 问题只讲成性能问题
- 忽略“静态列表”和“动态列表”的边界差别
