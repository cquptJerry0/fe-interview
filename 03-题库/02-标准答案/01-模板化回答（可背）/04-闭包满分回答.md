## 模块 1｜主回答

### 1）一句话结论

- 闭包可以理解成：函数在定义时记住了它所在的词法作用域，所以即使外层函数已经执行结束，内部函数仍然能访问当时作用域里的变量。
- 它解决的核心问题是“状态保留”和“封装私有数据”。
- 但如果闭包长期持有不再需要的大对象、DOM 引用或上下文，就可能让这些数据无法及时被回收，带来内存占用问题。

### 2）原理图（ASCII）

```txt
outer()
  let count = 0
  return function inner() {
    count++
  }

调用 outer()
  -> 生成 inner
  -> inner 持有 outer 的词法环境引用
  -> 即使 outer 执行结束
  -> count 仍可被 inner 继续访问
```

### 3）最小例子

```js
function createCounter() {
  let count = 0

  return function () {
    count += 1
    return count
  }
}

const counter = createCounter()
console.log(counter()) // 1
console.log(counter()) // 2
```

### 4）面试口语稿

- 闭包我会这样讲：函数不仅有代码本身，还有它定义时所在的词法环境。只要内部函数在外部被继续引用，这个词法环境里的变量就不会立刻消失，所以内部函数后续还能访问它们。它最核心的价值是保留状态和封装私有数据，比如计数器、柯里化、once、缓存函数这些都离不开闭包。但闭包也不是天然有问题，真正的风险在于你让它长期持有了本来该释放的大对象、DOM 或上下文，结果垃圾回收回不掉，最后表现成内存占用越来越高。

## 模块 2｜深入展开

### 1）原理链路

```txt
为什么外层函数结束了，变量还在？
  -> 因为内部函数还被引用
  -> 内部函数持有外层词法环境
  -> 只要引用关系还在
  -> 这部分环境就不能被回收
```

- 这题不能只答“函数加上它能访问的变量就是闭包”，还要讲清“为什么它能保留状态”。
- 关键点是：变量能不能被回收，不看函数是不是执行结束，而看有没有活跃引用还在使用它。
- 闭包不是额外神秘机制，本质还是词法作用域和引用关系共同作用的结果。

### 2）业务化解释

- 项目里闭包经常出现在防抖、节流、once、缓存、工厂函数、自定义 Hook 里。
- 比如防抖函数要记住上一次 `timer`，如果没有闭包，这个状态就没法在多次调用之间共享。
- 另一个典型场景是模块私有状态：外部只暴露方法，不直接暴露内部变量。
- 所以闭包不是“少数高级题”，而是日常 JavaScript 工程里非常常见的基础能力。

### 3）取舍 / 易错点

- 闭包本身不是性能问题，只有在它保留了不该长期保留的数据时，才可能带来内存负担。
- 常见误区 1：把闭包和匿名函数画等号，实际上命名函数一样可以形成闭包。
- 常见误区 2：只会背定义，举不出真实场景。
- 常见误区 3：一听到内存泄漏就怪闭包，真正的问题往往是引用没有解除。
- 循环里配合 `var` 产生的共享变量问题，本质上也是闭包加作用域行为共同导致的经典坑。

- 这题可以进入模板化回答。

### 难题加厚｜额外图

```txt
闭包导致对象被保留的常见链路

handler 被全局数组保存
  -> handler 闭包引用 bigData
  -> bigData 引用大量对象 / DOM
  -> 只要 handler 不释放
  -> bigData 就无法被回收
```

### 难题加厚｜额外例子

```js
function bindPreview(node, data) {
  function onClick() {
    console.log(data.title)
  }

  node.addEventListener('click', onClick)

  return () => {
    node.removeEventListener('click', onClick)
  }
}
```

- 如果页面卸载后不解绑，而 `data` 又很大，这个闭包就可能让数据继续被持有。

```txt
createFn():
  env = { value: 0 }
  return function inner():
    env.value += 1
    return env.value
```

## 模块 3｜追问与详细回答

### 追问 1｜闭包和作用域链是什么关系？

- 作用域链描述的是“查找变量时按什么路径往外找”。
- 闭包描述的是“函数为什么能在定义位置之外，继续访问原来作用域里的变量”。
- 两者相关，但不是同一个概念。
- 你可以理解成：闭包成立的底层前提，就是 JavaScript 的词法作用域和作用域链查找规则。

### 追问 2｜为什么循环里配合 `var` 容易出问题？

- 因为 `var` 是函数作用域，不会像 `let` 一样为每次循环创建独立块级绑定。
- 如果循环里注册回调，这些回调后面执行时，拿到的往往是同一个共享变量。
- 所以经典现象就是循环结束后，回调都读到同一个最终值。
- `let` 之所以更自然，是因为每轮循环都有新的绑定。

### 追问 3｜闭包为什么会和内存泄漏放在一起问？

- 因为闭包会延长某些变量的生命周期。
- 如果这些变量本来已经不需要，但由于闭包仍被外部引用，它们就回收不了。
- 所以问题不在“闭包”这个词本身，而在“有没有不必要的长生命周期引用”。
- 这也是为什么事件监听、定时器、缓存和全局数组最容易牵出这类问题。

### 追问 4｜闭包常见的项目用途有哪些？

- 计数器、once、柯里化、防抖、节流、缓存函数、工厂函数都很常见。
- 这些场景共同点都是：需要在多次调用之间保留某个状态。
- 如果面试时能从“状态保留”和“私有封装”两个角度一起回答，会更完整。
- 不要只停在抽象定义层。

### 追问 5｜闭包和 React 里的 stale closure 有什么关系？

- stale closure 本质上也是闭包现象：回调拿到的是它创建那一刻的变量快照。
- 如果后续状态变了，但这个回调没有更新引用，它就可能继续读旧值。
- 所以 React 里很多旧值问题，不是“闭包错了”，而是你没有正确处理依赖和回调更新。
- 面试里能把普通闭包和框架场景串起来，通常会比较加分。
