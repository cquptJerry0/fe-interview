## 这题在问什么

不是只问你“定义是什么”，而是在问：
- 闭包到底为什么能保存状态
- 它在项目里怎么用
- 为什么它又可能引发内存泄漏和 stale 数据问题

## 60 秒直答

闭包就是函数和它创建时所在词法作用域的组合。最实用的理解不是背定义，而是“函数执行完了，外层变量本来该销毁，但因为内部函数还在引用，所以这些变量继续存活”。它最常见的价值是保存状态、做私有变量、封装回调；最常见的风险是定时器、事件监听、异步回调长期持有旧引用，导致内存泄漏或数据过期。

## 核心机制

- JS 用词法作用域决定变量查找路径
- 内部函数引用外部变量时，外层环境不会被立即回收
- 所以闭包能“记住”之前的状态

## 最小例子

```js
function createCounter() {
  let count = 0
  return function () {
    count += 1
    return count
  }
}

const counter = createCounter()
console.log(counter()) // 1
console.log(counter()) // 2
```

## 业务 / 验证

项目里最常见的是搜索防抖、订阅回调、React effect 里的旧状态。验证思路不是抽象讲 GC，而是直接看：
- 组件卸载后定时器有没有清
- 事件监听有没有移除
- 回调里拿到的是不是旧值

## 易错点

- 只会说“函数套函数就是闭包”
- 只讲优点，不讲旧引用和泄漏风险
- 项目例子里讲不出清理动作
