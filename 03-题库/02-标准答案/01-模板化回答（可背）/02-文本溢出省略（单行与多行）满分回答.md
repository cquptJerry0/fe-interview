## 模块 1｜主回答

### 1）一句话结论

- 单行省略最稳的经典写法是：有明确可收缩宽度、`overflow: hidden`、`white-space: nowrap`、`text-overflow: ellipsis`。
- 多行省略没有像单行那样一个“又简单又绝对通用”的老方案；工程上通常分三档：主流方案是 `-webkit-line-clamp`，近似兼容方案是 `max-height + overflow + 伪元素 / 渐隐`，强控制方案是 `JS` 测量截断。
- 很多“写了 ellipsis 但不生效”的根因，不是属性名背错，而是元素根本没有进入“会溢出”的布局条件，尤其在 `flex` 布局里经常卡在 `min-width: auto`。

### 2）原理图（ASCII）

```txt
单行省略为什么容易成立？

文本一行排开
  -> 盒子宽度有限
  -> white-space: nowrap
  -> overflow: hidden
  -> text-overflow: ellipsis
  -> 浏览器只需要处理“一行末尾怎么画”
```

```txt
多行省略为什么更难？

文本会自动换行
  -> 浏览器先排版成第 1 行、第 2 行、第 3 行...
  -> 你要解决的不只是“末尾怎么画 ...”
  -> 而是“第 N 行后面怎么截断、怎么隐藏、怎么保持视觉自然”

所以多行省略通常变成：
  限制可见行数 + 隐藏超出内容 + 补视觉收口
```

```txt
如果盒子根本不收缩
  -> 就不会真正发生溢出
  -> 单行 ellipsis 不会出现
  -> 多行 clamp 也可能看起来“不像在工作”
```

### 3）最小例子

```css
.single-line {
```


```css
.flex-row {
  display: flex;
}

  min-width: 0;
  overflow: hidden;
  white-space: nowrap;
  text-overflow: ellipsis;

```

```js
function clampText(node, text) {
  let left = 0
  let right = text.length

  while (left < right) {
    const mid = Math.ceil((left + right) / 2)
    node.textContent = text.slice(0, mid) + '...'

    if (node.scrollHeight > node.clientHeight) {
      right = mid - 1
    } else {
      left = mid
    }
  }

  node.textContent = text.slice(0, left) + '...'
}
```

### 4）面试口语稿

- 文本省略我会分单行和多行讲。单行比较稳定，本质是让文本在有限宽度里不换行，再把超出的内容隐藏，并告诉浏览器在末尾画 `...`。多行就没这么简单，因为浏览器要先把文本排成多行，然后你还要控制只显示前几行，所以工程上通常有三档方案：主流是 `-webkit-line-clamp`，代码最短；如果要更保守兼容，可以退到 `line-height × 行数 = max-height` 再配合 `overflow` 和伪元素 / 渐隐做视觉收口；如果还要强控制，比如后面接“展开全文”或者高亮关键词，就要用 `JS` 测量截断。写了还不生效时，我不会先怀疑浏览器，而是先查布局条件，尤其是 `flex` 场景下子项默认 `min-width: auto`，这时候通常要补 `min-width: 0`。

## 模块 2｜深入展开

### 1）原理链路

```txt
为什么省略号不生效？
  -> 先看有没有发生真实溢出
  -> 再看 overflow 是否隐藏
  -> 单行场景是否禁止换行
  -> 多行场景有没有限制可见行数 / 可见高度
  -> flex 场景下元素是否允许收缩
```

```txt
max-height 兼容方案的核心关系

设：
  line-height = 24px
  想显示 3 行

那么：
  max-height = 24px * 3 = 72px

超过 72px 的文本内容
  -> overflow: hidden
  -> 被裁掉
  -> 再用 ... / 渐隐做视觉收口
```

```txt
flex 场景为什么常出问题？

父容器 display: flex
  |
  +-- 左侧图标 / 头像：固定宽度
  +-- 右侧标题：默认 min-width: auto

默认情况下
  标题会尽量保留自己的内容宽度
  -> 不愿意缩小
  -> 盒子不进入真正溢出状态
  -> ellipsis 看起来失效

补上 min-width: 0 后
  -> 标题允许收缩
  -> 才真正进入省略逻辑
```

- `text-overflow: ellipsis` 不是“自动截断神器”，它只是在溢出发生时告诉浏览器如何绘制结尾。
- 单行省略本质上只需要解决“这一行装不下了怎么办”。
- 多行省略则要解决“第 N 行之后的内容怎么裁、怎么收口、视觉是否自然”，所以天然比单行复杂。
- 这题本质上是“布局约束 + 溢出条件 + 视觉收口”一起看，而不是单独背某一个属性。

### 2）业务化解释

- 最典型的场景是卡片标题、列表项摘要、表格单元格和消息预览。
- 卡片和列表经常处在 `flex` 布局里：左边有头像或图标，右边是文本区域，所以 `min-width: 0` 是高频坑点。
- 摘要类文案通常更适合多行省略，因为用户至少还能看到前两三行语义；而表格列标题更常用单行省略，保持横向整齐。
- 如果后面还要接“展开全文”“查看详情”“高亮关键词”，纯 CSS 方案就未必够，需要考虑 `JS` 截断。

### 3）取舍 / 易错点

- `-webkit-line-clamp`：代码最短、主流项目最常用，但它更像工程上最实用的方案，不是那种特别朴素的老通用写法。
- `max-height + overflow + 伪元素 / 渐隐`：兼容思路更保守，但本质是“视觉近似”，`...` 不一定精确贴在最后一个可见字符后面。
- `JS` 截断：控制力最强，能处理“省略后还要接按钮 / 高亮 / 精确字符边界”，但复杂度最高，容器宽度变化、字体加载、`resize` 时都要重算。
- 单行和多行都要先确认“盒子是否真的受限”，否则根本谈不上溢出。
- `flex` 场景常见误区是漏掉 `min-width: 0`；表格场景常见误区是列宽其实没限制死；多行兼容方案常见误区是把“视觉看起来像省略”误当成“真实字符截断”。

## 模块 3｜追问与详细回答

### 追问 1｜为什么单写 `text-overflow: ellipsis` 不生效？

- 因为它只负责“溢出后怎么显示”，不负责制造溢出条件。
- 单行场景下，通常还需要 `overflow: hidden` 和 `white-space: nowrap`。
- 同时元素还要有可感知的宽度边界，否则文本会继续把容器撑开。
- 所以真正要检查的是“溢出有没有发生”，而不是只盯着 `ellipsis` 本身。

### 追问 2｜为什么 `flex` 布局里经常失效？

- 因为 `flex` 子项默认的 `min-width` 往往不是你想象中的 `0`，而是更偏向保留内容本身宽度。
- 这会导致文本区域根本不愿意缩小，自然也就不会发生溢出。
- 所以常见修复是给文本那一列补 `min-width: 0`。
- 这题很多人答不出来的关键点，就在这里：不是 ellipsis 坏了，而是布局约束没进来。

### 追问 3｜多行省略除了 `-webkit-line-clamp` 还有什么兼容方法？

- 有两类常见兜底。第一类是 `line-height × 行数 = max-height`，再配合 `overflow: hidden` 和伪元素 `...` 或渐隐遮罩做视觉收口。
- 这类方案的优点是思路简单、兼容更保守，缺点是它通常只是“视觉近似”，不是精确字符级截断。
- 第二类是 `JS` 测量截断，比如根据容器高度、`scrollHeight` 和字符范围做二分裁剪，再自己补 `...`。
- 它控制力最强，但实现和维护成本都更高。

### 追问 4｜`line-height × 行数 = max-height` 这套兼容思路到底在做什么？

- 它本质上是在用“可见高度”模拟“最多只显示几行”。
- 例如行高是 `24px`，想显示 `3` 行，那就把 `max-height` 设成 `72px`，再把超出的内容隐藏掉。
- 这样浏览器并不知道你想“精确省略到某个字符”，它只知道“盒子高度到这里为止”。
- 所以这类方案更多是高度裁切 + 视觉收口，不是严格意义上的字符级多行省略。

### 追问 5｜项目里到底该怎么选这三类方案？

- 如果是普通内容摘要、现代前端项目、没有特别苛刻的兼容要求，优先 `-webkit-line-clamp`。
- 如果你想要更保守兼容、且能接受“视觉近似”，用 `max-height + overflow + 伪元素 / 渐隐` 就够了。
- 如果省略后还要接交互、强调字符边界准确、或者要和高亮关键词等逻辑联动，就考虑 `JS` 截断。
- 所以这题不是“哪种最好”，而是“你要的是代码最短、兼容更稳，还是控制最强”。
