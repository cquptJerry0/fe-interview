## 这题在问什么

这题其实混了 3 个层次：
- 防抖：减少触发频率
- 节流：限制执行频率
- 搜索乱序：处理异步竞态，不是简单的频率控制

## 60 秒直答

防抖和节流的区别我会先讲清：防抖是“最后一次触发后再执行”，适合搜索输入；节流是“固定时间窗口内最多执行一次”，适合 scroll、mousemove。它们解决的是触发频率问题，但搜索乱序不是同一个问题：即使做了防抖，请求返回顺序仍可能乱。所以真实项目里我会把它拆成两层：前面用防抖减少请求次数，后面用 `AbortController` 或请求序号解决竞态覆盖。

## 核心机制

- 防抖：每次触发都重置 timer，只有停下来才执行
- 节流：时间窗口内只允许一次执行
- 请求乱序：后发的请求不一定后返回，所以要加“只认最新结果”的保护

## 最小例子

```js
function debounce(fn, delay) {
  let timer = null
  return (...args) => {
    clearTimeout(timer)
    timer = setTimeout(() => fn(...args), delay)
  }
}

function throttle(fn, delay) {
  let lastTime = 0
  return (...args) => {
    const now = Date.now()
    if (now - lastTime < delay) return
    lastTime = now
    fn(...args)
  }
}
```

## 业务 / 验证

搜索场景里我会这样说：
- 防抖把请求次数压下来
- 竞态保护保证 UI 只展示最新关键词结果
- 验证时看请求数、结果覆盖顺序、用户快速输入时 UI 是否稳定

## 常见追问

- 输入框搜索一定用防抖吗？什么时候用节流？
- 只做防抖为什么还会结果错乱？
- `AbortController` 和请求序号各有什么优缺点？
- React 里如何避免旧请求回写到已卸载组件？

## 易错点

- 把“防抖/节流”和“请求乱序”混成一个问题
- 只会写函数，不会讲场景和验证
- 没有提到取消请求或忽略过期响应
