## 这题在问什么

面试官通常想确认你有没有把这几个点串起来：
- 同步代码先执行
- 宏任务和微任务怎么排队
- 微任务为什么总比下一个宏任务先跑
- 浏览器渲染插在什么位置

## 60 秒直答

浏览器事件循环可以理解成：先执行当前这轮同步代码，同步代码里产生的微任务会在当前宏任务结束后立刻清空，然后事件循环再进入下一轮宏任务。常见宏任务有 script、setTimeout、I/O 回调，常见微任务有 Promise.then、queueMicrotask、MutationObserver。面试里我会强调两点：第一，微任务一定是在当前宏任务收尾时清空；第二，浏览器通常会在宏任务和微任务都处理完之后，找合适时机做渲染。

## 核心机制

- 整个 script 本身就是一个宏任务
- 同步代码执行过程中，微任务先进入微任务队列
- 当前宏任务结束后，立刻清空微任务队列
- 清空完成后，才有机会进入下一轮宏任务

## 最小例子

```js
console.log(1)
setTimeout(() => console.log(2), 0)
Promise.resolve().then(() => console.log(3))
console.log(4)
```

输出顺序是：`1 4 3 2`

## 业务 / 验证

这题最容易落到真实问题的是“你以为 setTimeout 很快执行，但 Promise.then 还是比它早”。比如某些状态更新、埋点上报、DOM 读取顺序异常，都可以用最小代码先验证。浏览器里直接开 Console 跑最小例子，就是最简单的验证方式。

## 常见追问

- `requestAnimationFrame` 属于哪一类，为什么常用在动画里？
- 微任务太多会发生什么？
- Node 里的事件循环和浏览器完全一样吗？
- 为什么有时候会觉得页面“卡住不渲染”？

## 易错点

- 把微任务和宏任务只当成背诵名词
- 忽略“当前宏任务结束后先清空微任务”这个核心规则
- 把浏览器和 Node 的事件循环完全混为一谈
