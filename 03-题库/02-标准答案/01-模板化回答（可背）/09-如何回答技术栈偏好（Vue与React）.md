## 这题在问什么

这题通常不是让你站队，而是看：
- 你有没有真实使用经验
- 你能不能客观表达偏好，而不是情绪化比较
- 你是否具备迁移和学习能力

## 60 秒直答

我不会上来就说哪个绝对更好，而是先说明自己的主要实践场景。比如如果我最近项目主要是 React，我会说自己在 React 生态里更熟，包括 Hooks、状态管理和工程实践；但 Vue 的响应式模型和单文件组件我也理解，切换到 Vue 项目不会有认知断层。最后我会补一句：技术选型不是个人偏好优先，而是看团队存量、业务复杂度和交付效率。

## 核心机制

- 先讲自己熟悉哪个生态
- 再讲另一个生态你也理解到什么程度
- 最后把话题落回“业务约束和团队协作”

## 最小例子

一个安全表达模板：

```text
我当前实践更多在 React，所以在 Hooks、组件抽象和状态管理这块更顺手。
Vue 我也用过，尤其是它的响应式和模板心智成本更低。
如果是我做技术选择，我会优先看团队存量、交付节奏和项目复杂度，而不是只按个人偏好拍板。
```

## 业务 / 验证

如果你真做过项目，可以补一句：
- 为什么当前项目选了 React / Vue
- 这个选择带来了什么收益或约束
- 如果换另一个框架，成本在哪里

## 常见追问

- 那你为什么当前项目不用 Vue / React？
- 两者在状态管理和组件抽象上的差异怎么看？
- 如果明天让你切到另一个技术栈，你准备怎么补？

## 易错点

- 直接贬低另一个技术栈
- 只谈情绪，不谈项目约束
- 说“我都会”，但举不出任何实践细节

## 关联深挖

- 如果继续追问原理，分别转到 React Hooks、Vue 响应式等内部卡片
