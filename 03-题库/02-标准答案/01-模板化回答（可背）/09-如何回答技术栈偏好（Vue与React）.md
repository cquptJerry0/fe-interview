## 模块 1｜主回答

### 1）选择结论

- 这题不能答成“我站哪一边”，而要答成“我当前主实践在哪、我对另一边理解到什么程度、真实选型时看什么”。
- 最稳的结构是：先讲当前更熟的生态，再客观承认另一套也理解和能迁移，最后把话题落回团队存量、业务复杂度和交付效率。
- 也就是说，这题核心不是技术辩论，而是成熟表达能力和迁移能力。

### 2）选择图 / 决策树（ASCII）

```txt
面试官问：你更偏 Vue 还是 React？
  |
  +-- 先说当前主要实践在哪
  |
  +-- 再说另一套你理解到什么程度
  |
  +-- 最后落回选型标准
         -> 团队存量
         -> 业务复杂度
         -> 交付效率
         -> 工程体系匹配度
```

### 3）最小对比表 / 最小例子

```txt
React
  关键词：组合式、显式、Hooks、生态灵活

Vue
  关键词：模板心智稳定、响应式直接、单文件组件友好
```

```txt
一个安全表达模板：
我当前项目实践更多在 React，所以在 Hooks、组件抽象和工程化这块更顺手。
Vue 我也理解它的响应式模型和组件写法，如果切到 Vue 项目，不会有认知断层。
如果是做技术选择，我不会只按个人偏好拍板，而是看团队存量、业务复杂度和交付效率。
```

### 4）面试口语稿

- 如果面试官问我更偏 Vue 还是 React，我不会直接站队。我会先说明自己当前主要实践在哪个生态，比如如果我最近项目主要用 React，我会说自己在 Hooks、组件抽象、状态管理和工程化这块更熟；但 Vue 的响应式模型、模板写法和组件组织方式我也理解，切换过去不会有认知断层。最后我会补一句：真实项目里的技术选型不会只看个人偏好，而是看团队已有积累、业务复杂度、招聘和维护成本、交付效率这些更实际的约束。

## 模块 2｜深入展开

### 1）对比维度

- 当前实践深度。
- 组件组织和心智模型。
- 状态管理和工程生态。
- 团队存量和招聘成本。
- 迁移学习成本与可替代性。

### 2）选项本体拆解

- `React` 更偏显式组合，UI 就是函数和状态的映射，生态很灵活，很多事情能自己组装。
- `Vue` 更强调模板和响应式的直观性，单文件组件和内建约定会让很多团队更容易快速统一写法。
- 所以这题最稳的答法不是说“谁吊打谁”，而是承认它们在心智模型和工程组织上的差异。
- 真正成熟的表达，是能把偏好和选型拆开讲：偏好是实践熟悉度，选型是业务约束下的决策。

### 3）取舍 / 易错点

- 不要贬低另一套技术栈，这种表达在面试里很容易扣分。
- 不要说“我都一样熟”，除非你真的能马上举出两边具体实践细节。
- 不要把选型只落在个人喜好上，团队现状和业务约束才是更有说服力的维度。
- 最危险的回答是情绪化站队，而不是客观比较。

### 4）专题判断

- 这题可以进入模板化回答。
- 如果继续追问 React Hooks 原理、Vue 响应式原理、状态管理对比，建议转到对应内部专题题卡。

## 模块 3｜追问与详细回答

### 追问 1｜如果当前项目主要用 React，为什么不直接说“我只会 React”？

- 因为面试官想看的通常不是“你有没有立场”，而是“你有没有迁移能力和客观表达能力”。
- 直接把自己锁死在一个框架上，容易让人担心你适应性不足。
- 更成熟的说法是：当前主实践在 React，但 Vue 的核心心智我也理解。
- 这样既真实，又不会把自己说窄。

### 追问 2｜如果问到两者差异，最值得讲什么？

- 我会优先讲组件组织方式、状态心智、生态约束和团队协作感受。
- 比如 React 更偏函数式组合和显式控制，Vue 更偏模板直观和响应式驱动。
- 这比只背一堆 API 差异更像真实项目经验。
- 因为面试官真正关心的，通常是你怎么看工程实践，而不是只会列功能清单。

### 追问 3｜如果明天要切到另一套技术栈，你会怎么补？

- 我会先补核心心智，不会一上来只背 API。
- 比如从组件模型、状态流转、生命周期 / 副作用、工程构建和路由体系这些关键点切进去。
- 再结合一个真实小项目把常用路径走一遍，迁移速度通常会很快。
- 面试里这样回答，能体现你对学习路径也有方法感。

### 追问 4｜真实项目做选型时，你最看重哪些维度？

- 团队现有积累、招聘成本、业务复杂度、交付节奏、组件库和工程体系匹配度。
- 这些因素往往比单个框架的某个语法优势更重要。
- 也就是说，技术选型更像工程决策，不是个人审美投票。
- 这句话说出来，通常会比单纯比较框架优缺点更成熟。

### 追问 5｜如果岗位 JD 明确偏 Vue，而你最近主要做 React，怎么答？

- 先承认自己最近主实践在 React，这是事实。
- 再说明 Vue 的核心机制和开发方式你并不陌生，并举出你能迁移的抓手，比如响应式、组件拆分、路由和状态管理。
- 最后补一句：框架切换需要时间，但底层前端能力和工程思维是可迁移的。
- 这样既不装熟，也不会把自己讲成完全不匹配。
