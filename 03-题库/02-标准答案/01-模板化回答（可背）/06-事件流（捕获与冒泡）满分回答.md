## 这题在问什么

这题不是为了背“先捕获后冒泡”，而是想看你能不能把传播顺序和实际代码行为对应起来。

## 60 秒直答

DOM 事件传播一般分 3 个阶段：捕获、目标、冒泡。捕获是从 window/document 往目标元素走，冒泡是从目标元素再往外层回传。默认 `addEventListener` 监听的是冒泡阶段；如果第三个参数或 `options.capture` 设为 `true`，就是捕获阶段。面试里我会再补一句：不是所有事件都冒泡，但大多数点击类事件都遵循这个模型。

## 核心机制

- 事件先沿祖先链向下，到目标元素
- 在目标元素触发处理逻辑
- 再沿祖先链向上冒泡
- `stopPropagation()` 可以阻止继续传播

## 最小例子

```js
outer.addEventListener('click', () => console.log('outer bubble'))
outer.addEventListener('click', () => console.log('outer capture'), true)
inner.addEventListener('click', () => console.log('inner'))
```

点击 `inner` 时，顺序通常是：
- `outer capture`
- `inner`
- `outer bubble`

## 业务 / 验证

真实项目里最常见的是弹层、菜单、列表项点击联动。比如点击卡片会进入详情，但卡片内的删除按钮只想删当前项，这时就要结合传播顺序和 `stopPropagation()` 控制行为。

## 常见追问

- `stopPropagation` 和 `preventDefault` 区别是什么？
- 为什么有些事件不冒泡？
- React 的合成事件和原生事件传播有什么关系？
- 为什么事件委托通常基于冒泡而不是捕获？

## 易错点

- 把阻止默认行为和阻止传播混为一谈
- 只会背顺序，不会结合点击冲突场景解释
- 忽略目标阶段的存在

## 关联深挖

- 与事件委托题一起出现时，优先把“传播顺序”讲清，再讲委托
