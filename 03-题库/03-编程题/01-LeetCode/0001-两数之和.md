## 题目与边界

给定整数数组 `nums` 和整数 `target`，返回两个下标，使得 `nums[i] + nums[j] === target`。

边界：
- 每个输入通常只对应一个答案
- 不能复用同一个元素
- 面试时最好主动说明：如果题意改成“可能无解”，你会返回 `null` 或抛错

## MVP 思路

最稳的写法是哈希表：
- 遍历到当前值 `x`
- 先看 `target - x` 是否已经出现过
- 出现过就直接返回两个下标
- 没出现过就把 `x -> index` 记进 `Map`

这样比双重循环更像面试里的标准做法，因为时间复杂度能从 `O(n^2)` 降到 `O(n)`。

## 代码

```ts
export function twoSum(nums: number[], target: number): [number, number] | null {
  const seen = new Map<number, number>()

  for (let index = 0; index < nums.length; index++) {
    const value = nums[index]
    const matchedIndex = seen.get(target - value)

    if (matchedIndex !== undefined) {
      return [matchedIndex, index]
    }

    if (!seen.has(value)) {
      seen.set(value, index)
    }
  }

  return null
}
```

## 复杂度

- 时间复杂度：`O(n)`
- 空间复杂度：`O(n)`

## 最小用例

```ts
console.log(twoSum([2, 7, 11, 15], 9))    // [0, 1]
console.log(twoSum([3, 3], 6))            // [0, 1]
console.log(twoSum([-1, -2, -3, -4], -6)) // [1, 3]
console.log(twoSum([1, 2, 3], 100))       // null
```

## 面试时怎么讲

我会先复述题意：在一遍遍历里找到补数。然后说核心想法是“空间换时间”，用哈希表记录已经见过的数。当前数是 `x`，就查 `target - x` 是否出现过，出现过直接返回；否则继续往后扫。这样时间复杂度 `O(n)`，比双重循环的 `O(n^2)` 更稳。最后我会主动补一个边界：如果题意允许无解，我会返回 `null`。

## 可选加分点

- 解释为什么要“先查再存”，这样才能避免同一个元素被复用
- 主动说明重复值场景，比如 `[3, 3]`
- 如果面试官追问测试，可以马上写出 3 组最小用例
