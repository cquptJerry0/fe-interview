# 07-编程题-加分点

目标：在 MVP 基础上给出可落地的加分点，并按收益排序。

输入：
- MVP 解法
- 题目类型（算法/组件/系统小设计）

输出（对齐 `.trae/templates/04-编程题-加分点.template.md`）：
- 3-6 个加分点（按收益排序）
- 每个加分点的最小改动方案
- 可讲的话术（体现工程思维）

常见加分维度：
- 边界与错误处理
- 可测试性（测试用例/可注入依赖）
- 可扩展性（抽象边界）
- 性能（复杂度/渲染优化）
- 可访问性/国际化/格式化

排序规则（先收益后成本）：
- 优先“低成本高收益”：补边界、补清理、补测试用例、补一处关键抽象
- 再做“中成本中收益”：性能优化、重构解耦、可扩展设计
- 最后才谈“高成本高收益”：引入新依赖/新架构/大范围改动

面试话术模板：
- “我先保证 MVP 可跑；如果还有时间，我会按收益排序补 3 个点：A（边界）→B（可测）→C（性能）。每个点我都能说明为什么值得做，以及最小改动方案。”
