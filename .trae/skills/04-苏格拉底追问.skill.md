# 04-苏格拉底追问

目标：用递进追问把“会背但不懂”或“完全不会”变成“能自己讲清楚”。

输入：
- 题目与 tags
- 当前策略（深讲/教到会）

输出（对齐 `.trae/templates/02-追问脚本.template.md`）：
- 4 轮追问：确认理解 → 推到边界 → 对比取舍 → 实践排障

追问规则：
- 每轮追问都要指向一个可验证的结果（能画图/能举例/能写伪码/能说出边界）
- 发现概念空洞时，立即切到“例子驱动”而不是继续问术语

## 追问题干库（可直接复用）

### 第 1 轮：确认理解（把“名词”变成“输入输出”）

- 你先用一句话说本质：它解决什么问题？
- 如果只让你用“输入 → 处理 → 输出”讲一遍，你怎么讲？
- 你能画一个最小流程图吗？（3-5 个节点）

验收：用户能给出稳定的一句话结论 + 最小流程。

### 第 2 轮：推到边界（把“正确”推到“适用范围”）

- 什么时候不适用？给一个反例。
- 最容易出错的 1-2 个坑是什么？怎么避免？
- 如果把约束改掉（数据量更大/并发更高/SSR/弱网），方案还能成立吗？

验收：用户能说出至少 1 个边界 + 1 个反例或坑点。

### 第 3 轮：对比取舍（把“会做”推到“会选”）

- 备选方案 A/B 分别是什么？适用场景怎么分？
- trade-off：性能/一致性/复杂度/迁移成本/可观测性怎么权衡？
- 你会用什么决策维度做最终选择？（列 3-5 个维度）

验收：能给出对比矩阵的口述版（3 个维度起）。

### 第 4 轮：实践排障（把“懂原理”推到“能落地”）

- 线上出问题你怎么定位？先看什么指标/日志/面板？
- 你会加哪 2 个关键埋点来验证假设？
- 怎么做最小复现？复现后怎么验证修复有效？

验收：能给出“定位路径 + 验证点”，而不是泛泛说“打 log”。

## 停止条件（避免追问失控）

- 用户能用自己的话复述出：结论 + 例子 + 边界 + 取舍
- 或者明确卡点是“缺前置知识”，切换到补课（例子/图解）再继续追问
