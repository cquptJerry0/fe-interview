## 1. V8 垃圾回收机制完整流程，分代回收每一步细节，为什么要分代？

### 思维导图关键点

- **一句话结论**：V8 的垃圾回收核心是“分代假说 + 可达性分析 + 尽量降低停顿时间”。
- **为什么分代**：
  - 大部分对象“朝生夕死”。
  - 少部分对象会长期存活。
  - 所以把堆分成**新生代**和**老生代**，用不同策略提高效率。
- **新生代回收**：
  - 对象先分配到新生代。
  - 新生代空间小，GC 频繁。
  - 常用复制算法，分为 From / To 两块 semi-space。
  - 存活对象复制到 To 空间。
  - 多次存活或空间不够时晋升到老生代。
- **老生代回收**：
  - 对象生命周期长，空间大。
  - 先标记可达对象。
  - 再清除不可达对象。
  - 必要时整理压缩，减少内存碎片。
- **现代优化**：
  - 增量标记：把标记过程拆成小块。
  - 并发标记/清理：部分工作放到后台线程。
  - 并行回收：多个线程一起干活。
  - 写屏障：记录老对象引用新对象，避免新生代 GC 漏标。
- **面试拔高点**：
  - GC 不是只看引用计数，而主要看对象是否从 GC Roots 可达。
  - GC 优化目标不是“没有停顿”，而是尽量缩短主线程停顿。

### 60-90 秒口语稿

V8 的垃圾回收主要基于分代假说：绝大多数对象生命周期很短，少部分对象会长期存活。所以它会把堆内存分成新生代和老生代。新创建的对象一般先进新生代，新生代空间比较小，回收频繁，通常用复制算法，把存活对象从 From 空间复制到 To 空间，然后整体交换空间；如果一个对象多次 GC 后还活着，或者 To 空间放不下，就会晋升到老生代。

老生代对象存活时间更长、空间更大，复制成本太高，所以一般走标记清除和标记整理：先从 GC Roots 出发标记所有可达对象，不可达对象就是垃圾；清除后如果有较多内存碎片，会做整理压缩。现代 V8 还会做增量标记、并发标记、并行清理等优化，把一次长时间 STW 拆小或者放到后台线程，降低页面卡顿。另外因为老生代对象可能引用新生代对象，所以还需要写屏障和 remembered set，保证新生代回收时不会漏掉这些跨代引用。

在实际项目里，如果一个页面长列表、图表或者缓存对象越来越多，导致内存持续上涨，我不会只说“浏览器会自动 GC”，而是会用 Memory 快照看对象是否还被闭包、定时器、全局缓存或者 DOM 引用链持有。

### 高频追问

- **为什么新生代不用标记清除？**
  - 因为新生代对象大多很快死亡，复制少量存活对象更划算。
- **为什么老生代不用复制算法？**
  - 老生代对象存活率高，复制大量对象成本太高。
- **什么是 STW？**
  - Stop The World，GC 某些阶段需要暂停 JS 执行，避免对象图变化导致回收不一致。

## 2. async/await 底层实现，Generator 和 Promise 如何协作，手动模拟实现

### 思维导图关键点

- **一句话结论**：`async/await` 本质上可以理解为“Generator 自动执行器 + Promise 链式调度”的语法糖。
- **async 函数特点**：
  - 一定返回 Promise。
  - 普通返回值会被包装成 resolved Promise。
  - 抛错会变成 rejected Promise。
- **await 做了什么**：
  - 暂停当前 async 函数后续执行。
  - 把 await 后面的值转成 Promise。
  - Promise fulfilled 后，把结果恢复给后续代码。
  - 后续代码进入微任务队列执行。
- **Generator 协作模型**：
  - `yield` 暂停执行。
  - `next(value)` 恢复执行。
  - Promise resolved 后调用 `next(res)`。
  - Promise rejected 后调用 `throw(err)`。
- **注意**：
  - 现代引擎不一定真的直接用 Generator 实现，但 Babel 转译和面试理解通常用这个模型讲。

### 60-90 秒口语稿

我理解 `async/await` 可以从两个层面讲。语义上，`async` 函数一定返回一个 Promise；`await` 会把后面的值包装成 Promise，然后暂停当前 async 函数的后续执行，等这个 Promise 状态变成 fulfilled 后，再把结果交给后面的代码继续执行。如果 Promise rejected，就相当于在 await 那一行抛错，可以被 `try...catch` 捕获。

实现模型上，可以把它类比成 Generator 加 Promise 自动执行器。Generator 的 `yield` 可以暂停函数，`next` 可以恢复函数。自动执行器会不断执行 Generator，遇到 yield 出来的 Promise，就等它 resolve 后把值传回 `next`，如果 reject 就调用 `throw` 把错误抛回 Generator 内部。这样就把异步 Promise 链写成了同步风格。

实际项目里，比如接口 A 的结果要作为接口 B 的参数，我用 `async/await` 可以把流程写得很直观，但我也会注意 await 后面的代码其实是微任务恢复执行，这会影响它和 `setTimeout`、DOM 更新之间的顺序。

### 手写模拟

```js
function asyncToGenerator(genFn) {
  return function (...args) {
    const gen = genFn.apply(this, args);

    return new Promise((resolve, reject) => {
      function step(type, value) {
        let result;

        try {
          result = gen[type](value);
        } catch (err) {
          reject(err);
          return;
        }

        const { value: yieldedValue, done } = result;

        if (done) {
          resolve(yieldedValue);
          return;
        }

        Promise.resolve(yieldedValue).then(
          (res) => step('next', res),
          (err) => step('throw', err)
        );
      }

      step('next');
    });
  };
}
```

### 使用示例

```js
const fn = asyncToGenerator(function* () {
  const a = yield Promise.resolve(1);
  const b = yield Promise.resolve(a + 1);
  return b;
});

fn().then(console.log); // 2
```

## 3. 闭包底层原理，内存泄漏场景 + 排查方案

### 思维导图关键点

- **一句话结论**：闭包不是“函数里面套函数”这么简单，而是函数对象保留了创建时的词法环境。
- **底层关键点**：
  - 函数创建时会记录自己的外部词法环境。
  - 内部函数如果被外部引用，外层函数执行完后，对应词法环境不会被释放。
  - 因为它仍然从 GC Roots 可达。
- **常见泄漏场景**：
  - 全局变量长期引用闭包。
  - 事件监听没有解绑。
  - 定时器没有清除。
  - 缓存 Map/数组无限增长。
  - 闭包里引用了大对象或 DOM 节点。
  - React/Vue 组件卸载后异步回调仍然持有状态。
- **排查方案**：
  - Chrome DevTools Memory。
  - Heap Snapshot 对比快照。
  - Allocation instrumentation 看对象分配。
  - Retainers 看是谁持有对象。
  - Performance Monitor 看 JS heap 是否持续上涨。

### 60-90 秒口语稿

闭包的本质是函数和它创建时词法环境的组合。一个函数在创建时，会记录它能访问的外层作用域。如果外层函数执行结束后，内部函数仍然被外部变量、事件、定时器或者缓存引用，那么这个内部函数关联的词法环境也不会被释放，因为从 GC Roots 出发还能访问到它。

所以闭包本身不是内存泄漏，泄漏的原因是闭包长期持有了不该继续持有的对象。比如闭包里引用了一个很大的列表、DOM 节点或者组件状态，而事件监听、定时器、全局缓存没有清理，就会导致这些对象一直不可回收。

排查时我一般会用 Chrome DevTools 的 Memory 面板做 heap snapshot，对比操作前后的对象数量和 retained size，再看 Retainers 路径，找到是谁还在引用它。工程里常见处理方式是组件卸载时清理事件监听和定时器，缓存设置上限，异步请求加取消或忽略过期结果。

### 高频追问

- **闭包一定会内存泄漏吗？**
  - 不会。只有闭包持有的对象生命周期超过预期，才可能泄漏。
- **为什么外层函数执行完变量还在？**
  - 因为内部函数还引用它，对应词法环境仍然可达。
- **闭包变量存在栈上还是堆上？**
  - 面试里可以说：如果变量需要被闭包长期引用，引擎会把它放到可长期存活的环境结构里，而不是简单随调用栈销毁。

## 4. 事件循环 + 微任务队列执行顺序，复杂代码逐行说输出

### 思维导图关键点

- **一句话结论**：先执行同步代码；一个宏任务结束后，清空所有微任务；有渲染机会再渲染；然后进入下一个宏任务。
- **浏览器主线**：
  - 执行一个 task，比如 script、setTimeout、点击事件。
  - 同步代码进入调用栈立即执行。
  - 遇到 Promise.then / queueMicrotask / await 后续，放入微任务队列。
  - 当前调用栈清空后，进入 microtask checkpoint。
  - 微任务会一直清空到队列为空。
  - 然后浏览器可能进行渲染。
  - 再取下一个 task。
- **常见任务分类**：
  - 宏任务：script、setTimeout、setInterval、用户事件、网络回调等。
  - 微任务：Promise.then/catch/finally、queueMicrotask、MutationObserver、await 后续。
  - requestAnimationFrame：通常在渲染前执行，不简单等同于宏任务。
- **复杂代码输出题步骤**：
  - 先标同步输出。
  - 再记录宏任务。
  - 再记录微任务。
  - 每执行完一个宏任务，立刻清空当前产生的所有微任务。
  - 微任务里再产生微任务，也要继续清空。

### 60-90 秒口语稿

浏览器事件循环可以按一个固定顺序分析：先执行当前宏任务里的同步代码，比如整个 script。同步执行过程中，如果遇到 `setTimeout`，它会注册一个新的宏任务；如果遇到 `Promise.then`、`queueMicrotask` 或者 `await` 后面的代码，会进入微任务队列。

当前宏任务的同步代码执行完之后，不会马上执行下一个 `setTimeout`，而是先进入微任务检查点，把微任务队列清空。这里要注意，微任务执行过程中如果又产生新的微任务，也会继续执行，直到微任务队列为空。之后浏览器才有机会进行渲染，然后再进入下一个宏任务。

所以复杂输出题我一般按三栏写：同步输出、微任务队列、宏任务队列。每走完一个宏任务都清空微任务，这样基本不会乱。在项目里这个知识点会影响加载态、DOM 更新后读取布局、Promise 和定时器之间的顺序判断。

### 高频追问

- **await 后面的代码算什么？**
  - 可以理解为 Promise resolved 后进入微任务。
- **微任务会不会饿死宏任务？**
  - 会有风险。如果微任务不断递归创建微任务，可能导致渲染和下一个宏任务迟迟无法执行。
- **Promise 构造函数里面是同步还是异步？**
  - `new Promise((resolve) => { ... })` 里的 executor 是同步执行；`.then` 回调是微任务。

## 5. Proxy vs Object.defineProperty，为什么 Vue3 改用 Proxy，监听数组 / 嵌套对象的细节

### 思维导图关键点

- **一句话结论**：`Object.defineProperty` 是属性级劫持，`Proxy` 是对象级代理；Vue3 用 Proxy 是为了更完整、更自然地拦截对象操作。
- **Object.defineProperty 局限**：
  - 只能劫持已有属性。
  - 新增/删除属性监听不到。
  - 数组索引和 `length` 变化处理麻烦。
  - 需要递归遍历对象，初始化成本高。
- **Vue2 处理方式**：
  - 初始化时递归 defineReactive。
  - 数组通过重写 `push/pop/splice` 等方法增强。
  - 新增属性需要 `Vue.set`。
- **Proxy 优势**：
  - 能拦截 `get/set/deleteProperty/has/ownKeys`。
  - 可以监听新增、删除、in、遍历等操作。
  - 数组索引和 length 更自然。
  - 嵌套对象可以懒代理，访问到再 reactive。
- **Vue3 响应式主线**：
  - `get` 时 track 收集依赖。
  - `set/delete` 时 trigger 触发更新。
  - 嵌套对象在 get 时转成 reactive。
- **注意点**：
  - Proxy 代理的是对象，不是原对象本身。
  - 解构 reactive 对象可能丢失响应式，需要 `toRefs`。
  - ref 用 `.value` 是为了包装基本类型。

### 60-90 秒口语稿

Vue2 的响应式主要基于 `Object.defineProperty`，它是在对象已有属性上定义 getter 和 setter。问题是它只能劫持已经存在的属性，对新增和删除属性无能为力；数组的索引修改和 length 变化也很难完整监听，所以 Vue2 需要 `Vue.set`，并且对数组的变更方法做了重写。

Vue3 改用 Proxy，是因为 Proxy 是对整个对象做代理，可以拦截更多操作，比如读取、设置、新增、删除、判断属性是否存在、遍历 key 等。这样数组索引变化、对象新增属性、删除属性都能更自然地进入响应式系统。Vue3 的核心流程是：get 时做依赖收集 track，set 或 delete 时触发 trigger。对于嵌套对象，Vue3 通常不是一开始深度递归代理所有层级，而是在 get 到子对象时再懒代理，这样初始化成本也更低。

在实际项目里，比如一个复杂表单动态增删字段，Vue3 对新增字段的响应式支持会比 Vue2 更自然；但我也会注意不要随便解构 reactive 对象，否则可能丢失响应式连接。

### 高频追问

- **Vue3 能监听嵌套对象吗？**
  - 能，但通常是访问到嵌套对象时再懒代理。
- **Proxy 为什么不能直接 polyfill？**
  - 因为 Proxy 是语言层面的对象代理能力，无法用 ES5 完整模拟。
- **Vue3 数组响应式是不是完全没有坑？**
  - 大多数索引和长度变化可以拦截，但依赖收集粒度、遍历依赖、length 触发范围仍然需要框架内部特殊处理。

## 6. 单 DOM 实现带 hover 动画、滑块过渡的开关样式，不能用伪元素之外的标签

### 思维导图关键点

- **一句话结论**：一个真实 DOM 负责轨道，伪元素 `::before` 负责滑块，用 `transition + transform` 做动画。
- **核心点**：
  - 只能一个 DOM。
  - 轨道用元素本身。
  - 滑块用 `::before`。
  - hover 或 active 状态改变背景和滑块位置。
  - 动画优先用 `transform`，避免 layout。
- **面试说明**：
  - 如果只是 hover 开关，CSS 就够。
  - 如果要真实点击切换，需要 JS 改 class 或 aria 状态。
  - 如果允许 input，可以用 checkbox，但“单 DOM”一般更适合 button/div + 伪元素。

### 60-90 秒口语稿

这题我会用一个 DOM 表示开关轨道，然后用 `::before` 伪元素表示滑块。轨道本身设置宽高、圆角和背景色，`::before` 绝对定位在左侧，设置成圆形。hover 或者 `.is-on` 状态下，改变轨道背景色，同时让 `::before` 通过 `transform: translateX(...)` 平移到右侧。这里用 transform 做滑动动画，而不是改 left，可以减少布局计算，更符合性能优化思路。

如果面试官要求真实点击切换，我会用 JS 切换 class 或 `aria-pressed`；如果只是 hover 动画，纯 CSS 就能完成。实际项目里类似开关组件还要补键盘可访问性和状态同步。

### 最小可用版代码

```html
<button class="switch" aria-pressed="false"></button>
```

```css
.switch {
  position: relative;
  width: 56px;
  height: 30px;
  border: 0;
  border-radius: 999px;
  background: #d0d5dd;
  cursor: pointer;
  transition: background 0.25s ease;
}

.switch::before {
  content: '';
  position: absolute;
  left: 3px;
  top: 3px;
  width: 24px;
  height: 24px;
  border-radius: 50%;
  background: #fff;
  box-shadow: 0 2px 8px rgba(0, 0, 0, 0.18);
  transition: transform 0.25s ease;
}

.switch:hover,
.switch.is-on {
  background: #1677ff;
}

.switch:hover::before,
.switch.is-on::before {
  transform: translateX(26px);
}
```

### 高频追问

- **为什么用 transform 不用 left？**
  - `left` 更容易触发布局，`transform` 通常可以走合成层，动画更流畅。
- **真实开关怎么做？**
  - 点击时切换 `.is-on` 和 `aria-pressed`。
- **可访问性怎么补？**
  - 用 button、维护 `aria-pressed`、支持键盘触发。

## 7. 重排重绘触发场景，如何做到只重绘不重排，线上项目优化案例

### 思维导图关键点

- **一句话结论**：重排是重新计算布局，重绘是重新绘制视觉，合成是把已有图层组合到屏幕；性能成本一般是重排 > 重绘 > 合成。
- **重排触发**：
  - 改 width、height、margin、padding、border。
  - 改 display、position、top、left。
  - DOM 增删。
  - 字体变化。
  - 读取 `offsetWidth/getBoundingClientRect` 等布局信息，可能强制同步布局。
- **重绘触发**：
  - color、background、box-shadow、visibility 等不影响布局的样式。
- **只合成/少重绘**：
  - 动画优先用 `transform`、`opacity`。
  - 避免用 `top/left/width/height` 做动画。
  - 批量读写 DOM，避免 layout thrashing。
  - 用 `requestAnimationFrame` 合并更新。
  - `will-change` 谨慎使用。
  - `contain` 隔离布局影响。
- **线上案例**：
  - 长列表滚动卡顿：虚拟列表 + 固定高度/缓存高度。
  - 拖拽动画卡顿：`left/top` 改成 `transform`。
  - 高频 resize：节流 + 批量计算。
  - 表格展开收起：减少同步读写布局。

### 60-90 秒口语稿

重排也叫 layout，是浏览器重新计算元素几何位置和尺寸；重绘是布局不变，只重新绘制颜色、阴影、背景等视觉；如果只是 transform 或 opacity 这类属性变化，很多情况下可以直接走合成层，成本更低。

常见触发重排的操作包括改宽高、margin、padding、display、position、DOM 增删，或者在写样式之后立刻读 `offsetHeight`、`getBoundingClientRect`，这会强制浏览器同步计算布局。要减少重排，我会优先用 transform 做位移动画，用 opacity 做淡入淡出；把 DOM 读写拆开批处理，避免读写交叉；长列表用虚拟列表；复杂组件可以用 `contain` 限制布局影响范围。

实际项目里，比如拖拽卡片时，如果每次 mousemove 都改 `left/top`，会导致频繁 layout。我会改成只更新 `transform: translate3d(...)`，再配合 rAF 合并一帧内的更新，滚动和拖拽会明显更流畅。

### 高频追问

- **display:none 到 block 会触发什么？**
  - 通常会触发重排和重绘。
- **visibility:hidden 呢？**
  - 元素仍占位，一般不触发布局变化，但会触发重绘。
- **transform 一定不重排吗？**
  - 通常不会影响正常文档流布局，但是否提升为独立图层由浏览器决定，不能滥用 `will-change`。

## 8. BFC 原理 + 应用，手写多种垂直居中，不定宽高 + 兼容老旧浏览器方案

### 思维导图关键点

- **一句话结论**：BFC 是块级格式化上下文，它让内部布局和外部布局相互隔离。
- **BFC 特性**：
  - BFC 内部块盒垂直排列。
  - 同一个 BFC 内相邻块 margin 会折叠。
  - BFC 区域不会和 float 元素重叠。
  - BFC 会包含内部浮动元素高度。
- **触发 BFC**：
  - `overflow: hidden/auto/scroll`
  - `display: flow-root`
  - `display: inline-block`
  - `display: table-cell`
  - `position: absolute/fixed`
  - `float` 非 none
  - flex/grid item 等
- **应用**：
  - 清除浮动。
  - 防止 margin 折叠。
  - 两栏布局避免文字环绕 float。
- **垂直居中方案**：
  - flex。
  - absolute + transform。
  - table-cell。
  - line-height 单行文本。
  - absolute + margin auto。
  - inline-block + vertical-align 兼容老浏览器。

### 60-90 秒口语稿

BFC 是块级格式化上下文，可以理解成页面布局里的一个独立容器。BFC 内部元素怎么布局，不会轻易影响外部；外部浮动也不会和 BFC 区域重叠。它常用来解决清除浮动、margin 折叠、两栏布局等问题。比如父元素里全是 float 子元素时，父元素高度塌陷，给父元素加 `overflow: hidden` 或 `display: flow-root`，就能让它形成 BFC 并包住内部浮动。

垂直居中要按场景选。现代浏览器最推荐 flex，简单稳定；不定宽高可以用 absolute 加 transform；兼容老浏览器可以用 table-cell 或 inline-block 加 vertical-align；单行文本可以用 line-height。实际项目里，我一般优先用 flex；如果是弹窗居中，就用 fixed/absolute 加 transform；如果要兼容很老的浏览器，再考虑 table-cell 或负 margin 方案。

### 多种居中代码

#### flex 居中

```css
.parent {
  display: flex;
  align-items: center;
  justify-content: center;
}
```

#### 不定宽高：absolute + transform

```css
.parent {
  position: relative;
}

.child {
  position: absolute;
  left: 50%;
  top: 50%;
  transform: translate(-50%, -50%);
}
```

#### 单行文本垂直居中

```css
.box {
  height: 40px;
  line-height: 40px;
}
```

#### table-cell 兼容方案

```css
.parent {
  display: table-cell;
  width: 300px;
  height: 200px;
  text-align: center;
  vertical-align: middle;
}

.child {
  display: inline-block;
}
```

#### 已知宽高：absolute + 负 margin

```css
.parent {
  position: relative;
}

.child {
  position: absolute;
  left: 50%;
  top: 50%;
  width: 100px;
  height: 60px;
  margin-left: -50px;
  margin-top: -30px;
}
```

### 高频追问

- **`overflow:hidden` 清除浮动的原理？**
  - 它触发 BFC，BFC 计算高度时会包含内部浮动元素。
- **`display: flow-root` 和 `overflow:hidden` 哪个更好？**
  - 语义上 `flow-root` 更明确，不会带来裁剪副作用。
- **margin 折叠怎么解决？**
  - 让父子或兄弟不处于同一个普通流上下文里，比如创建 BFC、加 border/padding、使用 flex 等。

## 9. 数组去重：包含对象、嵌套数组、循环引用，不能用 Set

### 思维导图关键点

- **一句话结论**：这题考的不是普通去重，而是“深度相等 + 循环引用处理”。
- **限制条件**：
  - 不能用 Set。
  - 基本类型用 `Object.is` 判断更稳。
  - 对象/数组要递归比较结构和值。
  - 循环引用需要记录已经比较过的对象对。
- **实现思路**：
  - 遍历原数组。
  - 对每个元素，和结果数组里的元素逐个 deepEqual。
  - 如果都不相等，放入结果。
  - deepEqual 内用 WeakMap 记录 `a -> [b1, b2...]`，避免循环引用死递归。
- **复杂度**：
  - 去重外层最坏 \(O(n^2)\)。
  - 每次深比较还取决于对象规模。
  - 空间复杂度主要来自递归栈和 WeakMap。

### 60-90 秒口语稿

这题不能用 Set，而且还包含对象、嵌套数组和循环引用，所以不能只做引用去重。我的思路是写一个 `deepEqual`，基本类型用 `Object.is` 判断；对象和数组比较原型、key 数量和每个 key 对应的值。为了处理循环引用，比较两个对象时用 WeakMap 记录已经比较过的对象对，如果再次遇到同一组对象，说明之前已经进入过这条比较路径，可以直接认为当前路径成立，避免无限递归。

去重时，我遍历原数组，把当前元素和结果数组里已有元素逐个深比较，如果都不相等才 push。这个方案最坏是 \(O(n^2)\)，但它满足题目复杂条件。实际业务里如果数据有稳定 id，我会优先用 id 去重；只有没有 id 且要求结构相等时，才做这种深比较。

### 最小可用版代码

```js
function deepEqual(a, b, memo = new WeakMap()) {
  if (Object.is(a, b)) return true;

  if (a === null || b === null) return false;
  if (typeof a !== 'object' || typeof b !== 'object') return false;

  if (a instanceof Date || b instanceof Date) {
    return a instanceof Date && b instanceof Date && a.getTime() === b.getTime();
  }

  if (a instanceof RegExp || b instanceof RegExp) {
    return a instanceof RegExp && b instanceof RegExp && String(a) === String(b);
  }

  if (Object.getPrototypeOf(a) !== Object.getPrototypeOf(b)) return false;

  let comparedList = memo.get(a);
  if (comparedList && comparedList.indexOf(b) !== -1) {
    return true;
  }

  if (!comparedList) {
    comparedList = [];
    memo.set(a, comparedList);
  }
  comparedList.push(b);

  const keysA = Reflect.ownKeys(a);
  const keysB = Reflect.ownKeys(b);

  if (keysA.length !== keysB.length) return false;

  for (let i = 0; i < keysA.length; i++) {
    const key = keysA[i];

    if (!Object.prototype.hasOwnProperty.call(b, key)) {
      return false;
    }

    if (!deepEqual(a[key], b[key], memo)) {
      return false;
    }
  }

  return true;
}

function uniqueArray(arr) {
  const res = [];

  outer:
  for (const item of arr) {
    for (const existed of res) {
      if (deepEqual(item, existed)) {
        continue outer;
      }
    }
    res.push(item);
  }

  return res;
}
```

### 高频追问

- **为什么不用 JSON.stringify？**
  - 属性顺序、函数、undefined、Symbol、循环引用都会出问题。
- **为什么不用 Set？**
  - Set 对对象按引用去重，结构相同但引用不同的对象不会被认为相等。
- **生产环境一定要这么写吗？**
  - 不一定。有业务主键时优先用主键去重，深比较是兜底方案。

## 10. 手写节流防抖，区别应用场景，优化立即执行 / 收尾逻辑

### 思维导图关键点

- **一句话结论**：防抖是“等你停下来再执行”，节流是“一段时间最多执行一次”。
- **防抖 debounce**：
  - 高频触发后，等最后一次触发结束一段时间再执行。
  - 适合搜索联想、输入校验、窗口 resize 结束后计算。
- **节流 throttle**：
  - 高频触发过程中，固定时间间隔执行一次。
  - 适合滚动监听、拖拽、按钮防连点、上报曝光。
- **立即执行**：
  - 第一次触发马上执行。
- **收尾逻辑**：
  - 高频触发结束后，最后一次参数也要执行。
- **面试重点**：
  - 要保留 `this` 和参数。
  - 要能清理定时器。
  - 要说明 leading/trailing。

### 60-90 秒口语稿

防抖和节流都是控制高频事件。防抖是事件频繁触发时不执行，等它停止一段时间后，只执行最后一次，所以适合搜索框输入联想、表单校验、resize 结束后重新计算布局。节流是高频触发期间按照固定间隔执行，比如滚动监听、拖拽移动、曝光上报。

实现上，防抖主要是每次触发都清掉上一个 timer，重新计时。节流要记录上次执行时间，如果距离上次执行超过间隔就立即执行，否则根据 trailing 配置补一次收尾执行。工程里我一般会根据场景选择：输入类用防抖，过程类用节流；如果是按钮提交，还要配合接口状态锁，不能只靠防抖。

### 防抖代码

```js
function debounce(fn, wait, options = {}) {
  const { leading = false, trailing = true } = options;
  let timer = null;
  let lastArgs = null;
  let lastThis = null;
  let invokedLeading = false;

  return function (...args) {
    lastArgs = args;
    lastThis = this;

    if (!timer && leading) {
      fn.apply(lastThis, lastArgs);
      invokedLeading = true;
    } else {
      invokedLeading = false;
    }

    if (timer) clearTimeout(timer);

    timer = setTimeout(() => {
      timer = null;

      if (trailing && !invokedLeading) {
        fn.apply(lastThis, lastArgs);
      }

      lastArgs = null;
      lastThis = null;
    }, wait);
  };
}
```

### 节流代码

```js
function throttle(fn, wait, options = {}) {
  const { leading = true, trailing = true } = options;

  let lastTime = 0;
  let timer = null;
  let lastArgs = null;
  let lastThis = null;

  return function (...args) {
    const now = Date.now();

    if (!lastTime && leading === false) {
      lastTime = now;
    }

    const remaining = wait - (now - lastTime);

    lastArgs = args;
    lastThis = this;

    if (remaining <= 0 || remaining > wait) {
      if (timer) {
        clearTimeout(timer);
        timer = null;
      }

      lastTime = now;
      fn.apply(lastThis, lastArgs);

      lastArgs = null;
      lastThis = null;
    } else if (!timer && trailing) {
      timer = setTimeout(() => {
        lastTime = leading === false ? 0 : Date.now();
        timer = null;

        fn.apply(lastThis, lastArgs);

        lastArgs = null;
        lastThis = null;
      }, remaining);
    }
  };
}
```

### 高频追问

- **防抖和节流怎么选？**
  - 输入停止后只要最后结果：防抖。
  - 过程中需要持续响应但降频：节流。
- **为什么要 trailing？**
  - 防止最后一次触发被丢掉，比如拖拽停止时要同步最终位置。
- **为什么要保存 this 和 args？**
  - 保证包装后的函数行为和原函数一致。

## 11. 实现 repeat 函数，间隔指定时间重复执行指定次数

### 思维导图关键点

- **一句话结论**：本质是异步调度题，用计数器控制执行次数，用定时器控制间隔。
- **常见题意**：
  - `repeat(fn, times, interval)` 返回一个新函数。
  - 调用新函数后，每隔 interval 执行一次 fn。
  - 总共执行 times 次。
- **实现选择**：
  - 可以用 `setInterval`。
  - 也可以用递归 `setTimeout`，更容易控制异步函数、错误和间隔。
- **边界**：
  - `times <= 0` 直接结束。
  - 保留 `this` 和参数。
  - 如果 fn 是异步函数，可以等本次执行完成后再计下一次。
- **复杂度**：
  - 时间复杂度 \(O(times)\)。
  - 空间复杂度 \(O(1)\)，不算异步调用栈。

### 60-90 秒口语稿

repeat 这题我会先确认函数签名。常见写法是 `repeat(fn, times, interval)` 返回一个新函数，调用这个新函数后，每隔指定时间执行一次原函数，总共执行指定次数。实现上可以用 `setInterval`，但我更倾向于递归 `setTimeout`，因为它更容易控制每次执行之间的间隔，也更方便兼容异步函数和错误处理。

核心就是维护一个 count，每执行一次加一；如果 count 达到 times，就 resolve 结束；否则继续 setTimeout 下一次。实际项目里类似逻辑可以用在轮询、重试、定时上报，但生产环境还要补取消能力和页面卸载清理。

### 最小可用版代码

```js
function repeat(fn, times, interval) {
  return function (...args) {
    const context = this;
    let count = 0;

    return new Promise((resolve, reject) => {
      if (times <= 0) {
        resolve();
        return;
      }

      function run() {
        Promise.resolve(fn.apply(context, args))
          .then(() => {
            count++;

            if (count >= times) {
              resolve();
              return;
            }

            setTimeout(run, interval);
          })
          .catch(reject);
      }

      setTimeout(run, interval);
    });
  };
}
```

### 使用示例

```js
const repeatLog = repeat((msg) => {
  console.log(msg);
}, 3, 1000);

repeatLog('hello');
```

### 高频追问

- **第一次是否立即执行？**
  - 要看题意。上面版本是等待 interval 后第一次执行；如果要求立即执行，把最后的 `setTimeout(run, interval)` 改成 `run()`。
- **为什么不用 setInterval？**
  - `setInterval` 不关心上一次是否执行完成；如果 fn 是异步的，可能出现重叠执行。
- **如何取消？**
  - 可以返回带 `cancel` 方法的控制器，或者内部保存 timer 并暴露清理函数。
