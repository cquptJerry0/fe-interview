# 秋招上场系统 Overview Spec

## 定位

本系统把秋招备战当作一个项目管理。

核心目标不是整理资料，而是在 20 天内持续判断并提升每个内容的上场能力。

最终判断只有一个：

```text
这个内容现在能不能上考场？
```

## 系统边界

本系统包含三条主线：

- 八股线
- 手写线
- 项目线

本系统包含两个承载位置：

- Git 仓库：唯一内容源，维护正文内容。
- 飞书多维表格：进度驾驶舱，维护状态、下一步动作和 Git 文件路径。

本系统不做：

- 不做学习日报。
- 不在飞书维护正文内容。
- 不把 raw 当作复习主系统。
- 不为了整理而整理。

## 三条线职责

### 八股线

解决概念、原理、高频问答和 408 基础。

核心问题：

- 我能不能说清楚这个知识点是什么？
- 我能不能说清楚为什么这样设计？
- 我能不能接住常见追问？

### 手写线

解决 JS 手写、React 手写和 LeetCode。

核心问题：

- 我能不能现场写出来？
- 我能不能边写边讲思路？
- 我能不能处理边界和变体？

### 项目线

解决 AI 项目、后端能力、数据库、Redis、Hive、工程设计和项目表达。

核心问题：

- 我能不能讲清项目场景？
- 我能不能讲清技术选择？
- 我能不能回答为什么不用其他方案？
- 我能不能说清收益、风险和兜底？

## 状态模型

只保留两个状态：

- 未上场：没学过、讲不顺、写不出、答不完整。
- 可上场：能用自己的话讲清楚，能举例，能接基础追问。

## raw 与主系统

raw 是原材料区，只负责可追溯。

主系统是上场内容区，只负责可复习、可口述、可手写、可追问。

对应关系：

```text
raw -> 原材料
bagu / coding / project -> 主系统
飞书多维表格 -> 进度和状态
```

## 面经处理原则

面经是雷达和考卷，不是学习主线。

流程：

```text
快速扫描 -> 抽问题 -> 去重归类 -> 归入三条线 -> 只学习高价值薄弱点
```

只有三类问题进入主系统：

- 重复出现的问题
- 自己明显答不好的问题
- 和简历或项目强相关的问题

## 飞书多维表格

飞书建议拆成三张表：

- 八股表
- 手写表
- 项目表

飞书只回答：

- 今天学什么？
- 哪些还未上场？
- 哪些已经可上场？
- 对应 Git 文件在哪里？
- 下一步动作是什么？

## AI 执行协议

AI 处理本系统时必须先判断任务类型：

- 原材料录入：进入 raw。
- 八股整理：进入 bagu。
- 手写整理：进入 coding。
- 项目打磨：进入 project。
- 进度跟踪：进入飞书多维表格。
- 不确定内容：进入 specs/research。

AI 不应把面经原文直接改写成答案，也不应在 raw 里维护完整答案。

## 20 天推进方式

先对齐最小规则，再启动执行。

不等待所有 spec 完美。

推荐顺序：

```text
先完成整体规则
优先启动手写线和前端八股线
AI / 项目 / 408 进入调研池
调研完成后回填局部 spec
每天三条线并行推进
```
