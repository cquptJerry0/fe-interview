## 一句话结论

浏览器用事件循环把“同步执行、微任务清空、渲染、宏任务推进”串起来；Promise.then 属于微任务，优先于下一轮宏任务执行。

## 关键点拆解

- 同步代码先跑完（调用栈清空）
- 清空微任务队列（Promise.then、MutationObserver 等）
- 浏览器在合适时机执行渲染（与帧调度有关）
- 再取出一个宏任务执行（setTimeout、I/O 等），进入下一轮

## 图解

```
一轮 loop:
同步栈 → 清空微任务 → 渲染机会 → 执行一个宏任务 → ...
```

## 对比与取舍

- 浏览器 vs Node：实现细节不同，但“微任务优先、宏任务推进”的面试心智模型类似
- rAF：和渲染节奏绑定，适合做帧同步更新；setTimeout 不保证在下一帧

## 实践与验证

写一个最小例子打印顺序，验证：同步 > 微任务 > 宏任务：
- 同步里 `console.log(1)`
- `Promise.resolve().then(() => console.log(2))`
- `setTimeout(() => console.log(3))`
