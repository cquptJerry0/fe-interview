## 一句话结论

闭包是“函数 + 它创建时的词法作用域”，让函数在离开创建环境后仍能访问外层变量；工程上常用来封装私有状态（防抖/节流/缓存），风险是意外保活导致内存与状态问题，排障要从“长期存活引用链”入手。

## 解释（从零到一）

最底层视角：
- JS 函数创建时会记录词法环境（作用域链）
- 只要有一个仍然可达的函数对象引用了外层变量，那些变量就不会被 GC 回收

最小例子：

```js
function makeCounter() {
  let n = 0;
  return () => ++n;
}
const inc = makeCounter();
inc(); // 1
inc(); // 2
```

为什么防抖/节流离不开闭包：
- 它们需要在多次调用之间保存 `timer/lastTime`，这些状态通常放在返回函数的外层变量里

## 图解

```text
makeCounter 执行结束
  |
  | 返回的函数 inc 仍然被外部引用（可达）
  v
闭包环境中的 n 被保活
```

## 对比与取舍

- 闭包保存状态 vs 外部全局变量保存状态
  - 闭包：状态封装、污染小、可复用；缺点是容易不小心保活大对象
  - 全局：简单但污染命名空间、易冲突、难测试

## 实践与验证

- 常见泄漏路径：
  - 事件监听/订阅未解绑（回调闭包长期存活）
  - 定时器未清理
  - 缓存 Map 无淘汰策略
- DevTools 验证（Memory）：
  - 录制 heap snapshot，找对象的 retained path，看是否被某个回调/监听闭包引用
  - 关注 listeners / timers / subscriptions 是否持续增长

## 易错点

- 闭包里引用了大对象/DOM，导致不易察觉的内存保活
- 在循环里捕获同一个变量引用导致值不符合预期（需要块级作用域或显式捕获）
