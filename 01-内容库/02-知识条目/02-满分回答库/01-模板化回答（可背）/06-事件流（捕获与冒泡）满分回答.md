## 一句话结论

DOM 事件传播分捕获、目标、冒泡三个阶段，默认监听在冒泡阶段。`stopPropagation` 控制传播链，`preventDefault` 控制默认行为，两者作用面不同。高分点是能结合真实冲突场景讲“为什么要在捕获阶段拦截”。

## 技术解释

### 1) 三阶段传播模型

```text
捕获：window -> ... -> target
目标：target
冒泡：target -> ... -> window
```

- `addEventListener(type, handler, { capture: true })` 绑定在捕获阶段。
- 不传 `capture` 默认是冒泡阶段。

### 2) 核心 API 区别

- `stopPropagation()`：阻止继续传播到后续节点。
- `stopImmediatePropagation()`：除了阻止传播，还会阻止当前节点后续同类监听器。
- `preventDefault()`：阻止默认行为（如链接跳转、表单提交），不等于阻止传播。

### 3) 为什么有时要用捕获

- 你要做全局安全拦截（如埋点、权限、统一关闭策略）。
- 冒泡阶段可能已被子组件 `stopPropagation` 截断。
- 捕获可更早拿到事件，减少链路不确定性。

### 4) 常见排障点

- 使用 `event.target` 和 `event.currentTarget` 混淆，导致命中对象判断错误。
- 多层弹窗叠加时，关闭逻辑写在错误阶段，造成误关或关不掉。
- 被动监听器下调用 `preventDefault` 无效。

## 对比与取舍

- 冒泡阶段：更符合组件局部处理，代码直观。
- 捕获阶段：更适合全局兜底与高优先级控制。
- 一般策略：局部逻辑走冒泡，全局治理走捕获。

## 实践与验证

- 给关键交互链路打印阶段日志（capture/target/bubble）。
- 在复杂弹窗页做点击路径回放，确认没有误触发。
- 对触控滚动场景检查监听器是否需要 `passive`。

## 业务举例

### 背景与约束

- 页面存在全局蒙层 + 弹窗 + 内部下拉层，点击行为冲突频发。
- 线上问题是点击弹窗按钮后偶发触发外层关闭。
- 要求不改业务交互定义，优先修复误触发。

### 方案与取舍

- 内层按钮保持冒泡阶段处理业务逻辑。
- 外层关闭逻辑改为捕获阶段并增加命中白名单判断。
- 仅在必要节点使用 `stopPropagation`，避免全链路粗暴拦截。

### 实施与验证

- 增加事件阶段日志和点击路径追踪。
- 回放 30+ 组复杂交互路径验证关闭行为。
- 灰度观察误关闭率和用户返回率。

### 结果与复盘

- 误触发关闭问题消失，交互稳定。
- 复盘确认根因是多层组件都在冒泡阶段抢处理权。
- 后续沉淀“弹层事件阶段规范”。

## 面试口述版（60-90秒）

事件流我会按三阶段讲：捕获、目标、冒泡。默认监听是冒泡阶段，所以大多数组件事件委托都基于冒泡。然后我会区分两个常被混淆的 API：`stopPropagation` 是阻止传播链，`preventDefault` 是阻止默认行为。真实项目里我会根据优先级选阶段，局部交互走冒泡，全局兜底或防止被子组件拦截时用捕获。比如多层弹窗冲突问题，我会通过阶段日志定位，再把外层关闭策略放到捕获并加命中判断。

## 易错点

- 把阻止传播和阻止默认行为混为一谈。
- 全局滥用 `stopPropagation` 导致埋点丢失。
- 忽略捕获阶段导致复杂页面事件冲突难排查。
