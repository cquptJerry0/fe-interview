## 一句话结论

一次 DOM 事件传播分“捕获→目标→冒泡”，默认监听在冒泡阶段；事件委托依赖冒泡；需要全局优先处理或不想被 stopPropagation 影响时可用捕获（`capture: true`）。

## 解释（从零到一）

最底层视角：浏览器在派发事件时会沿 DOM 树走两遍：
- 捕获：从外到内
- 冒泡：从内到外

最小例子（验证顺序）：

```js
outer.addEventListener("click", () => console.log("outer capture"), { capture: true });
outer.addEventListener("click", () => console.log("outer bubble"));
inner.addEventListener("click", () => console.log("inner capture"), { capture: true });
inner.addEventListener("click", () => console.log("inner bubble"));
```

`stopPropagation` vs `preventDefault`：
- `stopPropagation()`：阻止事件继续传播（影响捕获/冒泡链路）
- `preventDefault()`：阻止默认行为（如 a 跳转、表单提交），与传播是两回事

## 图解

```text
window → document → html → body → outer → inner   （捕获）
inner                                           （目标）
inner → outer → body → html → document → window  （冒泡）
```

## 对比与取舍

- 冒泡 vs 捕获
  - 冒泡：更常用、可组合性好、方便事件委托；缺点是可能被子节点 stopPropagation 截断
  - 捕获：适合全局拦截/埋点/权限前置；缺点是更容易与组件内部交互冲突

## 实践与验证

- 常见业务场景：弹窗“点外关闭、点内不关闭”
  - 外层监听点击关闭
  - 内层 stopPropagation 阻止冒泡到外层
- 排障“父元素收不到事件”：
  1) 子元素是否 stopPropagation
  2) 监听是否绑定在捕获/冒泡阶段
  3) target 是否被遮罩层/层级影响（点击命中不是预期元素）

## 易错点

- 把 preventDefault 当成阻止冒泡
- 监听注册阶段写错导致逻辑顺序不符合预期
