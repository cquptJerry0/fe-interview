## 一句话结论

省略号生效的前提不是 `text-overflow` 本身，而是“元素必须真的溢出且被裁剪”。单行用 `nowrap + overflow:hidden + text-overflow:ellipsis`，多行通常用 `-webkit-line-clamp`；在 flex/grid 里经常要补 `min-width: 0` 才会触发溢出。

## 技术解释

### 1) 单行省略的必要条件

- 元素有宽度约束（固定宽度、最大宽度或父容器约束）。
- 内容超出该宽度。
- 溢出被隐藏。
- 禁止换行。

```css
.ellipsis-1 {
  overflow: hidden;
  white-space: nowrap;
  text-overflow: ellipsis;
}
```

### 2) 多行省略的主流实现

```css
.ellipsis-3 {
  overflow: hidden;
  display: -webkit-box;
  -webkit-box-orient: vertical;
  -webkit-line-clamp: 3;
}
```

- 这是工程里最常见方案，兼容性已能覆盖现代浏览器主流场景。
- 需注意行高和容器高度配合，避免视觉截断异常。

### 3) 为什么在 flex 里常失效

- flex 子项默认 `min-width: auto`，会尽量保持内容最小宽度。
- 结果是子项不愿意缩小，自然也不会溢出，自然看不到省略号。
- 解决方式是给文本项显式 `min-width: 0`（grid 场景类似）。

```css
.row {
  display: flex;
}
.title {
  min-width: 0;
}
```

### 4) 常见布局边界

- 行内元素对宽度约束不敏感，必要时改 `display: block/inline-block`。
- 父容器没有明确宽度上下文时，省略号也不会触发。
- 表格布局、绝对定位场景要单独验证宽度计算链路。

## 对比与取舍

- 单行省略：稳定、低成本，适合列表标题。
- 多行省略：视觉友好，但存在兼容和行高细节问题。
- JS 截断：可控性高但维护复杂，通常只在复杂富文本场景考虑。

## 实践与验证

- 准备极长中文、英文、emoji、无空格字符串做回归样例。
- 用截图对比工具验证不同断点下卡片高度是否一致。
- 针对 flex/grid 页面检查是否都补了 `min-width: 0`。

## 业务举例

### 背景与约束

- 商品列表页标题长度差异大，导致卡片高度不一致，瀑布流错位明显。
- 要求不改数据结构、两天内完成修复并回归全端。
- 页面使用 flex 布局，历史样式较复杂。

### 方案与取舍

- 单行场景统一走 `ellipsis-1`，详情摘要走 `line-clamp`。
- 对所有 flex 文本子项补 `min-width: 0` 作为规范。
- 放弃 JS 截断方案，避免额外计算和多语言边界复杂度。

### 实施与验证

- 抽取统一样式工具类，替换历史散落写法。
- 加 20+ 条视觉回归样例，覆盖长词、空格、混排场景。
- 与 QA 联合在移动端/桌面端做断点回归。

### 结果与复盘

- 卡片高度稳定，错位问题消失。
- 复盘发现“省略不生效”主要不是属性写错，而是布局约束缺失。
- 后续将 `min-width: 0` 纳入组件规范检查。

## 面试口述版（60-90秒）

这题我会先讲一个核心前提：省略号只有在“真实溢出并被裁剪”时才会出现。单行是 `nowrap + overflow:hidden + text-overflow`，多行主流是 `-webkit-line-clamp`。面试官常追问 flex 里为什么不生效，我会明确回答：因为 flex 子项默认 `min-width:auto`，元素不缩小就不会溢出，所以要补 `min-width:0`。落地上我会强调回归策略，不只看一个 demo，而是要覆盖长中文、长英文、emoji、不同断点，保证布局稳定。

## 追问

## 易错点

- 只写 `text-overflow: ellipsis`，漏掉其他必要条件。
- 忘记给 flex 子项加 `min-width: 0`。
- 多行省略没有回归不同字体与断点，线上出现截断异常。
