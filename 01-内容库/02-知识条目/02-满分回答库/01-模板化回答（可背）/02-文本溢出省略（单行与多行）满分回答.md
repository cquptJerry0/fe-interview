## 一句话结论

单行省略是 `nowrap + overflow:hidden + text-overflow:ellipsis`；多行省略常用 `-webkit-line-clamp`；在 flex/grid 中经常需要给文本项加 `min-width: 0` 才能产生 overflow 从而触发省略。

## 解释（从零到一）

最底层视角：`text-overflow: ellipsis` 只有在“元素确实发生溢出且被裁剪”时才会显示省略号，所以必须同时满足：
- 有宽度约束（`width/max-width` 或父容器约束）
- 溢出被裁掉（`overflow: hidden`）

单行最小例子：

```css
.ellipsis-1 {
  overflow: hidden;
  white-space: nowrap;
  text-overflow: ellipsis;
}
```

多行最小例子（主流实现）：

```css
.ellipsis-3 {
  overflow: hidden;
  display: -webkit-box;
  -webkit-box-orient: vertical;
  -webkit-line-clamp: 3;
}
```

为什么在 flex 里不生效（代码层原因）：
- flex 子项默认 `min-width: auto`，最小宽度不小于内容最小宽度
- 结果是文本项“不肯被压缩”，容器不产生 overflow，自然不会触发省略

修复（给文本项允许收缩）：

```css
.row { display: flex; width: 200px; }
.title {
  min-width: 0;
  overflow: hidden;
  white-space: nowrap;
  text-overflow: ellipsis;
}
```

## 图解

```text
触发 ellipsis 的前提：
宽度被限制 -> 内容超过盒子 -> overflow 被裁剪 -> ellipsis 渲染

flex 特殊点：
默认 min-width:auto -> 盒子不愿缩 -> 没有 overflow -> 没有 ellipsis
```

## 对比与取舍

- 多行省略：line-clamp vs 固定高度裁剪
  - line-clamp：表达清晰、维护简单；缺点是实现细节依赖浏览器支持与差异
  - 固定 line-height + max-height：兼容更宽；缺点是通常不保证出现省略号形态

## 实践与验证

- 验证省略是否生效：在 DevTools 里把容器宽度调小，确认文本确实被裁剪且显示 `…`
- 排障顺序：
  1) 是否有宽度约束
  2) 是否设置 overflow hidden
  3) flex/grid 是否需要 `min-width: 0`
  4) 是否是纯 inline（必要时 `display: inline-block`）

## 常见追问

- 为什么必须有宽度约束？
- 多行省略兼容性如何？不支持怎么办？
- 省略后用户怎么看全量（tooltip/展开/可访问性）？

## 易错点

- 忘了 `overflow: hidden` 或没宽度约束导致不溢出
- flex 子项没加 `min-width: 0` 造成“看起来不生效”
- 用 `Math.min` 之类 JS 截断替代省略，导致字符宽度不一致、可访问性差
