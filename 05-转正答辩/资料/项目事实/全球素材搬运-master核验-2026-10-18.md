### 2.4 建立素材归属与访问控制体系

该体系覆盖事实查询、用途区分、写前检查、归属确认与受限交互。维护权、当前业务能否新增使用、历史内容能否读取是不同问题，不能压缩成“转独立后禁止编辑旧素材”。

#### 2.4.1 事实与规则分工

| 事实 | 代码位置 |
| --- | --- |
| 查询同一份素材信息获得 owner 与当前业务 redirect | `apps/material/api/service/materialTransfer/ownership.ts:96`、`:341` |
| Feed 返回 `owner_biz_id`、`owner_biz_id_inferred` 和当前查询 Biz 下的 `material_lineage_info.redirect_item_id`；VIMO 消费并透传归属来源，不自行实现归属推断 | `apps/material/api/service/materialTransfer/ownership.ts` 的 `loadSnapshot`、`inspectByBiz` |
| owner 控制编辑，不用于直接判断搜索可见性 | `apps/material/api/service/materialAccess.ts:92` |
| 搜索过滤被替代旧素材；显式选择命中旧素材则整批拒绝并返回映射 | `apps/material/api/service/materialAccess.ts:117`、`:125` |
| 保存前重新查询，先检查替代关系再检查归属；无法查询则拒绝写入 | `apps/material/api/service/materialAccess.ts:136`、`:175` |

操作语义：

| 用途 | 当前业务存在旧新映射时 | 只有其他业务归属时 |
| --- | --- | --- |
| 搜索 `search` | 过滤旧项，返回映射供列表清理缓存与勾选；不自动把搜索 ID 改成新 ID | 仍允许搜索 |
| 新增选材 `selection` | 拒绝包含失效素材的提交，返回旧新映射；不静默删掉部分项继续写 | 仍允许选用 |
| 历史读取 `reference` | 按原 ID 读取历史引用、合集、预览和发布快照 | 保留读取 |
| 编辑、上下线等维护操作 | 拒绝操作旧项，提供新素材查看入口 | 拒绝维护；未分配归属时进入确认 |

表达判断：共享使用不等于可修改，禁止新增使用也不等于禁止历史读取。`owner` 与 `redirect` 解决不同问题，不能由归属字段直接推导所有操作权限。

### 7.1 全球素材搬运系统协作

- 关键连线：VIMO 向 BPM 建单，BPM 审批后调用业务节点；搬运管理向 OpServer 预检、创建和查询；归属管理向 Feed 查归属及当前业务映射、确认归属；目标操作同区本地执行、跨区委托目标站点。

### 7.2 搬运异常执行与状态收敛

- 类型与位置：一个通栏画板，上部局部时序图，下部小型分层状态图，置于搬运管理方案表之后。两幅图分别有子图名，不能把时序箭头和状态转换混画。
- 时序图阅读问题：已发起执行但未收到完整响应时，如何保留结果并继续同一次执行。
- 参与方：BPM 或人工操作入口、VIMO 搬运服务、任务主库、素材服务。
- 关键顺序：读取任务与固定执行成员 → 先落逐素材执行 ID → 分片创建 → 合并已确认受理项 → 响应缺失项复用原 ID 重试，已受理未终态项继续查询 → 保存逐素材结果。标明每次回写冲突时重读主库、合并本次增量，而非重放旧 JSON。
- 状态图阅读问题：停止流程等待和素材完成为什么可以发生在不同时间。
- 状态关系：待受理到受理或拒绝；受理后执行中到成功或明确失败；缺响应保持待确认、缺查询项保持执行中；执行终态不回退。流程等待正常完成或超时后沿通知进入结束，结束后手动刷新仍可更新未终态素材结果而不回退流程。
- 独立结果：面板与测试记录为后处理结果，不画成可以将素材 SUCCESS 改成 FAILED 的后续状态。
- 图注：请求未知时保留执行身份，流程停止等待时保留真实结果；重试、查询和后处理各自更新对应记录。
- 不展开：完整审批分支、所有错误码、目标面板加锁。后者用方案表解释实际并发风险，避免此图承载所有机制。

### 7.3 素材归属控制分层架构

- 类型与位置：分层技术架构图，作为归属管理主图。先用操作规则表引出维护、选用与历史读取的差异，再看此图如何接入；图后方案表只解释关键取舍。
