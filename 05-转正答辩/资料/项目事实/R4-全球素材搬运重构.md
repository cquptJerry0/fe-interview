## 1. 当前事实摘要

1. 全球素材搬运用于把一个业务已经验证的素材复用到另一个业务，减少重复生产、上传和配置。
2. 旧链路已经具备搬运能力。本轮是存量链路重构，重点处理前端等待超时、受理状态不清、逐素材结果缺失、失败恢复和后处理边界。
3. 用户与 MT 共同 Owner，用户负责 VIMO 侧方案和实现，包括前端、Node、任务持久化、Workflow 接入、结果查询和后处理。
4. 素材服务负责实际复制素材文件、元数据、资源包和血缘等对象；VIMO 负责业务任务、预检、审批编排和目标业务后处理。
5. 旧链路问题修复 MR 2808、2829 已合入。
6. 9 月 17 日项目群已确认搬运功能上线。MR 2965 的 Open 状态属于 9 月 3 日历史核验，本轮未重新查询 MR，不能继续用它推断功能尚未上线。
7. 已有经过资源包 MD5 与设计师清单核对的候选数据，以及内容侧确认的待搬运清单；实际成功搬运量、面板新增可用量和实验收益仍缺证据。候选与待搬运数量均不计为已新增供给。

## 2. 业务、用户和真实链路

### 用户与场景

| 角色 | 任务 |
|---|---|
| 来源业务运营 | 选择可以被复用的素材 |
| 目标业务运营 | 申请搬运，配置目标业务、面板和测试 |
| 审批人 | 判断跨业务使用是否允许 |
| VIMO | 保存申请、预检、状态和后处理结果 |
| Workflow | 承接审批和 DAG 编排 |
| 素材服务 | 执行素材、资源和血缘复制 |

### 旧链路

```text
运营在页面发起
→ 前端等待长任务
→ 调用素材服务
→ 返回批量结果
→ 页面继续处理面板等后续步骤
```

主要问题：

1. 页面超时后无法判断下游是否已经受理。
2. 任务和逐素材结果缺少稳定持久化。
3. 重试可能重新创建目标素材。
4. 素材搬运成功与面板、测试等后处理结果混在一起。
5. 页面或实例退出后，恢复路径不清楚。

### 重构链路

```text
创建 VIMO 搬运任务
→ 保存申请快照
→ VIMO 预检业务配置
→ 素材服务预检版权、归属、UGC、血缘和执行状态
→ 冻结可执行素材集合
→ 创建 Workflow 审批
→ 审批通过
→ 准备自定义字段等依赖
→ 为每个素材生成并落库 externalTaskId
→ 按 50 个素材分片调用 CreateSyncTaskV2
→ 保存受理结果
→ MGetMaterialTransferResult 轮询
   ├─ SUCCESS：记录 targetItemId
   ├─ FAILED：记录失败
   └─ PROCESSING：保留，下一轮继续查询
→ 仅对搬运成功的素材执行后处理
   ├─ 查询／创建目标面板分类
   ├─ 加入面板
   ├─ 创建或复用自动测试任务
   └─ 飞书通知
```

对象依赖：

```text
申请快照
→ 预检结果
→ 冻结执行集合
→ Workflow 审批
→ 自定义字段定义
→ externalTaskId
→ 下游 execution
→ targetItemId
→ 面板／测试／通知
```

## 4. 已确认的技术判断

### 4.1 VIMO 保存业务事实，Workflow 负责编排

问题：长任务依赖前端或 Workflow 变量时，页面退出、实例异常和大量逐素材状态都难以恢复。

选择：

1. `material_transfer_task`保存申请快照、预检、冻结集合、逐素材结果和步骤结果。
2. Workflow 节点主要传递 `taskId`，承接审批和 DAG 顺序。
3. 审批和执行编排在 Workflow 查看，业务结果在 VIMO 任务台查看。
4. 任务更新使用 version 乐观锁。

边界：

1. Workflow 创建请求到达但响应丢失时，应先查询原实例，不能直接再创建。
2. 已设置 `idempotent_id=taskId`，仍缺真实重复请求的 status/body/回读证据。
3. 异步预检依赖 Node 进程继续执行；进程重启可能留下长期 PENDING。

### 4.2 预检靠近事实源，执行时复查动态事实

选择：

1. VIMO 检查参数、目标配置、素材类型、目标面板和跨区字体 MD5。
2. 素材服务检查素材存在、归属、版权、UGC、已有关系和搬运模式。
3. `precheckRevision`避免旧轮次响应覆盖新结果。
4. `CreateSyncTaskV2`再次检查血缘和 `PROCESSING`等执行时事实。

原因：预检到审批完成之间，素材状态和血缘可能变化。预检用于提前暴露问题，不能当作事务锁。

边界：

1. 字体跨区查询异常的存量逻辑可能降级为空集合。
2. 最终结果以素材服务执行和回读为准。

### 4.3 稳定 ID、终态单调和后处理分账

问题：分片调用可能部分成功或网络超时；Workflow 重投时重新生成执行 ID 可能创建重复素材；后处理失败不能污染搬运成功事实。

选择：

1. 在调用素材服务前一次性落库 `externalTaskId`。
2. 节点重投复用原 ID，只处理未受理素材。
3. `SUCCESS/FAILED`终态不回退，查询集合只保留未终态项。
4. 轮询超时不把仍在处理的素材强制写成失败。
5. 搬运结果写入 `itemResults`，面板、自动测试和通知写入 `stepResults`。
6. 自动测试任务查询后复用，通知前记录尝试时间。

边界：

1. VIMO 提供稳定关联键，素材服务对重复提交的端到端去重仍需 replay 回读。
2. 长期 `PROCESSING`缺少已确认的自动兜底时限和人工 SOP。
3. 当前是本项目的定向恢复机制，不扩写为通用补偿平台。

| 技术判断 | 当前实现与边界 |
| --- | --- |
| 分开候选与执行集合 | `request_snapshot`保存目标和操作配置；`precheck_results`保存本轮候选与校验；`item_results`提交时冻结成员、后续只更新执行事实；`step_results`保存各节点及后处理回执。当前 VIMO 模型无独立 `idempotency_key`字段，不复制旧方案 DDL。 |
| 分开三条状态线 | `precheck_status`、`current_step`、`transfer_status`分别表达预检、编排阶段和搬运结果；逐素材再分受理与执行状态。冻结集合不等于审批许可；PRECHECK 不能直接跳执行。END 后查询仍可更新未终态素材，不回退流程阶段。 |
| 避免并发覆盖 | `version` CAS 失败后，调用方重读主库，只合并本次素材或步骤的增量；不能直接用新版本重放旧 JSON。冻结集合、回写工单等一次性操作不能统一自动重试。 |
| 区分准入与归属 | `MaterialAccessService`查询 Feed 的 `redirect_item_id`与`owner_biz_id`。旧 ID 准入按当前业务和 search/selection/reference 策略处理，归属控制编辑。未确认 VIMO 有独立 access 数据库表。 |
| 前置整批准入 | selection 在分桶、删除原关系和写循环前整批检查；命中旧素材返回409及映射，不静默过滤。reference 保留历史原ID，不构成编辑豁免。保存时重新查询同一份准入与归属快照。 |
| 保护草稿事务 | 面板替换先用任务版本和claimToken取得本轮执行权；事务内锁Draft并复核Draft/Prod指纹；Draft更新、`client_scene_oprations`日志与任务回执同事务提交。该执行权不代表所有人工编辑入口的全局锁。 |
| 隔离发布内容 | 基于旧Prod生成仅替换引用的预期内容，候选diff试合并后比完整指纹。草稿独有引用不自动发布；发布前记录UNKNOWN，异常后回读Prod，海外审批场景核对Pre与审批后标PENDING_APPROVAL，不盲目重复发布。 |
