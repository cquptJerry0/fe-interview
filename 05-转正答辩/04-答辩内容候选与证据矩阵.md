# 答辩内容候选与证据矩阵

> 这份文件比较“哪些内容值得讲、能证明什么、风险在哪里”。它不直接生成正文，也不提前固定主 Case 数量。

最近更新：`2026-09-03`

## 一、筛选方法

每个候选从六个方面判断：

1. 业务重要性。
2. 个人 Ownership。
3. 技术判断密度。
4. 结果成熟度。
5. 证据强度。
6. 与其他内容的区分度。

最终去向只有四种：

```text
主 Case：承担一项核心能力判断
快速产出：建立业务覆盖和交付密度
横向能力：跨多个项目证明工作方法
附录：承接完整证据、边界和长尾细节
```

## 三、哪些内容可以“由点成面”

### 3.1 自动链路：由单个发布问题展开为完整执行链路

起点可以是 `publish_task`。继续向前追，会连到事件、`distribute_record`、Draft 更新和分类同步；继续向后追，会连到正式版本、超时恢复和失败诊断。

它可以证明：

1. 能看清端到端业务链路。
2. 能按失败语义拆分任务。
3. 能选择正确的计算和事务粒度。
4. 能根据真实日志定位性能成本。
5. 能处理运行时恢复和兼容边界。

`publish_task`必须留在自动执行链路中。单独抽走会让 Draft 修改和正式发布之间缺少关键连接。

### 3.2 OpenAPI/vimocli：由接口接入展开为开放能力

起点可以是素材或面板发布接口。继续向外会连到资源权限、风险审批、JWT、服务账号、BAM／IDL、网关、CLI、Skill 和 Agent。

它可以证明：

1. 能把页面能力整理成稳定 contract。
2. 能区分身份有效、接口可访问和资源可操作。
3. 能控制 CN／I18N 的站点和协议差异。
4. 能平衡 codegen 覆盖和手写语义。
5. 能把能力交给脚本、服务账号和 Agent 复用。

该候选投入和证据都较多。框架决策时要允许它包含多个技术判断，不能机械压成两页。

### 3.3 TTP：由一个 Pre 状态展开为合规发布模型

起点可以是新增 Pre。继续追问会连到 TTP 最终写入、审批单、版本校验、Diff、事务、权限和环境依赖。

它可以证明：

1. 理解合规要求怎样改变系统写入边界。
2. 能处理 Pre 与审批单一致性、多人审批和版本倒退。
3. 能从真实旧 Diff 问题修正缓存身份。
4. 能在 TTP 环境不完整时区分主链路和辅助能力。

它的强项是正确性和交付，不依赖效率百分比。

### 3.4 全球搬运：由旧链路故障展开为跨系统任务重构

起点应是旧链路已有搬运能力，但前端等待、受理状态、逐素材结果和失败恢复不清。后续展开任务持久化、Workflow、素材服务、稳定 ID、分片执行和后处理。

它可以证明：

1. 能读懂存量链路的真实失败。
2. 能重新划分 VIMO、Workflow 和素材服务的职责。
3. 能处理长任务、部分成功、重试和结果回读。
4. 能与 MT 和下游团队共同 Owner 跨系统项目。
5. 能如实管理未合入项目的阶段结果。

该项目有技术密度，结果成熟度低于前三项。篇幅要根据提交前状态调整。

## 四、四个强候选的差异

| 评委判断 | TTP | 自动链路 | OpenAPI/vimocli | 全球搬运 |
|---|---:|---:|---:|---:|
| 业务与风险理解 | 强：合规最终写入 | 强：运营自动执行 | 强：开放与机器调用 | 强：跨业务复用 |
| Ownership | 强：用户确认 Owner | 强：用户确认 Owner | 强：用户确认 Owner | 强：与 MT 共同 Owner |
| 技术判断 | 状态、事务、Diff、降级 | 失败语义、粒度、性能、恢复 | 权限、身份、contract、语义层 | 持久化、预检、幂等、部分成功 |
| 结果成熟度 | 主干 + TTP 联调 | 主干 + PPE 性能样本 | 主干 + 请求与使用数据 | 旧修复合入；重构阶段验证 |
| 最突出的能力 | 合规工程收口 | 复杂链路治理 | 能力标准化与复用 | 跨系统重构 |
| 主要重复风险 | 与自动链路都讲发布 | 与 TTP 都涉及 Draft／Prod | 会调用其他 Case 的领域能力 | 与自动链路都涉及任务恢复 |

四项都能贡献不同判断。最终是否全部展开，要看答辩时长和页面预算。删减时优先保留“判断差异”，不按项目时间平均分配。

## 七、正文重叠控制

1. TTP 只讲合规写入、Pre／Prod、审批、Diff 和 TTP 环境。
2. 自动链路只讲事件执行、`distribute_record`、Draft、`publish_task`、粒度和性能。
3. OpenAPI/vimocli 只讲调用 contract、权限、身份、站点和 CLI，不重复领域实现。
4. 全球搬运只讲存量跨系统任务、ID 映射、部分成功和后处理。
5. AI Native 若独立成节，使用 Coco 作为主例；vimocli 和 Agent 只补职责边界。
6. 第一部分只标重点热区，不提前讲完整技术方案。

## 九、架构决策时的建议输入

当前可以先比较三种方案：

1. 四个重点项目全部展开，靠篇幅差异控制时长。
