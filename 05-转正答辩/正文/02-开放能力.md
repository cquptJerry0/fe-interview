## 从页面操作到程序调用

VIMO 的素材查询、配置和发布原本主要通过页面完成，批量运营和业务服务接入需要更直接的调用方式。在已有接口与初始 CLI 的基础上，扩展素材操作、资源授权和客户端适配，<b><span text-color="rgb(36,91,219)">让脚本与 Agent 复用业务能力完成实际任务</span></b>。

| 批量核查 | 分类整理 |
| --- | --- |
| 运营借助 Agent 查询约 150 个老特效的上下线状态，无需再为此新增批量搜索入口。 | 一次任务移除一万多个素材关联，案例记录人工约 1 天、AI 约 15 分钟。 |

上述为代表案例，不外推平均提效。本人建设范围是本轮素材操作扩展、授权接入、vimocli 适配与交付配套；初始 CLI、接口生成和公共平台为已有基础。

【使用数据条：补同一统计窗口的调用量、活跃身份及业务采用，个人账号与服务账号按真实口径说明；不把请求量作为完成任务数。】

【关系总览图：使用方 → CLI 或直接调用 → VIMO 业务接口；标出公共接入能力和本人改动范围。只建立地图，详细鉴权与适配关系留到下方。】

## 开放业务操作

接口需要让调用方表达业务目标，同时继续遵守 VIMO 的业务与权限规则。重点展开两项选择，而不按组件逐一介绍。

| 业务操作的表达 | 业务授权的承接 |
| --- | --- |
| 发布接口接收素材或分类目标，由服务端解析相关变更并复用已有发布能力，减少调用方自行拼装发布参数的工作。 | 素材开放操作使用独立资源权限；已有后台接口的个人调用复用原有授权规则，根据业务基础选择接入方式。 |

【服务端设计图：业务目标如何转为实际操作；身份验证后分别进入开放授权或已有业务授权路径。标出公共中间件与业务资源检查的职责，避免把所有请求画成同一条鉴权链。】

<p>图外保留关键判断：<b><span text-color="rgb(36,91,219)">验证调用身份不等于授予业务权限</span></b>，具体业务仍需检查操作与资源范围。</p>

【就近采用证据：权限配置界面，以及商业化、模板等实际接入记录。选能说明业务差异和复用结果的证据，不另铺完整组件清单。】

## 让调用工具适应不同使用环境

同一业务操作会在本地终端、脚本和云端 Agent 中执行，身份来源、网络与站点并不相同。客户端保留业务命令的使用方式，将这些差异放到请求适配中处理，<b><span text-color="rgb(36,91,219)">避免每个业务重复实现接入逻辑</span></b>。

【客户端图：业务命令 → 业务/协议适配 → 公共请求与结果输出。接口生成与手写命令、Skill 使用说明用侧边关系标注，不画成每次请求的执行步骤。】

云端 Agent 的登录态不会自动从页面传入，服务地址也可能与办公网不同。页面侧利用已有登录态换取凭证并随任务注入，CLI 按服务、站点和网络配置选择入口；业务接口继续按当前身份检查权限。

【接入案例区：左侧为本地与云端的差异，右侧放运营 Agent 的实际采用记录。若总图已解释凭证流转，此处不再重画 JWT 全链路。】

| 使用中的问题 | 配套建设 |
| --- | --- |
| 新操作已接入，使用方还不知道怎样调用 | 用户 Skill 和操作指南承接命令使用方法 |
| 接口、CLI 和使用说明分别变更，交付易遗漏 | 开发流程与发布配套按产物组织，保留必要人工确认 |
| 用户本地版本滞后 | 客户端版本检查、自更新与 Skill 同步 |

以上以一次真实交付记录说明采用情况，避免再次展开完整研发工作流。调用观测只补充它能够回答的维护问题，统计口径与在建内容单独标明。
