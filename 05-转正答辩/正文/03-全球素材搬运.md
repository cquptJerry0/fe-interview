# 3 全球搬运

## 3.1 背景

<p>剪映、CapCut、醒图和 Hypic 需要跨业务、跨地区复用已有素材，补充高价值内容供给。例如，剪映希望引入 CapCut、醒图的人像效果，CapCut 希望复用 Hypic 的优质效果；同一业务也需要将已有素材用于海外、图片编辑或 Live 等场景。</p>
<p>原有工具已经支持跨区搬运，但仍有三项缺口：</p>
<ul><li>场景覆盖不全：缺少同区搬运，无法统一承接跟随使用和独立维护的需求。</li>
<li>执行过程难追踪：没有任务列表，申请人与目标面板等信息未持久化；流程中断后，难以确认已完成的素材和剩余操作。</li>
<li>维护边界不清楚：多个业务共用素材时，一方的编辑或下架会影响其他使用方，需要明确谁能维护、谁能使用。</li>
</ul>
<p>本次沿用素材服务的复制与关系管理能力，由 VIMO 补齐同区场景，串起申请、审批、执行和结果查询，并将归属规则接入素材编辑与面板选材。首期优先承接无需改包的素材。</p>

<p>申请要经过人工审批，执行时必须仍对应审批的那批素材。批量调用可能只受理一部分，或者执行后没有返回响应；此时整批重跑可能重复创建，直接判失败又会遗漏已经完成的素材。</p>
<p>素材复制、上面板和测试还各有结果，不能归为一个成功或失败。轮询与后处理同时回写时，也需要保留彼此的进展。</p>
</td><td vertical-align="top"><p><b>难点</b></p>
<p>共用素材时，一方编辑或下架会影响其他业务，已有 CapCut 误下架 Pippit 素材的情况。需要限制维护权，又不能阻断正常共享使用。</p>
<p>历史素材还可能缺少归属；转独立后，新素材已生成，面板却仍引用旧 ID。管理规则必须同时兼容新操作和已有内容。</p>

<p><b>沉淀流程接入方案</b></p>
<p>后续需求同样需要“审批通过后执行”。将建单、查询、身份处理封装，并保留审批分支与业务节点的配置范例，新场景可直接沿用接入方式。相较于分别补审批字段、维护回调和连接 FaaS，BPM 用工单保存流程信息、用节点调用业务接口，减少重复接入；各场景仍维护自己的业务数据与规则。</p>

</ul>
<blockquote><p>【画板占位｜素材归属控制】</p>

</blockquote>
<ul><li><b><span text-color="rgb(36,91,219)">统一执行写前校验</span></b>：页面打开后归属仍可能变化，仅靠置灰不足以保护写入。编辑、上下线和面板写入口共用校验，写前重新查询；查询失败停止写入，历史读取、移除和内部替换按各自规则处理。</li>
</ul>
<p><b>归属已确定</b>：使用方不能修改归属其他业务的素材。</p>
<img src="../图表/全球搬运-编辑拦截.png" data-lark-token="P1RpbldpVoe7Utxe1bHckiIZnlh" caption="编辑拦截：提示实际归属业务"/>

</ul>
