# 转正答辩协作入口

本目录只服务本人的转正答辩。当前约定更新于 2026-10-18，替代旧阶段地图、候选矩阵和旧章节安排。

## 读取顺序

1. 首次进入先读本文件和 [写作约定](./写作约定.md)。
2. 整体组织、内容取舍或收稿：读 [WIP转正答辩](./WIP转正答辩.md)。
3. 局部写作：只读当前模块正文；不默认加载全部模块、会话和研究记录。
4. 补事实时从 [资料索引](./资料/来源索引.md) 进入对应材料，核对其时间、口径和来源。
5. 资料区的旧稿、样本、研究记录只提供材料，不定义当前结构或写作要求。不要把旧的“已确认”“当前”“最终”当作本轮决定。
6. 定义能力框架或进行后期精修 Review 时，再读 [答辩定位与能力主张](./答辩定位与能力主张.md)。起稿不默认逐项套用，不提前把项目绑定到能力维度。

## 文件职责

| 入口 | 唯一职责 |
| --- | --- |
| 写作约定.md | 本次答辩的内核、内容要求、格式和 Review 标准 |
| 答辩定位与能力主张.md | 独立于项目的能力参考，含 AI Native；供后期精修判断，不是起稿门槛或本人能力结论 |
| WIP转正答辩.md | 整篇结构、模块职责、内容比重和待用户确认的取舍 |
| 正文/ | 每个模块唯一维护稿；当前为待整体确认的骨架 |
| 资料/来源索引.md | 会话、事实、样本与旧稿的查阅入口，数据冲突和备份位置 |
| 资料/项目事实/ | 带原核验日期的研究记录；需按问题核对，不能直接视作最新状态 |
| 资料/旧稿/ | 重构前稿件快照，只按需复用事实与资源，不继续维护旧结构 |

## 协作边界

- 本人确认真实经历、关键判断和重点；AI 提供内容候选、整理组织、核验与执行，不要求本人逐句代写。
- 模块会话只处理约定模块；主协调负责全篇去重、比重、资料整理和 Review。派发任务以用户授权为准。
- 组织方案返回聊天，主协调收进唯一正文；不另建“讨论稿、确认稿、最终大纲”等并行版本。
- 未获明确授权不修改文件。修改权限限定于当次范围，不自动包含飞书发布、真实业务写操作或绘图。
- 2026-10-18 用户明确授权清空旧飞书正文并重搭大概框架，已完成。此后按模块完善；同步前回读最新内容，保留用户同期编辑，不将本次清空授权延伸为后续反复覆盖。
- 近期任务状态沿用仓库根目录待办，不重建 D0～D7 阶段体系。
- 使用 writing-collab；本目录停用 distill-work-summary。不把共享 Skill 改成本篇专用规则。
- 手工改动使用 apply_patch，不回滚用户已有改动。清理前核对备份，新增证据不得只留在将被删除的文件里。
- 删除文件不会清除会话记忆。接续旧会话时重读当前约定，旧提纲和局部排版建议不能覆盖本轮目标。
- 先把真实内容写清楚，再逐步完善表达，最后依据材料提炼能力主张。不得为覆盖能力框架制造难点、扩写普通交付或预先分配项目标签。
