# VIMO 业务全景与个人产出

> 这份文件负责回答“VIMO 是什么、我负责什么、全部工作怎样落在同一张业务图里”。它为答辩第一部分提供事实，不决定最终页面数量和 Case 顺序。

## 一、VIMO 一页业务说明

VIMO 是字节内部的运营后台，服务剪映／CapCut、醒图／Hypic、即梦／Dreamina、Pippit 等业务。运营、审核和研发在这里管理素材、分类、面板、版本、权限和发布任务，最终影响客户端能看到哪些内容、以什么顺序展示、在哪些地区或业务线生效。

素材工作通常包含以下动作：

1. 接入素材文件、基础信息、资源包和版权配置。
2. 将素材组织到分类和面板中。
3. 在 Draft 中编辑待发布内容。
4. 根据地区和合规要求进入 Pre、审批或正式发布。
5. 使用自动分发、OpenAPI、vimocli 或 Agent 批量执行运营任务。
6. 将其他业务已经验证的素材搬运到目标业务，再接入目标面板和测试流程。

我在素材方向的工作主要落在四段：合规发布、自动执行、开放调用、跨业务复用。素材接入和批量运营、策略控制、AI 工作方式也有持续交付。商业化是另一块业务范围，当前以审计、权益预设和 AI 模板配置为主。

## 二、用户与业务对象

### 2.1 主要用户

| 用户或角色 | 使用场景 | 操作对象 | 关心的结果 |
|---|---|---|---|
| 素材运营 | 创建、配置、分发和发布素材 | 素材、分类、面板、版本 | 内容按时、正确地进入目标业务和地区 |
| 审核与 TTP 可信人员 | 查看候选版本并决定是否生效 | Pre、Prod、审批单、Diff | US 内容最终写入符合合规要求 |
| 业务研发 | 接入新能力、排查问题、自动执行任务 | OpenAPI、BAM／IDL、日志、任务 | contract 稳定，错误可诊断，权限可控 |
| 脚本与服务账号 | 批量查询和修改 VIMO 资源 | 素材、面板、分类、实验、发布接口 | 机器身份稳定，结果可回读 |
| Agent | 理解运营目标并调用确定性工具 | Skill、vimocli、OpenAPI | 模型不直接拼装不受控请求，写操作有边界 |
| 目标业务运营 | 复用其他业务已验证的素材 | 搬运任务、目标素材、面板、测试 | 搬运状态清楚，失败可恢复，结果能继续运营 |
| 客户端用户 | 使用最终正式内容 | Prod 版本和素材资源 | 看到正确、合规、可用的内容 |

### 2.2 核心业务对象

| 对象 | 职责 | 与其他对象的关系 |
|---|---|---|
| 业务线 `biz` | 区分剪映、醒图、即梦等业务空间 | 权限、面板、素材和站点请求都要绑定业务线 |
| 站点 `site` | 区分 CN、I18N 及相应网关和身份 | 决定域名、bid、JWT、服务账号和请求 contract |
| 素材 | 被生产、管理、分发和消费的内容单元 | 带文件、元数据、版权、资源包和业务配置 |
| 分类 | 按业务语义组织素材 | 分类变化可能触发自动分发和面板 Draft 更新 |
| 面板 | 客户端内容组织与发布边界 | 包含分类、素材关系和版本 |
| Draft | 运营编辑中的候选版本 | 经过发布流程成为 Pre 或 Prod |
| Pre | 待 TTP 审批的候选版本 | 与审批单、版本和 Diff 关联，客户端不直接消费 |
| Prod | 客户端读取的正式版本 | 由普通发布或 TTP 审批晋升产生 |
| `distribute_record` | 记录自动分发或分类同步的执行任务 | 保存触发、状态、结果和失败信息 |
| `publish_task` | 记录 Draft 变化后的正式发布意图 | 独立处理发布、超时、重试和失败 |
| OpenAPI 权限 | 控制调用者能否访问某个接口 | 与 HTTP operation、path、bid 关联 |
| 资源权限 | 控制调用者能操作哪个面板或素材类型 | 区分 add、modify、publish 等动作 |
| 搬运任务 | 保存跨业务搬运的申请和逐素材结果 | 关联 Workflow、素材服务、目标素材和后处理 |

## 五、全部产出按业务问题聚合

### 5.1 合规发布

包含：

1. TTP Pre 状态和审批。
2. Pre、Prod 版本校验与 Diff。
3. TTP 环境依赖、Kani、TCC 和接口降级。
4. 素材和面板发布权限收敛。

聚合依据：这些工作共同决定 US 内容由谁、在哪个环境、以哪个版本写入 Prod。

### 5.2 自动执行与正式发布

包含：

1. 动态分类和分类同步进入任务链路。
2. `distribute_record`消费与统计。
3. `publish_task`正式发布。
4. 批量加载、分类归并、面板事务和受控并发。
5. 主库读取、无变化跳过、超时恢复和诊断。

聚合依据：这些工作共同处理事件发生后如何计算真实变化、更新 Draft 并把结果发布到正式版本。

### 5.3 开放调用与机器身份

包含：

1. OpenAPI contract、BAM／IDL 和网关。
2. API 权限与资源权限。
3. P0／P1／P2 风险分级。
4. 个人 JWT、服务账号和统一身份中间件。
5. CN／I18N 多站点 Operation contract。
6. generated API、hidden command、手写语义命令。
7. npm、Skill 和 Agent 的调用承接。

聚合依据：这些工作共同构成页面之外操作 VIMO 的统一出口。

### 5.4 跨业务素材复用

包含：

1. 旧搬运链路的拉取和结果缺失修复。
2. 搬运任务持久化。
3. VIMO 和素材服务的双层预检。
4. Workflow 审批与编排。
5. 分片执行、逐素材结果和稳定 ID。
6. 面板、自动测试和通知等后处理。

聚合依据：这些工作共同解决存量搬运链路的超时、状态、恢复和后处理边界。

### 5.5 素材接入与日常运营

包含：

1. 自定义字段上传校验。
2. 通用批量创建 v1。
3. 搜索、相似分、列表和导出。
4. 历史资源包、分级和实验查询。
5. 音视频、大小和字段等正确性修复。

聚合依据：这些工作分布在素材接入和日常维护阶段，单项较小，合起来能说明业务覆盖。

### 5.6 商业化后台

包含：

1. 国内外审计日志。
2. 权益预设包。
3. AI 模板按 ID 配置积分。
4. 商业化预览 OpenAPI。
5. 少量批量提审和白名单语义修复。

聚合依据：这些工作都服务商业化配置、审计和预览。它们没有形成一条连续技术主线，当前不强行编译成独立大 Case。

### 5.7 AI 辅助研发与运营

包含：

1. Coco 素材文档巡检。
2. vimocli 统一 Skill 和专项 Skill。
3. VIMO 素材 subagent。
4. SG 部署和模型选择。

聚合依据：都在探索模型、确定性工具和人工如何协作。当前结果成熟度不一致，需要在框架决策时确定篇幅。

## 六、四个重点候选在全景中的位置

| 候选 | 链路位置 | 主要问题 | 与相邻模块的关系 | 内容边界 |
|---|---|---|---|---|
| TTP | Draft 到 Prod 的合规分支 | ROW 直发 US Prod、审批一致性、版本和旧 Diff | 接收 Draft，输出客户端使用的 Prod | 讲合规状态、事务、Diff 和 TTP 降级；不重复自动任务性能 |
| 自动链路 | 事件到 Draft，再到正式发布 | 失败语义混杂、粒度错位、重复读写和超时恢复 | `publish_task`属于链路后半段 | 讲任务、分类、面板粒度与运行边界；不重复 TTP 审批 |
| OpenAPI/vimocli | 页面之外的统一调用入口 | contract、身份、权限、多站点和语义命令 | 可以调用素材、分类、面板和发布能力 | 讲调用与安全边界；不重讲领域内部实现 |
| 全球搬运 | 素材接入阶段的跨业务分支 | 前端超时、受理不清、逐素材恢复、重复创建和后处理 | 目标素材最终回到正常主链 | 按存量链路重构展开；讲跨系统任务与部分成功 |

这四项目前都是强候选。最终保留数量、顺序和篇幅由 `05` 决定。
