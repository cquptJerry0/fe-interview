## 2.1 背景

VIMO 素材管理平台承接剪映、醒图等业务的素材入库、管理与分发。运营需要批量查询、整理和配置素材，特效生产服务需要直接录入素材；随着 Agent 进入日常工作，这些操作也需要提供程序调用入口。

| 业务诉求 | 已有基础 | 建设方向 |
| --- | --- | --- |
| 临时任务反复用到查询、修改、发布等操作，只是目标和组合不同。逐项点页面耗时，为每次任务开发专用入口也难以复用。 | 页面与部分 OpenAPI 已有业务处理能力，接口、命令和任务说明的覆盖仍不完整，程序调用还需自行签名、人工授权。 | 开放现有功能；为批量处理等新需求直接建设接口和命令，无需先开发页面。由 Agent 组合操作，为后续运营工作流提供基础。 |

本人负责业务能力扩展、授权与公共组件、vimocli 完善及交付配套，复用团队已有的部分 OpenAPI、初始 CLI、接口生成与审批基础。

### 2.3.1 建设开放基础设施

开放接口负责将素材、分类等业务目标转换为实际操作，并在执行前检查调用者的权限。早期 HMAC 接入要求调用方自行签名、联系管理员授权；接入字节云网关后，复用身份、路由和运维能力，业务侧统一管理个人与服务账号的开放权限。

商业化随后提出快速接入 CLI 的需求：页面接口已经具备，CLI 操作与页面差异较小，原有 Kani 业务权限足以覆盖。因此增加个人 JWT 直连，省去重复的网关与开放授权配置；服务账号、素材独立资源授权等场景继续使用网关。<b><span text-color="rgb(36,91,219)">接入方式由调用主体和授权需求决定</span></b>。

【画板占位：开放基础设施架构】
架构图：调用方经网关或个人直连进入业务服务；公共中间件识别身份，OpenAPI／Kani 分别授权，素材接口经资源校验和目标解析复用原业务服务。浏览器凭证工具单列。

### 2.3.2 构建统一客户端

接口提供业务操作，使用者还需要选对对象、组织参数并处理结果。vimocli 按业务对象提供命令，Skill 说明任务如何组合和验收；底层适配各系统的协议与身份，使终端、脚本和 Agent 共用同一套操作。

【画板占位：vimocli 整体架构】
分层图：业务命令 → VIMO／CCC／MIS／QA 适配 → 公共身份、网络、请求与输出。侧边标注素材接口生成、Skill、自更新和调用观测。
【/画板占位】

| 组织业务命令 | 优化使用体验 | 建设调用观测 |
| --- | --- | --- |
| <b>分开接口与命令</b><br>接口更新涉及路径和字段，用户却按素材、面板等对象操作。因此沿用素材接口契约生成 API 与隐藏命令，公开命令另行维护业务参数和结果，<b><span text-color="rgb(36,91,219)">生成代码不覆盖手写命令</span></b>；同一契约也用于网关配置。<br>素材、活动、资源位、商品等业务复用公共请求能力，各系统适配自己的路由和数据格式。<br><br><b>固定输入输出</b><br>明确业务线、站点与目标，64 位 ID 按字符串处理。表格供人阅读，JSON 供程序解析，Raw 保留原始数据；日志和更新提示另走通道，避免打断结果解析。参数、认证、缺权错误分别给出处理入口。<br><br><b>配套任务说明</b><br>命令固定单次操作，用户 Skill 说明如何组合与验收。统一入口按任务加载领域说明，认证与排障共用，写操作保留确认、执行、回读要求，简单查询无需加载整套配置流程。<br><br>【截图占位：业务命令、Skill 任务说明及表格／JSON 输出】 | <b>适配环境与账号</b><br>本地可以复用登录工具，云端需要接收注入凭证，无人值守任务还需选择服务账号，因此由公共运行配置处理这些差异。<br>1. 支持环境注入、bytedcli 或 SDK 凭证，选定来源后保持本次执行身份。<br>2. 按服务、站点和网络选择入口，PPE 叠加泳道；失败不跨网络回退。<br>3. 支持服务账号发现、激活、切换与分站点管理；个人直连仍使用个人身份。<br><br><b>完善自更新</b><br>旧进程装完新包后仍调用旧版 Skill 同步器，无法用上同步修复。因此改由<b><span text-color="rgb(36,91,219)">新包安装阶段执行新版同步逻辑</span></b>，核验实际更新结果，新进程补偿遗漏或失败。<br>CLI 与 Skill 分别检查更新，说明可独立发布；更新失败不阻断业务。支持的平台升级后重跑原命令，临时运行与源码开发不修改全局安装。<br><br>【画板占位：旧进程安装、新包同步、新进程补偿；标出失败后的继续执行】<br>【截图占位：多环境身份、服务账号与自更新结果】 | <b>补齐命令视角</b><br>服务端事件看不到 CCC、MIS、QA 调用，也无法判断请求来自哪条命令。将命令信息带到公共请求入口，按实际请求记录业务、身份、站点、响应和 LogID；一次命令的多次请求分别记录，支持追溯执行失败的位置。<br><br><b>保护业务执行</b><br>观测复用业务请求，采集不能影响正常调用。因此在业务读取响应时采集，避免提前消费响应流；采集副本、发送队列和退出等待均设上限，上报失败不改变业务结果。<br><br><b>明确统计范围</b><br>客户端与服务端分别统计；认证、文件传输及外部 CLI 内部请求按范围排除。公共请求入口检查纳入质量校验，防止新增命令漏接观测。<br><br>【画板占位：命令信息 → 公共请求 → 响应采集 → 有界队列】<br>【截图占位：客户端命令与服务端接口看板；标明窗口及联调范围】 |

### 2.3.3 完善交付协作

一项新能力能否使用，取决于接口、授权、命令和说明是否配齐；进入云端后，还取决于沙箱安装的版本。将这些依赖纳入研发 Skill 和发布流水线，使开发、配置、验证和分发按同一次交付核对。

【画板占位：开放能力研发与交付流程】
流程图：需求、环境、接口／定义、命令／说明、验证、归档；发布支线为 Release MR 确认 → 固定 Tag → 安装包、Skill、国内外镜像 → 回读。网关配置单独核对。

| 沉淀研发方法 | 建设发布流水线 | 改善协作效率 |
| --- | --- | --- |
| <b>明确每阶段交付物</b><br>六阶段开发 Skill 将需求语义、环境、接口定义、业务命令、用户说明、真实验证与发布记录串联，避免代码完成后遗漏配置或交付。<br><br><b>保留业务差异</b><br>设计资料说明网关与直连的选择；接入指南和跨服务 Skill 核对运行服务、接口定义、网关路径及权限点，按目标业务配置。<br><br>【截图占位：同一需求的 Skill 执行记录、两端 MR、环境验证与交付结果】 | <b>同步多项产物</b><br>Release MR 人工确认后，流水线检查、构建并发布安装包，增量发布 Skill，构建国内外沙箱镜像。<br><br><b>固定版本并回读</b><br>发布期间仍可能合入新代码，因此各步骤固定使用本次 Tag，镜像安装指定 CLI 版本；逐项回读包、Skill 和镜像结果，失败定位到具体产物。客户端自更新将已发布版本送达本地。<br><br>【截图占位：同一次发布的安装包、Skill 与两地镜像版本及结果】 | <b>维护研发知识</b><br>接入资料需要跟随代码变化。人工触发知识库流水线生成更新补丁，检查修改范围与可应用性，审核后更新。<br><br><b>组织并行任务</b><br>业务接入与工程改造并行推进，Mira 工作台集中展示进度、待确认事项与产物入口；各需求保留独立会话、分支和环境，便于从总览回到原任务继续处理。<br><br>【截图占位：知识库待审补丁、Mira 总览与独立任务入口】 |
