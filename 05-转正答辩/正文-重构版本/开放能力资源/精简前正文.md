## 2.1 背景

VIMO 素材管理平台承接剪映、醒图等业务的素材入库、管理与分发。运营希望把批量查询、整理和配置交给 Agent，特效生产服务也需要直接录入素材。两类需求都要求将页面上的业务操作开放给程序。

| 业务诉求 | 已有基础 | 建设方向 |
| --- | --- | --- |
| 运营任务经常只改变处理对象、数量和操作顺序。逐项操作页面耗时，为每次任务开发专用入口又会产生重复开发。 | 已有页面功能和部分 OpenAPI 可复用，但程序调用覆盖不足，需要自行签名、人工申请授权，Agent 也缺少命令和任务说明。 | 开放现有操作，补充批量处理、按目标发布等能力；配套授权、命令和 Skill，让 Agent 按任务组合调用，为运营工作流提供基础。 |

本人负责业务能力扩展、授权与公共组件、vimocli 完善及交付配套，复用团队已有的部分 OpenAPI、初始 CLI、接口生成与审批基础。

### 2.3.1 建设开放基础设施

早期素材 OpenAPI 要求调用方自行计算 HMAC 签名，权限依赖人工开通。接入 CLI 和 Agent 后，这些步骤成为使用门槛。我接入字节云网关，复用身份验证、路由和运维能力；业务侧保留开放权限，统一管理个人与服务账号能执行的操作。

商业化随后需要快速接入 CLI，但它与素材的约束不同：页面接口和 Kani 权限已经具备，CLI 与页面操作的业务差异也较小。因此增加个人 JWT 直连，复用原接口及授权，省去重复的网关与开放权限配置；服务账号和需要独立资源授权的场景继续走网关。

![身份接入与授权分流](开放能力资源/画板-02.jpg)

<b><span text-color="rgb(36,91,219)">网关承接独立开放授权，个人直连复用已有业务权限。</span></b>身份通过验证后，仍须执行对应授权；只有未携带 JWT 的普通页面请求沿用会话登录。

| 网关接入 | 商业化快速接入 |
| --- | --- |
| ![字节云网关接口配置](开放能力资源/图片-13.png) | ![商业化复用已有接口与权限的接入诉求](开放能力资源/图片-14.png) |

| 开放业务操作 | 约束素材操作 | 封装开放组件 |
| --- | --- | --- |
| <b>让程序按业务目标操作</b><br>运营任务通常指定“这批素材”或“这个分类”，页面发布接口却接收选中的变更记录。若让每个调用方自行查询和拼装，就会重复实现内部发布规则。<br><br><b>方案</b><br>1. 扩展素材基础操作、分级、屏蔽、面板分类、实验、发布、下发控制和配置运维，复用已有业务服务。<br>2. 补充批量分类配置、关系维护和按目标发布。<b><span text-color="rgb(36,91,219)">服务端解析目标对应的变更与版本</span></b>，再调用原发布能力。<br>3. 分类归属不符或没有待发布变更时，返回具体原因，调用方无需猜测发布对象。<br><br><b>结果</b><br>Agent、脚本和生产服务共用业务操作；内部发布规则变更时，集中修改服务端。<br><br>【截图占位】目标输入与对应发布记录，证明按目标选取了哪些变更。【/截图占位】 | <b>将权限限定到任务范围</b><br>一个接口可以操作多个面板，接口权不足以限制具体对象；逐素材授权又需随素材增减反复维护。因此采用面板／素材类型粒度，并分别配置新增、修改、发布。<br><br><b>共用素材鉴权服务</b><br>1. 创建按目标类型检查新增权；编辑先回查实体，再检查真实类型的修改权。<br>2. 批量发布核对素材存在性、业务线和全部类型权限，<b><span text-color="rgb(36,91,219)">全部获权后才发起发布</span></b>，避免校验一种类型却发布另一种。<br>3. 分类关联检查目标面板的修改权，面板发布检查发布权。接口确定操作对象，公共服务统一校验授权。<br><br>![开放权限申请、审批与执行校验](开放能力资源/画板-03.jpg)<br><br><b>让用户自行申请与验证</b><br>缺权提示附申请入口，个人低风险 P2 自动开通，服务账号及高风险操作保留审批；混合申请按最高风险处理。获权后通过自测页验证当前身份的单次调用。<br><br>![按素材类型分别配置新增、修改、发布权限](开放能力资源/图片-15.png) | <b>公共中间件承接业务接入</b><br>各业务授权规则不同，验签、用户信息转换、业务线识别和调用上报可以共用。将这些处理封装为中间件，适配国内外框架，业务继续维护自己的权限规则。<br>1. 验签放在原登录检查之前，避免合法 JWT 被浏览器会话检查拦截。<br>2. <b><span text-color="rgb(36,91,219)">无效 JWT 直接拒绝</span></b>，不换用会话身份；可信身份接入 OpenAPI 或 Kani 授权。<br>3. 已接入素材、商业化、主应用、模板和用户管理 5 个模块，共用身份接入与调用上报。<br><br><b>从接口自测抽取凭证工具</b><br>自测页需要用当前用户身份发请求。我利用已有字节云登录态换取 JWT，将站点选择、缓存和刷新抽为公共工具，后续用于素材同步、BPM 建单和页面 Agent。<br><br>![字节云利用浏览器登录态签发个人 JWT](开放能力资源/图片-16.png)<br><br>ByteCloud 负责签发；公共工具在使用时检查有效期，封装请求遇到 401 最多刷新重试一次，登录态失效则交回页面。<br><br>![其他业务复用公共凭证工具](开放能力资源/图片-17.png)<br><br><b>将页面身份带入云端任务</b><br>沙箱无法直接使用浏览器登录态，因此由页面换取 JWT，随任务传入沙箱，配套生产网访问配置。VIMO Agent、Capcut 运营 Agent 共用这套方案，用户无需为云端执行再次登录。<br><br>![页面凭证传递与沙箱执行](开放能力资源/画板-04.jpg)<br><br>同一沙箱会承接多次任务，每次调用都注入当前凭证与业务线，不写入 CLI 登录配置，避免后续任务沿用旧身份。<br><br>![两个页面 Agent 复用云端接入方案的协作记录](开放能力资源/图片-08.png) |

### 2.3.2 构建统一客户端

业务接口可用后，使用者仍需选对对象、组织参数并读取结果。vimocli 将接口组织为素材、面板、商品等业务命令，适配不同系统的调用方式；Skill 负责说明任务步骤与验收方法，使人工操作、脚本和 Agent 共用同一套能力。

![vimocli 业务命令、系统适配与公共执行架构](开放能力资源/画板-05.jpg)

| 组织业务命令 | 优化使用体验 | 建设调用观测 |
| --- | --- | --- |
| <b>接口变化与使用方式分别维护</b><br>直接暴露接口名和内部字段，会把参数转换留给用户。沿用接口生成与业务命令两层结构，让接口更新不覆盖面向用户的设计。<br>1. 从素材接口契约生成调用代码与隐藏命令；公开命令维护业务参数、对象选择与结果展示。<br>2. 各系统适配自己的路由和数据格式，素材、活动、资源位、商品等业务复用公共请求能力。<br>3. 业务线、站点和目标显式确定，64 位 ID 按字符串处理，避免选错对象或精度丢失。<br><br><b>让结果可被继续使用</b><br>表格供人阅读，JSON 供程序解析，Raw 保留原始数据。日志和更新提示另走通道；参数、认证和缺权错误分别给出处理入口，Agent 可据此决定下一步。<br><br><b>统一安装，按任务加载说明</b><br>将分散的业务说明收进一个 Skill，入口只加载当前任务所需的领域指南，认证与排障共用。写操作明确确认、执行与回读要求，简单查询无需加载完整配置流程。<br><br>![统一 Skill 入口与领域说明](开放能力资源/图片-18.png) | <b>多环境适配</b><br>本地已有登录工具，云端依赖注入凭证，网络入口也不同。将差异放到公共配置，业务命令保持一致。<br>1. 支持环境注入、bytedcli 与 SDK 凭证，选定来源后保持本次执行身份。<br>2. 按服务、站点和网络确定地址，PPE 叠加泳道；失败时不跨网络回退。<br><br>![Aime 中复用身份执行命令](开放能力资源/图片-19.png)<br>![站点与网络环境配置](开放能力资源/图片-20.png)<br><br><b>服务账号管理</b><br>无人值守任务需要明确、稳定的调用主体。提供账号发现、激活、切换及分站点管理；OpenAPI 使用选定账号，个人直连仍使用个人身份。<br><br>![服务账号发现与激活状态](开放能力资源/图片-21.png)<br><br><b>自更新</b><br>能力已发布，本地包和 Skill 仍可能停在旧版。因此执行命令时分别检查两者更新，说明也可独立发布。<br>1. 旧进程无法执行新包中的同步修复，改由<b><span text-color="rgb(36,91,219)">新包安装阶段运行新版 Skill 同步器</span></b>，并核验实际更新结果。<br>2. 新进程补偿失败或遗漏的同步；支持的平台升级后重跑原命令，更新失败继续原业务。<br>3. 临时运行和源码开发不修改全局安装。<br><br>![CLI 升级完成，Skill 同步失败时提供手动补偿入口](开放能力资源/图片-22.png)<br>![CLI 与 Skill 自更新流程](开放能力资源/画板-06.jpg) | <b>从接口使用追溯到业务命令</b><br>原服务端埋点看不到 CCC、MIS、QA 调用，也无法判断请求来自哪条命令。逐命令加埋点又容易遗漏新增功能，因此将命令信息带到公共请求入口统一采集。<br>1. 关联命令、业务、身份、站点、响应和 LogID，一次命令的多次请求分别记录。<br>2. 公共请求入口检查纳入质量校验，新增业务沿用同一采集方式。<br><br>![命令上下文、请求响应与异步上报](开放能力资源/画板-07.jpg)<br><br><b>采集不干扰执行</b><br>业务读取响应时再采集，避免提前读走响应内容。采集副本、发送队列和退出等待均设上限，上报失败不改变业务结果。<br><br><b>形成独立的客户端使用视图</b><br>可按命令、站点和系统查看请求并追溯错误。客户端与服务端分别统计，认证、文件传输及外部 CLI 内部请求不计入该范围。<br><br>![调用看板分别展示客户端模块与服务端接口，截图日期为 10 月 1—7 日](开放能力资源/图片-23.png) |

### 2.3.3 完善交付协作

一次开放能力交付涉及服务端、网关、CLI、Skill 和云端镜像。只完成代码，用户仍可能缺少权限、找不到命令，或在沙箱里运行旧版本。因此将接入检查纳入研发 Skill，将包、说明和镜像纳入同一发布流程，分别保证能力配齐和版本送达。
