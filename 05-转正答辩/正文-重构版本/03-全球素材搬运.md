# 3 全球搬运

## 3.1 背景

剪映、CapCut、醒图和 Hypic 希望复用其他业务已经验证过的优质素材，补充各自的效果供给，支持体验和商业化增长。需求集中在跨业务复用、海内外复用和业务内多场景复用三个方向。

| 业务诉求 | 代表需求 |
| --- | --- |
| 跨业务复用 | 剪映引入 CapCut、醒图的人像效果；CapCut 复用 Hypic 的优质效果，补充美颜等方向的供给。 |
| 海内外复用 | 醒图的效果相机、编辑、人像等方向需要适配海外，希望已有素材能够在海内外业务间复用。 |
| 多场景复用 | 图片编辑、Live 等新场景需要复用已有素材，减少从头生产内容的成本。 |

本次在已有跨区搬运基础上补充同区搬运，并完善搬运后的维护规则。素材服务提供实际搬运及素材关系管理能力，VIMO 将这些能力组织成业务可以发起、查看和处理的任务，并把归属规则落实到素材编辑和面板使用中。

【高亮块】
本次建设围绕两个目标：让业务能够管理整批搬运任务；让搬运后的素材按正确的归属关系被维护和使用。
【/高亮块】

## 3.2 产出

- 素材筛选：统计剪映、CapCut、醒图、Hypic <b><span text-color="rgb(36,91,219)">4 条业务线、7 类、24,580 个素材</span></b>，提供分类清单与素材明细，支持业务筛选搬运内容。
- 搬运管理：补充同区的跟随、独立和跟随转独立场景；提交后无需持续停留在页面，<b><span text-color="rgb(36,91,219)">任务进度可追踪，逐素材失败可定位</span></b>，统一查询申请、审批和执行结果。
- 归属管理：按素材归属限制维护操作；转为独立维护后，拦截旧素材的编辑和新增上面板，并处理已有面板引用。
- 方案沉淀：整理 BPM 接入方式与流程配置范例，已用于海外数字资产开白的接入实现。
  - 稳定性， 排查错误等等更方便

## 3.3 技术设计

| 业务挑战 | 解决思路 |
| --- | --- |
| 一次申请包含多份素材，审批和执行跨越多个阶段；出现部分失败后，业务需要知道哪些已经完成、哪些仍需处理。 | 1. 以搬运任务保存申请和逐素材结果。<br>2. 将审批、执行和目标业务操作串联起来，提供统一查询与排错入口。 |
| 被复用的素材可能继续由来源业务维护，也可能交给目标业务独立维护；两种关系对应的编辑权限和引用处理不同。 | 1. 依据素材服务返回的归属和替代关系控制操作。<br>2. 分别处理新增使用与已有引用，避免独立维护后继续使用旧素材。 |

主路径标注申请、审批、搬运与结果处理；旁路展示素材归属查询和目标业务操作。同区调用本地能力，跨区调用目标站点接口。

| 旧链路出现超时或部分失败时，业务难以判断哪些素材已经搬入。需要用任务记录贯穿审批、搬运和目标业务操作，支持重新查询和排错。 | 跟随素材可以被目标业务使用，维护权仍属于来源业务。转独立后生成新的素材 ID，还需处理面板中保留的旧引用。 |
| <b><span text-color="rgb(36,91,219)">固定申请范围</span></b><br>1. VIMO 的搬运任务表保存申请、提交素材和执行记录；提交时固定预检通过的素材，后续执行读取同一份任务。<br>2. BPM 负责编排，节点以 `taskId` 定位任务、以业务上下文校验所属业务，避免逐节点重复传整批参数。<br>3. 预检轮次阻止旧结果覆盖新申请；执行时由素材服务复查当时的搬运条件。 | <b><span text-color="rgb(36,91,219)">约束维护权限</span></b><br>1. 使用服务端归属字段 `owner_biz_id` 判断维护权；编辑和批量状态变更在后端复用校验，保存前重新查询。<br>2. 页面提前提示受限原因；后端无法查到素材状态时停止写入。<br>3. 未明确归属时允许确认，写入携带最新素材快照；已有不同归属则拒绝覆盖。 |
| <b><span text-color="rgb(36,91,219)">分开记录结果</span></b><br>1. 分开保存流程阶段、逐素材受理与执行结果、后处理结果；部分成功时保留已生成的目标 ID。<br>2. 轮询超时保留未完成状态，后续仍可查询；明确终态不被旧响应改回处理中。<br>3. 面板和测试只处理成功素材，失败独立记录，保留已经搬入的素材。 | <b><span text-color="rgb(36,91,219)">区分新增与历史使用</span></b><br>1. 服务端的 `redirect_item_id` 指向当前业务转独立后的新素材。搜索过滤旧素材，新增上面板遇到旧 ID 时拒绝该批写入并返回新 ID。<br>2. 编辑旧素材同样检查替代关系，提示前往新素材。<br>3. 历史引用保留原 ID 读取，避免全局屏蔽导致已有内容无法查看；归属字段不直接决定搜索可见性。 |
| <b><span text-color="rgb(36,91,219)">继续中断任务</span></b><br>1. 调用前保存每份素材的固定执行标识，作为下游识别和查询同次执行的依据，重试复用原标识。<br>2. 分片保存结果，重试只继续尚未确认受理的部分。<br>3. 并发写入发生版本冲突后，读取最新任务并合并本次结果，保留其他请求已经写入的进度。 | <b><span text-color="rgb(36,91,219)">替换已有引用</span></b><br>1. 搬运前确认受影响面板，成功后按旧新映射替换普通及强插引用；替换前核对面板是否变化，草稿与回执在同一事务保存。<br>2. 草稿专有引用只更新草稿；线上引用选择本次替换差异，试合并后的完整内容必须符合预期，否则停止自动发布。<br>3. 发布响应不明时先回读实际版本，避免直接重复发布。 |

## 3.4 未来规划

| 方向 | 下一步建设 |
| --- | --- |
| 补齐商业化信息 | 在现有业务扩展字段同步之外，补齐付费配置等信息在不同业务间的映射，按目标业务规则随素材搬运，减少搬入后的重复配置。 |
| 接入 AI 选材 | 将取数、候选整理、去重检查接到可调用工具中，让业务通过自然语言生成候选清单；人工确认范围后进入现有预检、审批和搬运流程。 |
