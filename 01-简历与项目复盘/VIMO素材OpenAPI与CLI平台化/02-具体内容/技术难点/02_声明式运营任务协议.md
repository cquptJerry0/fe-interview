# 声明式运营任务协议

## 首先体现

将跨资源运营流程抽象为稳定协议，并在执行前完成校验和依赖编译的架构能力。

## 系统冲突

素材上新、分级、面板关联、实验和发布已经具备独立命令，但跨步骤参数传递、依赖关系、流程复用和版本兼容仍由临时脚本维护。

## 关键设计

1. 将复杂运营流程描述为带版本的任务协议，而不是不可校验的 Shell 调用序列。
2. 从领域命令编译器获得稳定的输入输出 Schema，在执行前校验参数与步骤输出引用。
3. 将步骤依赖编译为 DAG，检测循环依赖，并支持无依赖步骤并行执行。
4. 通过协议版本和迁移规则维护历史任务模板的兼容性。

## 简历钩子

> 声明式运营任务：设计 Task DSL，将多步骤运营流程编译为依赖 DAG，通过静态类型校验、步骤输出引用和模板版本管理，将分散的临时脚本沉淀为可复用、可评审的流程模板，覆盖 5 类核心运营场景。

## 面试展开

1. 为什么不直接使用 Shell 或 TypeScript 脚本？
2. 上一步输出如何安全传递给后续步骤？
3. 任务协议和 CLI 命令升级后如何保持兼容？
4. 为什么需要编译为 Task IR，而不是边解析边执行？
