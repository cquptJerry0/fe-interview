# Workspace 文件系统

## 首先体现

为 Agent 长任务设计持久交互空间、产物管理和恢复机制的能力。

## 为什么需要

素材任务需要持续上传资源包、CSV、预览图等输入，执行过程中还会生成脚本、数据快照、日志、失败清单和结果包。仅依赖聊天消息难以组织和取回这些内容；文件保存在临时 Sandbox 中，又会在容器释放、任务等待或人工接管时丢失现场。

## 设计定位

为每个任务提供独立的持久 Workspace，作为用户、Agent 和 Sandbox 共享的工作台：

1. 用户可以持续上传素材资源，并查看、预览和取回任务产物。
2. Agent 通过文件路径引用大规模输入和中间结果，避免将完整内容塞入模型上下文。
3. Sandbox 只提供可替换的计算环境，重建后重新挂载原 Workspace 即可继续执行。
4. 前端以文件树或画布式工作台呈现任务现场，形成类似“无限画布”的持续交互体验。

## 简历候选

针对素材资源难以通过对话持续传递、任务产物分散且 Sandbox 释放后现场丢失的问题，设计前端、Agent 与 Sandbox 共享的持久 Workspace，统一承载资源包、数据清单、执行脚本和结果文件；前端以文件树与画布式工作台呈现任务过程，支持资源持续上传、产物实时取回以及跨会话恢复执行。

## 后续需要设计

1. 前端上传文件后如何被 Sandbox 直接访问。
2. 多个 Sandbox 如何隔离并挂载任务工作区。
3. 文件变化如何增量同步并实时投影到前端。
4. 大文件、目录树和并发写入如何控制成本与冲突。
5. 产物如何管理版本、内容 Hash、依赖关系和历史快照。
6. 任务恢复时如何确定最后一个可信执行现场。
