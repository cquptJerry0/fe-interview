# 项目关联八股：复习导航

## 一、回答心智

这部分不是通用题库，而是从简历技术钩子反推面试官最可能追问的知识点。

回答顺序固定为：

```text
先说项目中怎么做
→ 再解释通用原理
→ 最后补方案边界和规模演进
```

不要一上来背定义，否则项目讨论会突然变成八股朗诵。

## 二、项目事实边界

当前项目的正确性底座是 MySQL：

- distribute_record 和 publish_task 保存业务任务状态。
- 唯一约束拦截重复有效任务。
- 带状态条件的更新负责消费者抢占。
- 行锁和事务负责 Draft、索引、操作记录与发布任务的一致提交。
- claimAt 拒绝租约过期的旧消费者。

Redis、MQ 和 Outbox 属于面试延伸：

- Redis 可以承担缓存、限流或跨批次协调，但不是当前业务状态真源。
- MQ 可以用于实时唤醒和扩展吞吐，但不能替代业务任务状态。
- Draft 与 publish_task 当前同库，可使用本地事务；未来跨库时才需要 Outbox。

面试时先讲清事实边界，再讨论更大规模的方案。

## 五、最后速记

```text
1. 任务表保存业务状态，MQ 负责消息到达。
2. 接受 at-least-once，用业务幂等得到正确结果。
3. 带状态条件的 UPDATE 才是原子抢占。
4. 事务保证共同成功，行锁或版本号防止并发覆盖。
5. 唯一约束防重复行，锁内合并防内容丢失。
6. 租约允许别人接管，令牌阻止旧消费者回来写。
7. MySQL 保存事实，Redis 加速读取。
8. Redis 锁减少并发进入，数据库条件拒绝过期写入。
9. 同键串行、异键并行、全局有界。
10. 先减少工作总量，再增加并发。
```
